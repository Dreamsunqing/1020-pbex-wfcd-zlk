# wfm-items

[GitHub 仓库](https://github.com/42bytes-team/wfm-items)

`wfm-items` 是 Warframe.market 物品及游戏数据元信息的公开数据仓库，为物品页面、搜索、筛选、订单表单、图片、翻译、套装关系、紫卡数据、玄骸和姐妹实体，以及其他面向市场的游戏数据提供支持。

物品页面错误、市场缺失物品、翻译错误、图标错误或套装分组错误时，通常需要更新此仓库。

## 适合贡献的内容

- 添加缺失的可交易物品。
- 修复物品名称、说明、Wiki 链接、图标或缩略图。
- 修正物品的可交易性、批量交易、入库、等级、使用次数或套装归属信息。
- 修复套装关系和套装根物品。
- 改进物品翻译。
- 若仓库维护掉落／地点信息，可添加或更新这些信息。
- 翻译紫卡属性、赤毒玄骸怪癖、赤毒玄骸幻纹、帕尔沃斯姐妹怪癖和幻纹。
- 用更好的资源替换损坏或低质量图标。

## 仓库结构

仓库按数据维护方式组织。

| 区域 | 用途 |
| ----------------- | ------------------------------------------------------------- |
| `tracked/` | 与上游游戏数据同步或比较的物品。 |
| `untracked/` | 需要人工维护的物品。 |
| `missing/` | 应添加到 Warframe.market 的新增或缺失物品。 |
| `icons/` | 物品 JSON 文件使用的本地图标资源。 |
| `tracked/rivens/` | 紫卡武器和属性。 |

目录名和生成脚本可能变化，应遵循相邻文件现有结构。

## 添加缺失物品

1. 检查物品是否已存在于 `tracked/` 或 `untracked/`。
2. 若不存在，在 `missing/` 中新建 JSON 文件。
3. 以相似的现有物品作为模板。
4. 先填写英语数据。
5. 只在确认正确时添加翻译。
6. 有图标时添加或引用图标。
7. 提交拉取请求，说明物品在游戏中的出处，以及为什么应允许交易。

有效证据包括 Warframe Wiki 页面、游戏截图、官方更新说明，或类似的已上架物品。

## 编辑现有物品

更新现有数据时保持修改集中。

例如：

- 用一个拉取请求修复某个损坏的套装关系。
- 用一个拉取请求补齐某种语言的一组缺失翻译。
- 用一个拉取请求添加相关物品的新图标。

除非改动极小，否则避免混入无关修复。

## 物品 JSON 注意事项

物品文件通常包含 `en`、`ru`、`ko` 等语言专属块，用于显示文字和链接。

常见字段可能包括：

- `tradable`
- `part_of_set`
- `set_root`
- `rarity`
- `max_rank`
- `mastery_level`
- `ducats`
- 图标或图片路径

并非每件物品都使用所有字段。应参考相似物品的模式，不要盲目添加字段。

## 套装

套装关系会影响物品页面和市场搜索，因此很重要。

编辑套装时：

- 数据格式要求时，使用 `set_root` 标记根物品。
- 确保每个部件引用相同的套装成员。
- 精确使用现有 `url_name` 值。
- 检查套装根物品和部件是否符合用户实际交易预期。

## 图标

图标应清晰、裁剪正确，并与对应物品一致。

根据现有文件模式，图标可以通过 URL 引用，也可以存入仓库。优先遵循相邻物品文件的风格。

## 审查要求

维护者通常会检查：

- 物品确实可交易或与 Warframe.market 相关。
- JSON 有效。
- 字段名和结构与现有文件一致。
- 套装关系正确。
- 图标合适。
- 翻译未改动无关语言。
- 紫卡／玄骸／姐妹数据位于正确目录。

修改不一定立即反映到线上站点；数据导入和部署需要时间。

## 避免事项

- 除非维护者明确要求，否则不要修改 `_id` 字段。
- 不要在没有证据时编造物品数据。
- 除非有明确的市场用途，否则不要添加不可交易物品。
- 不要提交未经审查的大批量机器翻译。
- 不了解导入流程时，不要以会被覆盖的方式修改生成数据或受跟踪数据。
- 不要将物品数据修改和无关仓库清理混在一起。
