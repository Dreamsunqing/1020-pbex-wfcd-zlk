# 规则

这些规则适用于与 Warframe.market API、WebSocket 或公开数据交互的客户端、集成、机器人、脚本和服务。

Warframe.market 是基础设施有限的社区项目。我们欢迎有用的第三方工具，但客户端必须能够被识别、尊重用户，并节约服务器资源。

## 标识你的应用

每个应用都应使用专用且有描述性的 `User-Agent` 请求头。

好的 `User-Agent` 能标识项目，让我们了解流量来源。尽可能包含项目名称、版本、网站、仓库或联系地址。

示例：

```http
User-Agent: ExampleMarketTool/1.2.0 (+https://example.com/contact)
```

不要将应用伪装成普通浏览器或其他应用。身份不明、类似浏览器的自动化流量调查成本高，也容易与恶意流量、僵尸网络、爬虫或滥用的自动解析程序混淆。

隐藏身份、冒充浏览器或故意使流量难以分类的应用可能被封锁。

## 不要克隆 Warframe.market

不要仅仅复制 Warframe.market 网站，并用我们的 API 和基础设施作为后端。

第三方工具应增加有意义的价值，例如专门工作流程、无障碍改进、通知、分析、覆盖层或集成。直接复制网站会将流量和基础设施成本转嫁给我们，同时重复用户体验并争夺相同的用户活动。

我们可能限制主要用途是网站克隆、数据镜像或流量转移层的应用。

## 谨慎发送请求

设计应用时，应尽量减少不必要的 API 调用。

使用缓存、复用响应、避免紧密轮询，并在适用时优先采用增量更新或 WebSocket 订阅。本地缓存能够满足需求时，不要反复获取大型集合或高流量接口。

Warframe.market 的基础设施预算并非无限。低效客户端会降低所有人的服务质量。

## 请求频率限制

公共 API 的一般限额为每秒 `3` 次请求。

部分接口可能有更严格的限制。合约搜索接口预计限制在每分钟约 `10` 至 `20` 次请求。

为保护服务稳定性，必要时限流规则可能不经通知而改变。

## 访问可能受限

我们保留临时或永久限制访问 Warframe.market 服务、API、WebSocket 或特定接口的权利。

限制可能适用于特定客户端、令牌、用户、IP 地址、网络、云服务商、国家、地区或流量模式。流量造成运行风险、影响用户、疑似滥用或管理成本过高时，我们可能不经提前通知实施限制。

有时防护措施覆盖面较广。DDoS 攻击、集中爬取、滥用自动化或 Cloudflare 级别防护期间，正常应用也可能受影响。在这些情况下，我们无法保证例外放行或 API 不间断访问。

## 自动化与交易机器人

自动化和交易机器人目前属于灰色地带。

它们可能为部分用户带来显著优势，并影响市场行为、用户体验和基础设施负载。未来我们预计对自动化和交易机器人施加更严格的限制。

如果应用自动执行交易行为，请预期规则可能变化，并且今后访问可能受限。
