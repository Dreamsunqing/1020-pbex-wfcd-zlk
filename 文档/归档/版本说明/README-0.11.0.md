# 世界状态资料库上游资料包

SourceWorkbench 是用于 Warframe 上游资料的桌面工作台，当前代码版本为 **0.11.0**。支持 JSON 浏览、中文标题与来源追踪、离线合并汇总、图片检索与导出、上游更新、历史快照，以及 Oracle 推算与 browse.wf 周期查询。应用源码位于 `src/`，资料快照位于 `世界状态上游/`。

0.11.0 合并独立攻略图片工具，新增“图片资源”，统一 WFCD 和 DE 官方图库，提供图片复制、原图保存、跨页选择及批量导出。界面重新整理，支持浅色／暗色／跟随系统；原独立工具目录已迁移并删除。图库集中在 `assets/content`，不随每个应用 ZIP 重复打包。详见 [合并、界面与空间整理](../过程记录/28-双工具整合与主题及空间整理.md)。

0.10.2 增加 WFCD 技能图，赏金奖励默认折叠并采用多列卡片，增加中文任务出处；官方图片获取与覆盖比较详见 [图片与奖励卡片](../过程记录/26-技能图片与奖励卡片及官方图库比较.md)。

0.10.1 统一技能／组件跳转卡片、补充官方技能中文标题，集团卡入口直接显示中文 Mod 名。已有 0.10.0 构建无需重建。[本次样式说明](../过程记录/25-技能中文与关联卡片样式.md)。

0.10.0 补齐嵌套对象逐字段合并、技能／组件双向导航，并在技能、武器名称旁增加集团卡／强化卡徽章；可移植技能跳转合并后的 `ExportAbilities`。更新后请重新构建一次全量资料。规则、映射依据和边界见 [本版详细文档](../过程记录/24-嵌套合并与关系导航.md)。

## 快速开始

### 使用桌面包

本地 0.11.0 桌面构建位于 `dist/`（不进入 Git），提供 Mac x64、Windows x64 ZIP；后续不再生成 Mac arm64。Apple Silicon 运行 x64 包需要 Rosetta。解压后打开应用，也可从源码运行。应用会从所在目录向上寻找本项目的资料和共享图库，也可在配置中手动选择。

桌面应用自带运行环境，无需安装 Node.js 或 Python；**应用包与资料目录分开发放**，需要另行克隆或准备资料目录。也可以浏览其他本地 JSON 目录，中文匹配和推算需有对应字典、规则及数据。完整操作见 [使用说明](使用说明-0.11.0.md)。

本机完整图库不进入 Git。迁到其他电脑时，携带 `assets/content` 与 `世界状态上游`；图片目录内需保留 `catalog.json`、`wfcd-image-index.json`、`img` 及 `official-public-export`，在配置中选择该 `content`。同一电脑的开发程序和发布程序共同读取一份图库。

### 从源码运行

需要 Node.js **22.19 或更高版本**及 npm；资料校验脚本需要 Python 3。

```bash
git clone https://github.com/Dreamsunqing/1020-pbex-wfcd-zlk.git
cd 1020-pbex-wfcd-zlk
npm ci
npm start
python3 工具/校验资料包.py
```

克隆后默认核验 637 个资料文件。对仍保留四个上游 `.git` 的原始本地资料包，可运行 `python3 工具/校验资料包.py --include-git` 核验全部 750 个文件。

## P3 离线构建与协作

在“合并汇总”点击“构建全量资料”，读取所选目录／快照和当前保存规则；查看卡片、配方与奖励、问题与覆盖、构建差异，并可导出独立版本目录。报告和奖励支持分页、搜索。原始 JSON 保持只读。

在“合并规则”编辑 → 校验 → 填修改说明 → 保存 → 返回合并汇总重建 → 检查差异。入口面向资料、开发和复核人员；当前是本机编辑，可导出规则文件经 Git 共同评审，不是多人在线后台。0.10.0 的技能、组件和嵌套字段实现见 [嵌套合并与关系导航](../过程记录/24-嵌套合并与关系导航.md)。打开旧构建时会提示重建；点击一次“构建全量资料”后生效。详细分工及字段限制见 [合并规则编辑与协作](../过程记录/21-合并规则编辑与协作.md)。

```bash
npm run build:data -- --root . --out artifacts/full-export
npm run build:data -- --root . --rules /path/to/merge-rules.json --out /path/to/output
```

CLI 默认使用内置全量规则；桌面规则需导出后显式通过 `--rules` 传入。可用 `--profile pilot` 复跑原小闭环。相同输入、规则及修订产生相同 datasetVersion，失败保留上一成功版本。

产物按类别、配方、奖励、关系和搜索索引分片，附完整参考 JSON、manifest 及逐字段报告。溯源用 manifest.inputs 下标和原始 pointer 节省重复内容；详情按需展开。完整工作包大小见当前验收基线，App 应按需裁剪运行分片，完整复核材料留在工作台。图片独立配置，有则显示、缺则保留文字。0.11.0 将 305 张技能图片统一到共享完整图库；赏金奖励默认折叠，展开后一行多张奖励卡，显示中文任务／活动出处和溯源依据。原有合并数据无需重建。

备份统一滚动保留“当前 + 上一版”；当前交付 0.11.0 后仅保留 0.10.2 的上一版 ZIP。规则、快照、合并构建与导出也采用上一版保留策略。`npm run pack:all` 构建两端并校验后清理。详见 [全量实现](../过程记录/20-P3全量静态合并实现.md)、[备份保留策略](../过程记录/22-打包与备份保留策略.md)。

## 字典与奖励如何关联

通用预览使用记录中的名称、`uniqueName`、`type` 或记录键等完整 `/Lotus/` 引用匹配中文。支持 Plus／Oracle 的“语言键 → 中文字符串”和 WFCD 的“物品路径 → 名称对象”，不按英文名称模糊匹配，也不改写原 JSON。

赏金使用独立的多步关联：**清单难度档位 → 完整奖励表路径 → `ExportRewards.json` → 物品目录 → `name` 语言键 → 中文字典**。蓝图可经 `resultType` 关联成品；内融核心／现金包分别按 `fusionPoints × itemCount`／`credits × itemCount` 换算，并保留原始包数与概率。

地区赏金没有直接指定每项任务的难度，因此按所属星球提供共享难度目录；分别使用各地区有效世界状态确认奖励表，区分“当前轮次已确认”“固定表”“候选表”。奖励池目前按来源顺序展示，尚未映射到具体任务阶段，也不计算额外目标或钢铁之路加成。

预览、周常和赏金的字典优先级各自独立。具体文件、字段、别名转换、补译和追溯规则见 [字段、字典与赏金奖励映射](../过程记录/13-字段字典与赏金奖励映射.md)。
