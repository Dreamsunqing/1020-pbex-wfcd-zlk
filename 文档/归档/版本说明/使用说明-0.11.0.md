# 上游资料工作台 0.11.0

当前版本提供各来源独立预览、自动更新、历史快照与回滚、Oracle 推理、实验室／Hex 周常和 browse.wf 查询，以及 P3 全量静态“合并汇总”和“合并规则”、完整卡片详情、数据结构和可选本地图片。已覆盖全量静态分类和全部奖励表；未规范化结构及其他语言保存在参考文件。邮件通知仍保留关闭的配置位置，没有发送代码。

## 图片资源与主题（0.11.0）

原攻略图片工具已并入工作台。顶部“图片资源”支持 WFCD、DE 官方或全部来源；按类别、图片状态筛选，搜索中文、英文、原始图名或完整物品 ID。完整名称优先显示，组件仍可通过所属装备名称检索。每页 72 项，可切换紧凑、标准、大图及透明棋盘／浅色／深色底色。卡片保持统一尺寸，描述放在详情中。

点击图片打开详情：查看尺寸、文件大小、来源、完整 ID、描述及关联物品，调整缩放，复制图片、复制名称或保存原图。选择中文／英文／双语命名后，复制名称与导出使用相同偏好。技能展示中文和英文原名；缺图说明明确保留。点击关联物品可继续查看图片，或进入已有的合并资料。

勾选卡片或“选择本页”，切换类别和分页后选择仍保留；“只看已选”复核选择，批量导出原图，同名自动编号。可以停止导出，已经成功的文件保留；导出期间关闭应用会提示先停止。右上角选择浅色、暗色或跟随系统，主题、卡片大小、底色和命名偏好在重启后保留。⌘ / Ctrl K 搜索当前页面；Esc 关闭图片详情。

本机资源位于 `assets/content`，共享目录不再依赖旧工具路径。应用 ZIP 不重复包含约 1.5 GB 图库；移动到另一台电脑时携带共享目录，并在配置中选择它。旧工具源代码、许可证和历史验收只保留在 `integrations/image-tool` 供维护参考，没有独立可执行程序或第二套图片。

整合与空间核对见 [双工具整合文档](../过程记录/28-双工具整合与主题及空间整理.md)。

## 打开应用

- Windows：解压 Windows x64 ZIP，双击 `Source Workbench.exe`，保留同目录的配套文件。
- macOS：解压 x64 ZIP，打开 `Source Workbench.app`。后续不再发布 arm64 包；Apple Silicon 运行 x64 包需要 Rosetta。
- 首次点击“打开目录”，选择本项目资料包根目录或 `世界状态上游` 目录。应用也可以浏览其他本地 JSON 目录。
- 应用自带运行环境，无需安装 Node.js 或 Python。预览和推算可以离线使用；检查上游需要网络。
- 当前构建未使用发布证书签名或 Apple 公证，系统可能要求通过系统安全设置确认来源。Windows 仍需在对应机器实测；Intel macOS 包已通过本机 Rosetta 烟雾测试。

应用与资料目录分开发放。应用压缩包不附带本项目约 643 MiB 的历史资料和 Git 历史。

## 浏览 JSON

左侧有四组可多选的 picker：来源、类型、语言、数据类别。类型包含字典、数据、索引、配置等；数据类别包含武器、战甲、同伴、MOD、资源、任务等。同一组选择多个条件取并集，不同组之间取交集，可以继续叠加文件名 / 路径搜索。选项数字表示其他筛选条件下的匹配文件数，不受当前组已选值限制；没有匹配文件的未选选项不可勾选。

picker 内支持搜索选项、清空本项；下方标签可逐个移除，“清空筛选”同时清除四组条件和路径搜索。关闭“只看 JSON”可以查看文本、规则源码和排期。

文件列表显示来源、类型、语言、数据类别徽章，鼠标悬停查看完整标签。分类由来源和文件路径规则推断，适用于本地目录和历史快照，不改写资料正文。Plus 的语言引用数据标为“语言无关”，WFCD 基础分类数据标为“英语”；独立字典按语言标记。综合字典按“综合”归类，不展开为单个物品类别；未识别文件显示“未分类 / 语言未标明”，仍可通过搜索找到。新增上游文件名可能需要补充分类规则。

选中文件后可切换表格、结构、原文、卡片和数据结构。表格新增“中文来源”列，键、类型、内容、来源列宽为 13%、7%、65%、15%，结构视图保持窄键和类型列。卡片统一为 184px 高，采用紧凑布局，一行显示多个；仅显示中文标题、原始名称、类型／字段数及翻译来源，不显示描述和字段明细。数组或记录映射是集合，点击“查看集合”仍显示该层的多张卡片（例如 DE 官方的 `/ExportCustoms`、`/ExportWeapons`），可继续搜索和分页；点击单条记录的“查看详情”进入同一条记录的完整卡片，查看全部字段、完整长文本、中文字段名及用途说明；对象和数组按需展开，每批 80 项，继续加载可看完所有内容。返回卡片时恢复原列表的路径、搜索和页码。点击记录进入下一层，点击“上一级”返回。路径框采用 JSON Pointer，例如 `/ExportResources`，键中的 `/` 写成 `~1`，`~` 写成 `~0`。

记录搜索作用于当前层级：匹配键名、该记录内部文本或解析出的中文标题。先进入数组或字典，再搜索名称和内部路径。每页最多显示 80 条记录，后台读取文件并解析；原文显示前 200,000 字符，导出可以获取完整正文。单文件读取上限 96 MiB。

标题先取记录已有的中文名称，再用名称、uniqueName、type 或记录键／字符串值中的完整 `/Lotus/` 路径匹配当前目录或所选快照的中文词典。兼容 Plus／Oracle 的路径→中文字符串，以及 WFCD i18n 的物品路径→名称对象。同来源字典优先，其后依次尝试 Plus、WFCD、Oracle 和其他中文字典；不按英文名称或路径末尾猜测翻译。找不到时保留原名并标记“未匹配中文”。来源详情显示文件完整路径、JSON Pointer 和字典 SHA-256；原有中文标记“原文”。本地字典修改后下次预览即重读，新增文件需刷新目录。

卡片不把 img、image、icon、thumbnail、SVG、base64 等字段当作文字摘要；已配置本地图库时，按完整物品 ID 或 imageName 显示可匹配的本地图片，不请求记录中的远程地址。完整详情、表格、原文和导出仍保留原始图片引用文本。翻译仅用于显示与搜索，不写入原 JSON，也不注入复制或导出结果。普通目录需包含能识别的中文字典（如 `dict.zh.json`、`dicts/zh.json`、`i18n/zh.json`）才能匹配。

“数据结构”扫描整份 JSON 的全部记录，显示字段路径、类型并集、中文用途、观察次数及样例。重复数组元素用 [] 表示，数字键、内部路径等同类条目用 {key} 合并，少量记录独有的字段仍保留；普通伤害分量等属性逐项展示。可按中文或英文字段搜索，并跳转查看实际值。此页不受当前 Pointer 限制；空容器与未出现的字段无法推断，待确认的业务含义标为“释义待补充”。

字段说明与记录标题的字典翻译分开维护，悬停字段中文名可查看 title 提示。暴击比例与 WFCD 攻击模式百分数分别处理，能量容量与配色、连续紫卡系数与倾向评级分别展示；更新日志展开后显示新增、调整和修复等全部内容。易读数值与原始数值并列，均不写回 JSON。规则、字段依据和离线盘点方法见 [卡片详情与数据结构](../过程记录/15-卡片详情与数据结构.md)。

文件只读。含注释或尾逗号的 JSON 配置以 JSONC 方式解析，并显示提示；原始正文保持不变。浏览时不自动下载图片，文本中的图片名称、链接、哈希保留。0.11.0 的完整共享 WFCD 图库包含 305 张技能图，对应 308 个技能 ID。技能、组件关联卡片和技能详情均可显示；普通缺图记录再按完整 ID 查本地官方图库，不做英文标题模糊匹配。

## 更新、快照和回滚

“导入当前目录”建立本地基线。导入保存各来源的原始文本，不执行上游代码，不修改原始目录及其 `.git`。本地基线版本以 `local:` 标识，首次联网检查会核对远端实际版本。

“检查上游并更新”按启用来源依次处理：

1. 官方：下载 15 种语言的 LZMA 索引，读取版本化 Manifest 名称，只下载版本变化的文件。
2. GitHub：锁定分支当前提交，读取完整文件树，下载关注的文本文件，校验 Git blob SHA-1、大小和本地 SHA-256。提交不变且配置未变时复用上一快照。
3. 校验 JSON/JSONC、仲裁逐小时排期与每日突袭排期，保存内容对象。
4. 全部启用来源成功后才切换 `current.json`。失败保留上一完整版本，状态页显示原因。

本地导入会记录 Git blob SHA-1；与远端文件树一致的文本直接复用已有内容。旧的本地基线缺少该字段时，会先计算校验后复用。

网络请求有超时与有限重试。GitHub 限流时可从启动环境提供 `GITHUB_TOKEN`。应用不会把凭据写入配置文件。

请求使用 `HTTPS_PROXY` / `HTTP_PROXY` 和 `NO_PROXY` 环境配置；也可在来源配置中的 `network.proxyUrl` 填写无凭据的 HTTP 代理地址，例如 `http://127.0.0.1:7892`。未配置时直接联网。已完成来源的候选记录会保存到 `candidates/`，后续来源失败后重试可复用；只有全部来源成功才发布。

版本列表可浏览历史快照、将历史版本设为当前版本。快照比较只列出各来源文件的新增、删除、修改和哈希变化。

“启用应用内定时检查”按配置周期执行，默认每 60 分钟。退出应用后停止；首次开启后会在一个周期后执行，可用“检查上游并更新”立即检查。常驻机器可使用 CLI `watch`；不自动安装系统服务。

资料存储位置显示在“配置”页面。包括：

```text
snapshots/
  objects/<前两位哈希>/<完整SHA256>   原始文本内容
  releases/<版本ID>.json             各来源文件与来源版本
  current.json                      当前版本指针与代次
  status.json                       最近检查状态
  events.jsonl                      检查、导入、失败、恢复和回滚事件
  runtime/world-state.json          browse.wf 周期基准（不纳入资料快照）
  runtime/oracle-world-state.json   Oracle 所需世界状态字段（不纳入资料快照）
```

桌面配置位于应用用户数据目录的 `sources.json`，偏好位于 `preferences.json`。CLI 默认使用工作目录的 `.workbench`，也可通过 `--store` 指定。两个入口共享快照时应配置相同的存储目录；并发更新由文件锁阻止。

## 推算实验室

输入来自当前浏览的本地目录或历史快照，需包含 Plus、Oracle 和 browse.wf 的对应文件。普通 JSON 目录不一定拥有推算所需资料。

### Oracle 推算与周常

主导航依次为“资料浏览、推算实验室、更新与版本、配置”。在“推算实验室”选择“推算与周常 · Oracle”。顶部只有参考时间和一个深绿色“刷新并查询”按钮，六个模块共用该时间。默认时间为当前时间；未手动编辑时，刷新会更新为当前时间；手动编辑后保留所选时间。修改时间后自动查询本页全部模块，修改模块内条件则只查询该模块，不额外联网。

| 模块 | 输入与行为 |
| --- | --- |
| 赏金轮次 | 用 Hex seed 复算扎里曼、英择谛实验室与 1999 的节点、挑战和同伴；各档可展开查看中文奖励、数量、概率 |
| 地区赏金 | 用 Cetus seed 复算平原、山谷、火卫二 15 个地区的赏金选项；各地区内选择难度查看奖励及轮次确认状态 |
| 入侵任务变化 | 分别按支援阵营复算每 15 分钟的任务，界面可查 2／4／8 轮，CLI 支持 1–8 轮 |
| 04 实验室／Hex 周常 | 整理有效 `Conquests` 的任务、第二档变体与风险及个人限制，保留原始值和转换后名称 |
| 05 活化战甲 | 按区分大小写的游戏名与已观察战甲复算每周组合 |
| 06 仲裁排期 | 查询缓存的逐小时排期，超出覆盖范围报错 |

点击“刷新并查询”联网获取数据，再查询全部六个模块；刷新复用代理和重试配置，失败保留原缓存并继续执行本地查询，界面提示刷新失败。仅保存推算所需的集团任务、入侵、周常字段和响应哈希，不保存完整响应，不随资料更新自动刷新。赏金要求参考时间落在对应集团的有效窗口内。入侵要求参考时间与数据采集时间处于同一 UTC 15 分钟窗口，防止把已经结束的入侵当作当前任务。后续轮次仅假定这些入侵继续存在，不预测新增、结束或奖励变化。

也可在“04 实验室／Hex 周常”模块点击“导入世界状态 JSON”通过文件选择器导入官方格式文件。**导入使用界面的参考时间作为该文件的采集时间**，用于历史回放；请先设为文件实际采集时间。导入和联网缓存均独立于资料快照，界面分别显示采集来源、时间、哈希和所选资料版本。

赏金轮次模块的 Hex seed 与地区赏金模块的 Cetus seed 各自独立，留空时使用有效世界状态。分别手填十进制整数可离线复算对应赏金，此时不附带当前有效窗口和奖励轮次；该输入不作用于入侵或周常。赏金、入侵和周常都保留原始键／路径，并可复制完整结果 JSON。缺少翻译显示原始键。

这三项兼容实现已按本包的 Oracle `.pluto` 源码核对，并与 Oracle 在线响应及独立 Python 向量比对；仍需游戏内验证。只解析规则数据，不执行上游代码。所选规则源码哈希与审阅版本不符时拒绝计算，提示更新兼容实现；修改清单会按所选版本重新计算。

01 的奖励按三个挑战清单的 `ChallengeMissionDifficultyTiers[].rewards` 逐档关联，17 档均可展开。02 的地区任务没有指定难度，因此在各地区提供共享的普通任务难度选择；不会将任务顺序当作难度顺序。普通难度覆盖平原 6 档、山谷 6 档、火卫二 5 档，保留清单原始档号；额外、无尽和隔离库任务不套用这些奖励。声望、物品报酬及好感度展示清单基础值／范围，不计算钢铁之路、额外目标等加成。

02 分别用平原、山谷、火卫二自己的有效世界状态奖励完整路径匹配清单候选表。唯一匹配时显示“当前轮次已确认”；没有匹配、缺失、过期或冲突时展开全部候选；清单只列一张表时标记“固定奖励表”。手填 seed 仅供离线复算，奖励候选不标记为实时。旧版缓存没有山谷字段时，刷新或重新导入世界状态即可补充。

奖励使用所选本地目录／快照的 Plus `ExportRewards.json`，通过完整 `/Lotus/StoreItems/` 路径转换匹配物品导出文件，再查中文词典；蓝图缺名时通过 `resultType` 关联成品中文名并加“蓝图”，来源注明派生。Endo 包用 `fusionPoints × itemCount`、现金包用 `credits × itemCount` 换算，详情和复制 JSON 保留原始包数。概率保留来源数值、不重新归一化、不用稀有度猜概率；缺失显示待补充。多个池只按源文件顺序显示，池号尚未映射任务阶段。没有预测实际掉落结果。

奖励默认折叠；展开物品下的“原始标识与来源”可查看表／物品／字典文件、JSON Pointer 和数量换算依据，复制结果包含奖励结构与全部输入文件哈希。赏金模块不加载图片，不改写原始 JSON。其局部关联继续使用所选资料；P3 新入口提供独立的全量静态构建。

周常在“04 实验室／Hex 周常”中分栏显示深层科研和时光科研。按 `Activation ≤ 参考时间 < Expiry` 筛选，严格使用 `difficulties[1]` 的变体和风险；个人限制来自 `Variables`。仅实验室 `Defense → DualDefense`，风险 `EMPBlackHole → MagneticHounds`，个人限制 `DullBlades → ComboCountChance`、`Undersupplied → MaxAmmo`。主界面显示中文，原始值和转换值收在“原始标识与翻译来源”详情中。缺少中文会显示“中文名称／说明待补充”，原始标识仍可展开查看或复制 JSON。周常独立使用各自窗口，过期或缺失显示待刷新，不生成下周任务；旧版缓存没有 `Conquests` 时提示刷新或重新导入。

周常规则依据所选 `weekly.php`，任务类型表使用同来源 `data/ExportMissionTypes.json`，中文说明来自所选 Plus 和 Oracle 字典。不会执行 PHP。

周常中文优先使用所选来源的中文文本；缺项再读取应用自带 `src/data/oracle-weekly.zh.json`。目前补齐 `NoPets`（禁止携带同伴）、`RangeDebuff`（范围缩减）和 `AnemicShields`（贫弱护盾），名称为本项目补译，效果依据官方更新 44 说明。补译显示徽章，详情提供来源；后续上游中文补齐时按字段优先采用上游。应用补充表独立于上游原始资料及资料快照，以应用版本、表版本和 SHA-256 追踪。

复制 JSON 同时包含 Oracle 兼容字段和带中文说明的结构，附规则、类型表、字典、补充译表和世界状态哈希，以及按字段记录的翻译来源和待补中文键。

活化战甲：默认填入示例名 `Tenno`，请按需替换为自己的游戏名，区分大小写。目标周与已观察战甲位于活化模块内，修改后自动重算。`#` 后缀按参考页面语义移除。本周推算可输入上周已观察到的战甲，下周推算可输入本周战甲；允许 0–3 个不重复输入。缺少历史时明确返回条件推算。用户名只用于本地计算，不写入更新事件。

结果包含周窗口、规则版本、战甲池哈希和结构化属性。兼容实现已经与独立 Python 参考向量校对；不代表完成游戏实测。战甲池或游戏规则变化后需要重新核对。

仲裁：读取 `arbys.txt` 进行逐小时排期查询，支持未来 1–168 小时；界面模块内可选 12／24／72／168 小时，默认 24 小时。超出表的覆盖范围会报错。此功能不生成表外排期，游戏更新后仍需核对表的有效性。

### browse.wf 周期与轮换

在“推算实验室”选择“周期与轮换 · browse.wf”。顶部只有参考时间和一个深绿色“刷新并查询”按钮，刷新世界状态基准后查询四个模块。未编辑的默认时间随刷新更新为当前时间，已编辑的时间保持不变。修改时间后自动查询，Teshin 周数、回廊周数、每日突袭天数各在对应模块中独立设置，修改后仅更新该模块。界面时间按系统时区显示，周轮换和每日排期始终按 UTC 计算；北京时间分别为周一／每日 08:00 切换。

| 模块 | 输入与规则 | 查询范围 |
| --- | --- | --- |
| 世界周期 | 双衍王境每 2 小时轮换，山谷温暖 6 分 40 秒／寒冷 20 分钟；平原与火卫二用世界状态基准 | 当前参考时间 |
| Teshin 周商品 | 从所选 `live.ts` 提取商品表与周基准 | 界面 1／4／12 周，CLI 1–52 周 |
| 普通／钢铁回廊 | 从所选 `live.ts` 提取 3 战甲／5 武器轮换表 | 界面 1／4／12 周，CLI 1–52 周 |
| 每日突袭 | 查询所选 `sp-incursions.txt` 中每天 6 节点，基础等级 +100 | 界面 1／7／30 天，CLI 1–30 天；到表尾截断 |

双衍王境与山谷、周轮换、每日突袭均可离线查询。点击顶部“刷新并查询”后，平原／火卫二直接读取官方 `https://api.warframe.com/cdn/worldState.php`，兼容 browse.wf / Oracle 的 HexSyndicate 150 分钟窗口和末段 50 分钟模型。参考时间遵循顶部输入；界面标明来源、获取时间、有效窗口与哈希。缓存仅保存时间基准和完整响应哈希，不保存整份响应。

基准过期或查询时间不在有效窗口内时，平原与火卫二显示“待校准”，不会沿旧基准外推。固定规则与周排期仍能查询。刷新失败保留旧缓存；该按钮不随上游资料定时检查触发，应用不在后台自动访问世界状态。网络请求复用配置的代理和重试机制。CLI `world-state` 刷新默认 `.workbench/runtime/world-state.json`；`cycles --world-state <文件> --at <ISO时间>` 可对一份本地世界状态文件在其有效窗口内校对，不改写缓存。

规则数组通过 JSON 解析提取，不执行上游 TypeScript。遇到不支持的公式变化时提示更新兼容实现；缺少字典或星图时显示原始键和原因。切换目录／快照会清除旧查询结果。查询记录含规则／排期哈希和所选快照 ID，运行时世界状态基准与资料版本分别标明。当前缓存每日突袭表覆盖 UTC 2025-01-13 至 2028-09-11（结束时刻不包含）；超出范围会明确报错。

这四组功能复刻缓存的 browse.wf 模型，未声称已完成游戏实测。山谷在温暖结束的精确毫秒立即进入寒冷，修正原页面 `>` 边界可能产生的零延时重排。

## 合并汇总、合并规则与本地图片（0.9.0）

打开资料目录或历史快照后，进入顶层“合并汇总”，点击“构建全量资料”。默认覆盖 101 条分类规则、32,690 个实体（含 72 个待补引用）、2,024 份配方、1,102 张奖励表、11,509 项奖励；其他语言和未规范化分组完整保存在 reference。

统一资料支持中文／英文／路径搜索和类型筛选；列表为精简卡片，进入后仍为完整卡片。字段可展开候选、原值及来源，关系可跳转配方和材料，“打开来源”会先核对原文件哈希。问题与覆盖用于查看差异和未建模字段，构建差异与上一成功版本比较。失败保留旧版，修复输入后重建即可。

“导出数据包”选择父目录后创建独立版本子目录，包含类别分片、配方、关系、奖励、搜索索引、来源报告和 manifest。跨来源差异仍待复核，标为 review-required，供 App 离线试接和人工检查。当前不部署服务器、不连接 uniCloud，也未实现 App 的在线更新。

在“配置 → 共享图片资源”选择本项目的 assets/content；启动时会自动寻找附近的共享图库。WFCD 原始图名与完整 ID 由 wfcd-image-index.json 关联哈希文件名；官方图片由 official-public-export/index.json 按完整 ID 关联。支持普通 WFCD img 目录作为资料卡配图，但完整“图片资源”入口需要 catalog.json 与完整清单。引用图继续标注参考图，普通资料卡不会拿敌人参考图冒充原图。图片资源与应用、JSON 导出包分开保存，跨电脑时需携带共享图库。

命令行：`npm run build:data -- --root . --out artifacts/p3-delivery`。完整流程见文档 16，字段合同见 17，验收和同事分工见 18，官方图片获取方法见 19。


### 合并规则维护

顶层“合并规则”提供版本与流程、分类、字段映射、路径别名、人工修订、完整 JSON 六个页签。资料人员维护类别和中文说明；开发核对字段语义；复核人员提供源 SHA-256 和修订依据。分类优先级数字越小越优先；字段来源优先级从左到右。修改后先校验，填写修改说明并保存，再到“合并汇总”重新构建。结构校验通过不代表源数据已验证；构建会继续检查输入哈希、字段及修订有效性。

“导入规则”载入本地 JSON 为草稿，“导出规则”保存当前草稿为文件；文件结构为 `{contract, overrides}`，可提交 Git 共同评审。规则保存在本机应用用户数据的 `merge-rules/`，不是多人实时同步后台。规则仅保留当前和上一版；“载入上一版为草稿”后仍需保存、重新构建。JSON 可编辑当前支持的配置，不执行自定义脚本。

### 空间与版本保留

应用包、规则、快照、每个上下文的合并构建、每个导出父目录的数据包均采用“当前 + 上一版”。上一版应用只保留 ZIP。生成 0.11.0 时保留 0.10.2 ZIP；下一次生成新版继续滚动。规则和快照通过原子切换后轮换，成功更新时回收不再被保留快照或下载候选引用的内容对象。原始上游目录、图库、Git 历史不参与清理。

本机完整打包可用 `npm run pack:all`，依次构建 Mac x64、Windows x64，校验源码后轮换备份。CI 分别生成两端包，不生成 arm64。完整实现及协作见文档 20、21，空间策略见文档 22。

### 蓝图图片（0.9.1）

“xx 蓝图”使用蓝图底纹在下、对应产出物的本地图片在上，两层合成显示；列表和详情均适用。合并资料按配方 resultId 找产出物；原始资料按 resultType，或图库 catalog 中通用蓝图唯一的 parents 关联。不会按名称删掉“蓝图”后猜图片。缺成品图时保留蓝图底纹；只有成品图时显示成品；均缺失时保留文字卡片。原 JSON 与图库文件均不修改。

### 嵌套合并与物品跳转（0.10.0）

更新应用后，在“合并汇总”点击一次“构建全量资料”。旧构建会提示重建，原有规则和原始 JSON 保留。嵌套对象现在按子字段合并；带完整 ID 的对象数组按 ID 对齐，无 ID 数组保留整组候选。不会把两个来源数组的第 1 项当作同一条目强行拼接。

物品详情顶部新增“技能、组件与关联关系”卡片区：点技能进入独立技能详情，可看中文名称、描述、启动能量和字段来源；点组件查看组件详情，并可从“用于物品”返回所属物品。支持“返回上一物品”和“返回统一资料”。组件数量、关联各处来源均保留；制造材料与蓝图配方材料区分展示，不执行递归总成本计算。对象／数组字段可继续逐层展开，已识别的内部物品引用可以点击跳转。

“合并规则 → 嵌套与关系”维护来源集合、统一集合、关系类型、嵌套实体类别和反向父级开关。旧规则缺少这一节时使用内置的技能、组件、所属物品、附带物品和显赫武器五条规则；保存后重新构建。未知字段虽然可以结构化合并，业务释义仍可能待补充。详细字段及验收见文档 24。

技能与武器名旁的集团卡／强化卡徽章可进入对应 Mod。可移植标记进入合并后的 ExportAbilities 技能目录，Prime 标记为“同系可移植”；源 Wiki 的依据可以定位到原文行号。关联徽章不代表集团商店当前一定在售。

### 技能中文与跳转卡片（0.10.1）

技能与组件采用统一的可点击卡片，支持点击卡片空白区域或键盘 Enter 进入详情。集团卡入口为深绿实心按钮，直接显示对应 Mod 的中文名称。原 JSON 浏览补充 abilityName／abilityUniqueName 中文解析，保留原字段与来源。已有 0.10.0 全量资料可直接使用，无需重新构建。

## 0.10.2 赏金卡片与图片核对
