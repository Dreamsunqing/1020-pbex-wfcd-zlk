# 字段、字典与赏金奖励映射

核对日期：2026-10-20（Asia/Shanghai）。适用项目：SourceWorkbench 本地 0.6.0，仓库 https://github.com/Dreamsunqing/1020-pbex-wfcd-zlk 。本文记录本对话已实现的关联；以本地代码为证据，不代表这些功能已推送 GitHub，也不代表独立世界状态 API 已采用相同实现。

## 1. 范围和基本规则

- 原始 JSON 保持原样；中文标题、奖励详情、来源追踪均为读取时生成的展示或结果字段。
- 用完整内部路径、uniqueName、节点 ID、语言键关联，不用中英文名称模糊拼接。
- 物品路径（例如 /Lotus/Types/...）、语言路径（/Lotus/Language/...）、奖励表路径是不同键空间；不能仅因为都以 /Lotus/ 开头就互换。
- 本版实现的是预览和特定模块的局部关联。全量跨来源统一构建、冲突裁决与合并汇总（原 P3）仍暂缓，邮件通知仍暂缓。
- 字典优先级由模块决定，不能宣称全项目存在一条统一优先级。详细见第 3 节。
- 文件、规则、字典来自当前选择的本地资料或历史快照；不把当前目录的字典混进旧快照。字典变更按内容哈希失效。Oracle 兼容源码先校验已审阅哈希，不执行上游 PHP／Pluto／TypeScript。

### 通用标题如何查

1. 顺序检查 name、title、displayName、label、Name、Title；原值含汉字即作自带中文，标记 original。
2. 没有中文时，依次收集上述名称字段、uniqueName、type、Type、当前记录键、字符串标量中的完整 /Lotus/ 引用。兼容用户提到的 /louts/ 拼写及前缀大小写，仅规范化这一前缀。
3. 对每个引用，按本场景字典优先级查完整键。Plus／Oracle 取字符串；WFCD 对象取上述标题字段中首个含汉字的字段。
4. 命中后提供中文标题、原引用、来源文件、JSON Pointer、SHA-256；无匹配则保留原标题并标记 missing。

关键区别：通用预览只查字典，不自动从物品路径跳到 ExportResources.name 再查语言字典。赏金模块专门实现了该多跳链路。预览也不会把英文名称、描述、图片路径随意当作翻译键。

表格有“中文来源”，卡片可查看来源详情；卡片隐藏图片字段、最多显示 8 个非图片摘要字段，不展示图片。标题可用于当前层级搜索，原文、复制及导出的原始 JSON 不被改写。库读取与分页证据：src/core/library.mjs:37；选定快照读取证据：src/desktop/worker.mjs:49。

## 5. 赏金奖励映射的完整实现

主实现 src/core/oracle-rewards.mjs:3–80；载入 src/core/oracle-data.mjs:41–44。Plus 的 ExportRewards.json 提供“奖励表完整路径 → 奖励池数组 → 奖励项数组”；每项通常含 type、itemCount、probability，其他表可能仅含 rarity。

### 5.1 奖励表如何选

**01：挑战清单档位直接绑定。**

Oracle 清单 data.ChallengeMissionDifficultyTiers[i].rewards → Plus/ExportRewards.json[该完整路径]。结果挂在 bounties[tag][i].rewardDetails，另保留 manifest-tier 依据、清单 JSON Pointer 和固定报酬。5 + 5 + 7 = 17 档。不是用任务名字或打乱后的序号猜奖励表。

**02：地区任务共享普通赏金难度目录。**

LocationSpecificJobs 没有给被选任务指定难度，不能把第 N 个地区任务当成第 N 档奖励。代码用清单 Jobs + 该星球任务路径前缀识别当前结果中的普通任务；各地区查看其所属星球的 JobDifficultyTiers，共享难度选择器。

- 排除 useExtraJobs、endless，以及无适用普通任务的情况。
- 平原 6 档、山谷 6 档、火卫二 5 档。火卫二原第 3 档为无尽，保留其余原始编号 1、2、4、5、6。
- 每个难度的 rewardManifests 是候选完整表路径。
- 实时查询时，各自查 Tag 为 CetusSyndicate／SolarisSyndicate／EntratiSyndicate 且 startsAt ≤ 查询时间 < endsAt 的唯一世界状态记录，将该记录 jobs[].rewards 与本难度候选路径求交集并去重。
- 唯一命中：status=world-state，仅展示命中表，含义为“当前轮次已确认”。
- 未唯一命中但清单本来只有一张候选表：status=fixed，含义为“固定表”。这与当前轮次被动态事实确认不同。
- 其余情况：status=unconfirmed，展示全部候选；缺失、过期、窗口重叠、多表冲突都不静默取第一张。
- 手填 seed 不确认实时轮次。仅有一张表仍可按静态清单标 fixed。
- 原兼容输出中按字符串位置提取的 A/B/C、vault 轮次字段，不作为新奖励选择器的依据；实际选择采用上述完整路径匹配。

官方输入字段是 SyndicateMissions[].Tag、Seed、Activation、Expiry、Jobs[].rewards；解析到缓存后分别为 Tag、seed、startsAt、endsAt、jobs[].rewards（状态摘要接口另显示小写 tag）。日期原始结构为 $date.$numberLong（毫秒）。缓存保留四个相关 Tag，含本次新增 SolarisSyndicate；旧缓存缺山谷时先降级候选，刷新后补齐。缓存包含筛选数据及来源、观察／加载时间、payloadHash、dataHash，不是完整官方响应副本。证据：src/core/oracle-state.mjs。

### 5.2 奖励项名称及数量怎么映射

当前专用解析器只索引以下 8 个 Plus 文件；均位于 世界状态上游/git/warframe-public-export-plus/：

| 文件 | 关联字段 | 可得到什么 |
| --- | --- | --- |
| ExportResources.json | [物品路径].name | 资源／零件的语言键与中文名 |
| ExportRecipes.json | [蓝图路径].name 或 resultType | 直接名称，或转向成品物品路径 |
| ExportWeapons.json | [物品路径].name | 武器／成品名称 |
| ExportWarframes.json | [物品路径].name | 战甲／成品名称 |
| ExportUpgrades.json | [物品路径].name | Mod、升级类名称 |
| ExportGear.json | [物品路径].name | 装备／消耗品名称 |
| ExportCreditBundles.json | [物品路径].name、credits | 现金包名称、每包现金量 |
| ExportFusionBundles.json | [物品路径].name、fusionPoints | 内融核心包名称、每包 Endo 量 |

链路顺序：

1. 奖励项 type 如果以 /Lotus/StoreItems/ 开头，仅将这一前缀转换成 /Lotus/。完整奖励表路径不转换；不做任意字符串删除。
2. 用转换后的完整路径查上述索引，取记录 name，再查 Oracle/dicts/zh.json，未命中再查 Plus/dict.zh.json。
3. 蓝图缺少可用直接名称时，从 ExportRecipes 的 resultType 查上述索引中的成品，取成品 name → 中文字典，组合“成品中文名 + 蓝图”。这是项目派生名称，nameSource.derived 明确记录，不能标成上游原文译名。
4. 数量通常为 itemCount；若记录含 fusionPoints 或 credits，则 quantity=该数值×itemCount。现金使用项目展示单位“现金”；原包名仍在 conversion.originalName。保留 itemCount 与完整 type。
5. 原 probability 保留为 rawProbability；可用 probability 必须是有限的 0–1 数值，页面再显示百分比。仅有 rarity 时不猜概率、不归一化、不将不同包数的同名物品合并。
6. 缺表或结构坏时 status=missing；条目缺名称、有效数量或概率时表为 partial 并产生警告；不伪造完整成功。

各候选池 index 从 1 开始，仅代表源数组顺序。它不是轮次 A/B/C，也不是任务阶段；stageCount 是清单提供的阶段数，当前尚未建立“第几个池对应第几阶段”的证据。

### 5.4 来源如何回溯

奖励表、奖励池和条目均有 file + JSON Pointer；nameSource 记录物品 name／resultType、语言键和字典 Pointer，蓝图附 resultSource，数量换算有 conversion.source。外层结果 inputHashes 保存输入文件哈希，sourceHash 保存已审阅兼容规则源码哈希，dataVersion 指明资料版本。路径中的 / 和 ~ 在 JSON Pointer 中转义为 ~1、~0。

结果中的 plus/、oracle/ 是来源 ID 前缀，不是另建的同名项目目录。界面可展开来源，复制结果 JSON 保留奖励详情；这与 JSON 浏览器“复制原始 JSON”是两个入口。

边界：没有预测实际随机掉落；没有把奖励池绑定到具体阶段；未覆盖额外、无尽、隔离库或钢铁加成；未加载 ExportRelics.json、ExportBoosters.json 作为奖励物品兜底；不应将当前赏金样本覆盖率推广到所有游戏奖励。

## 9. 与其他 Warframe 项目的边界

- 仓鼠互助洞 App、独立世界状态重构 API/Beta、SourceWorkbench 是不同项目。
- 历史 OpenViking 的 resources/projects/cangshu/ 存有大量独立 API 文档；目录名不代表这些实现属于仓鼠互助洞 App。用户已在 2026-10-04 明确纠正。
- 独立 API 历史设计中的 WG 覆盖、官方 Export／语义目录、WFCD 等多层解析优先级有自己的服务边界，不能抄成当前工作台的通用规则。
- 2026-10-01 的“只派生奖励表名称、未展开奖励池”描述的是当时 API 实现；本地工作台 0.6.0 已有上述赏金奖励池关联。这不证明 API 已同步实现。
- 旧科研分数、奖励池完整性等结论须携带日期、构建版本与证据；不能把某个旧 profile 的门槛当成所有版本游戏规则。
