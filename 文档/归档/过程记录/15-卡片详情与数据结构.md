# 卡片详情与数据结构 · 0.7.2

> 本文保留 0.7.2 阶段记录。0.8.0 已新增 P3 样本“合并汇总”与可选本地图片，见[离线小闭环](16-P3离线小闭环与合并汇总.md)和[图片说明](19-本地图片接入与官方图片获取分析.md)。

本阶段先用离线资料梳理 P3 流程：读取原始文件 → 观察字段结构 → 补充字段释义 → 确认关联与统一模型。当前完成前两步及常用字段释义；跨来源合并、冲突裁决和 App 接口尚未实现。所有展示都不写回上游 JSON。

## 使用方式

- **卡片**：统一为 184px 高，同一行等宽；列表仅显示中文标题、原始名称、类型／字段数和翻译来源，不展示描述及字段明细。紧凑布局可一行显示多个卡片。数组和记录映射点击“查看集合”后仍显示该层多张卡片，单条记录点“查看详情”进入详情，返回时恢复原列表的路径、搜索和页码。
- **详情**：展示当前记录的全部字段，含图片引用的原始文本；标注中文名称、原始键、类型、用途和说明依据。悬停中文字段名可查看 title 提示。点击后仍是一张完整记录卡片；所有字段作为这张卡片里的属性行展示，不拆分成字段小卡片，不切换到表格、结构或原文。
- **嵌套内容**：对象、数组按需展开，每批 80 项，“继续显示”可读取剩余项；标量正文不截断。空字符串、false、0、null 分别保留。若展开期间文件内容改变，提示重新打开，避免混合两版记录。
- **数据结构**：始终扫描整份 JSON，不受当前 JSON Pointer 影响；展示结构路径、类型并集、观察次数、中文释义、最多三个值样例、动态键样例和说明依据。支持中文或英文字段搜索、分页，以及跳转查看实际值。
- 顶部复制、导出仍操作当前 Pointer 对应的原始数据，不附加中文字段或结构说明。结构页的样例有长度限制，详情及导出可查看完整值。

## 重复结构如何合并

所有数组元素都参与扫描，统一放在 `[]` 下。例如 201 条记录只有最后一条带 `rare.nested`，该字段仍会出现，观察次数为 1。不会只取第一条或当前页的 80 条记录。

数字键、内部绝对路径、节点编号、十六进制标识，以及带名称的同类记录映射，使用 `{key}` 表示；所有值的子字段取并集。另有明确的文件／容器规则处理星图导出、文本图标索引、缓存索引和依赖包映射。

```text
原始：{"obj":{"1":{"a":1},"2":{"a":2,"extra":true},"3":{"b":0}}}
结构：$["obj"]{key}
        ├─ ["a"]      number
        ├─ ["extra"]  boolean
        └─ ["b"]      number
```

普通属性包仍逐项保留，例如 `damage.impact`、`damage.slash` 不会合成一个数值属性。记录里的实际键从不删除，详情和原文仍能逐一查看。

这是**当前文件的观测结构**，不是上游官方 Schema：没有出现的字段无法凭空发现；空数组无法推断元素类型；观察次数也不等于官方必填约束。混合类型及 null 会同时列出。

## 字段中文说明与记录翻译分开

记录名称继续通过 `preview-titles.mjs` 的完整路径字典匹配，并追踪字典文件、Pointer 和哈希。字段说明则由共享的 `src/core/field-guide.mjs` 提供，卡片摘要、详情 title 和数据结构页共用，不混充为上游原译。

| 字段 / 上下文 | 展示与处理 |
| --- | --- |
| `criticalChance` | 暴击几率，比例值 ×100 展示为百分比；原值另行完整保留 |
| `attacks[].crit_chance` | WFCD 已转换成百分数，不再次 ×100 |
| `criticalMultiplier` / `crit_mult` | 暴击倍率，显示“倍”及原值 |
| 战甲 `power` | 基础能量容量 |
| `color.energy` | 能量配色，不能当作能量容量 |
| `omegaAttenuation` / `primeOmegaAttenuation` | 连续紫卡系数；易读数值与原始浮点值分开显示 |
| `disposition` | 紫卡倾向档位，通常 1–5，与连续系数分开 |
| `patchlogs[]` | 更新日志；`name` 为更新版本名称，`date` 为日期，`additions` / `changes` / `fixes` 为新增／调整／修复 |
| `introduced` | 首次加入版本及其公告、日期等信息，和完整更新日志分开 |
| `damage` / `DT_*` | 保留伤害分量；不将不同攻击模式重复求和 |
| 赏金清单 / 奖励表 | 说明难度档位、奖励表引用、物品路径、数量等字段，保留已有的局部关联逻辑 |

暴击换算依据本包 `wfcd-items/build/wikia/transformers/transformWeapon.ts`；战甲、配色、倾向档位和更新日志结构依据 `wfcd-items/index.d.ts`。其他说明标注“工作台字段说明（结合当前来源使用）”；尚未确认的字段保留原键并标“释义待补充”，不猜单位或枚举对应关系。

## 离线盘点与后续维护

运行：

```bash
node scripts/inventory-structure.mjs
# 可指定资料目录和报告输出位置：
node scripts/inventory-structure.mjs <目录> <报告.json>
```

默认生成 `artifacts/json-structure/inventory.json`，逐文件记录 SHA-256、结构节点数、待补释义数，并汇总待核对字段及真实样例 Pointer，便于同事分工补齐。报告属于派生结果，不修改原始资料。

本轮扫描的 403 份 JSON 全部可解析。示例：

| 文件 | 合并后的结构节点 | 尚无中文释义的节点 |
| --- | ---: | ---: |
| Plus `dict.zh.json` | 2 | 0 |
| WFCD `i18n/zh.json` | 17 | 0 |
| WFCD `Primary.json` | 123 | 0 |
| WFCD `Warframes.json` | 64 | 0 |
| Plus `ExportWeapons.json` | 155 | 2 |
| Plus `ExportWarframes.json` | 36 | 2 |

计数包含根节点、数组元素及动态键节点，不能当成物品数量。“有说明”也不代表已形成跨来源统一规范；部分说明仍要求结合来源上下文。完整资料包的冷门字段、配置和用户档案字段仍有待补充项，报告会明确列出。

主要实现：`src/core/json-structure.mjs` 负责全量结构扫描与完整详情分页，`field-guide.mjs` 维护显示释义；Worker 将文件、字典固定在同一目录或快照上下文，结构缓存以文件内容哈希失效。Electron 仍保留原有 IPC 白名单和文件选择／导出对话框边界。
