# P3 数据规范与字段映射

对应 0.8.0，`schemaVersion: 1`、`mappingVersion: p3-pilot-1`、`builderVersion: 1.0.0`。机器可读规范以 `src/data/merge-contract.json` 为准。下列路径以 `世界状态上游/` 为根；历史快照文件 ID 使用来源前缀，保留实际 ID 与哈希。

## 标识和来源规则

统一实体 ID 使用完整 `/Lotus/...` 路径，优先取记录 `uniqueName` 或 Plus 路径键。不同同名物品不能按中文或英文名称合并，蓝图与成品不能混成一个实体。

唯一明确的奖励别名转换：当字符串以 `/Lotus/StoreItems/` 开头时，仅移除该处 `StoreItems/`，得到 `/Lotus/...`。字符串中其他位置的 `StoreItems` 不能全局删除。例如：

```text
/Lotus/StoreItems/Types/StoreItems/CreditBundles/Zariman/TableACreditsCommon
→ /Lotus/Types/StoreItems/CreditBundles/Zariman/TableACreditsCommon
```

非文本规范字段按 `official → plus → wfcd → oracle` 选择通过校验的候选；同来源再按语言、文件、指针稳定排序。不按整个来源对象覆盖，缺值可从下一候选补足。源值 `0`、`false` 保留，不能视为缺失。

中文、英文分别解析。顺序是官方对应语言的直写名称／描述 → Plus 语言键和对应字典 → WFCD 原文／物品本地化 → Oracle 字典；没有名称的蓝图可派生成品名。规范语言键 `zh-CN` 对应本包官方语言目录 `zh`，不是 `tc`。`name['zh-CN']` 有值不保证文本含汉字，如上游 Gauss 名称仍为 Gauss；不擅自音译。

## 本轮实际输入

| 来源 | 文件／组 | 用到的内容 |

## 规范实体

```json
{
  "id": "/Lotus/Weapons/Tenno/LongGuns/SapientPrimary/SapientPrimaryWeapon",
  "kind": "weapon",
  "name": { "zh-CN": "迅发电浆炮", "en": "Acceltra" },
  "description": { "zh-CN": "对应来源的完整中文描述", "en": "..." },
  "masteryRank": 8,
  "tradable": false,
  "stats": { "criticalChance": 0.32, "criticalMultiplier": 2.8, "rivenCoefficient": 0.65, "rivenDisposition": 1 }
}
```

此片段为字段示意，不代表文件完整记录。`kind` 目前为 weapon／warframe／resource／blueprint／mod。资源分片包括原料、部件、现金及内融包；尚未细分所有资源子类。

| 原字段 | 规范字段 | 单位和校验 |
| --- | --- | --- |
| `masteryReq` | `masteryRank` | ≥0 整数，段 |
| `tradable` | `tradable` | 布尔值，不把字符串转布尔 |
| 武器 `criticalChance` | `stats.criticalChance` | 0～1 比例，保留 6 位小数；必需 |
| `criticalMultiplier` | `stats.criticalMultiplier` | ≥0 倍率，6 位 |
| `procChance` | `stats.statusChance` | 0～1 比例，6 位 |
| `fireRate` | `stats.fireRate` | ≥0 次／秒，5 位 |
| `magazineSize` | `stats.magazineSize` | ≥0 整数，发 |
| `reloadTime` | `stats.reloadSeconds` | ≥0 秒，6 位 |
| `totalDamage` | `stats.totalDamage` | ≥0，基础面板，5 位 |
| `omegaAttenuation` | `stats.rivenCoefficient` | ≥0 系数，6 位 |
| WFCD `disposition` | `stats.rivenDisposition` | 1～5 整数档位，与系数分开 |
| 战甲 `health/shield/armor` | `stats.health/shield/armor` | ≥0 点数，6 位 |
| 战甲 `power` | `stats.energy` | ≥0，能量容量，6 位；必需 |
| 战甲 `sprintSpeed` | `stats.sprintSpeed` | ≥0 系数，6 位 |
| 数量包 `credits` | `bundle.credits` | ≥0 整数现金／包 |
| 数量包 `fusionPoints` | `bundle.endo` | ≥0 整数内融核心／包 |

浮点尾差按声明精度规范化，例如 `0.31999999 → 0.32`、`0.64999998 → 0.65`、`12.000001 → 12`，同时保留候选原值。显示暴击率时 `0.32 × 100 = 32%`。WFCD `attacks[].crit_chance` 为百分数，含不同攻击模式；本轮不把它当作基础 `criticalChance`，也不与基础伤害相加。配色中的 `energy` 不当作战甲容量。

## 配方和关系

主要读取 Plus `ExportRecipes.json` 的蓝图记录；官方同 ID 配方也参与候选比较。

| 配方源字段 | 规范字段／关系 |
| --- | --- |
| 记录路径键／`uniqueName` | `recipes[].id`，同时为 blueprint 实体 ID |
| `resultType` | `resultId`，形成 blueprint → product 的 `produces` 边 |
| `ingredients[].ItemType` | `materials[].itemId`，形成 blueprint → material 的 `requires` 边 |
| `ingredients[].ItemCount` | `materials[].count`，边 `quantity` |
| `buildPrice` | `credits`，非负整数 |
| `buildTime` | `seconds`，非负数 |
| `num` | `quantity`，正整数 |

材料按规范 ID 排序，但 provenance 指向源 `ingredients` 数组，不能用重排后序号冒充原数组位置。配方数量、费用和时长缺失停止构建；成品或材料的跨来源差异是关键冲突，停止发布。所有引用须存在，重复材料拒绝，成品依赖图出现循环拒绝。

蓝图和产品名各自独立：仅蓝图缺名时，沿 `resultType` 查成品在对应语言的名字，派生“成品名 蓝图”／“Name Blueprint”，标记 `derived-blueprint-name`，嵌套保留成品原文／字典来源，不能标为官方直接命名。

`relations.json` 每条边包含 `from/to/kind/source`；材料边有 `quantity`，奖励边有 `pool/probability/quantity`。产品、材料可反查引用，奖励表 ID 是关系的来源节点，不当作 items 实体。

## 扎里曼赏金奖励完整链路

```text
Oracle ZarimanJobManifest.json
  data.ChallengeMissionDifficultyTiers[0].rewards
    ↓ 完整表路径严格匹配
Plus ExportRewards.json[表路径][池序号][项序号]
  type → 限定 StoreItems 前缀转换 → 统一 itemId
  itemCount → 原始包数
  probability → 0～1 原始概率
    ↓ 同 ID 物品目录
ExportResources / ExportRecipes / ExportCreditBundles / ExportFusionBundles 等
  name → dict.zh.json → 中文
  resultType → 成品中文 → 派生蓝图名（仅缺名时）
  credits × itemCount → 现金数量
  fusionPoints × itemCount → 内融核心数量
```

本表 ID：`/Lotus/Types/Game/MissionDecks/ZarimanJobMissionRewards/TierATableRewards`。池保留源顺序，从 1 编号；规范 provenance 字段路径使用从 0 开始的数组索引。`stageMapping: unconfirmed`，不能声称第 1 池就是任务第 1 阶段。

奖励结构：

```json
{
  "itemId": "/Lotus/Upgrades/Mods/FusionBundles/UncommonFusionBundle",
  "rawType": "/Lotus/StoreItems/Upgrades/Mods/FusionBundles/UncommonFusionBundle",
  "itemCount": 10,
  "quantity": 500,
  "unit": "内融核心",
  "probability": 0.1739,
  "conversion": { "field": "bundle.endo", "perItem": 50 }
}
```

相同包的另一项 `15 × 50 = 750`。现金样本为 `1 × 15000`、`1 × 30000`。一般物品 `quantity = itemCount`。数量必须正整数，概率必须在 0～1 内，换算结果必须有限。概率按源值显示为百分数，不重新归一化；四舍五入后总和也不强改成 100%。此处完整表有 8 项，不预测实际随机掉落，不确认实时轮次，不计算额外目标／钢铁之路加成。

## Provenance、问题与未建模字段

每个参与裁决的字段记录：`entityId`、`field`、规范 `value`、`status`、`selected`、`rule`、`candidates`。每个候选含 `value/rawValue/source/transform`；source 含 `source/file/hash/pointer`。字典翻译另带 `dictionary`，蓝图派生另带 `resultSource`。

状态含 `resolved`、`missing`、`conflict`、`override`。普通字段冲突暂取优先候选并列出差异，不丢弃其他候选；整包质量降为 `review-required`。关键配方冲突不会降级通过。没有输入的非必需面板字段可省略，已经参与翻译或配方解析但没有值的字段可在 provenance 中标为 missing。

`issues.json` 含代码、严重度、实体、字段、说明和来源。`source-records.json` 完整保留范围内每份源记录，`coverage.unmodeled` 列出未建模的顶层键。当前 828 是“按记录和来源累加的顶层键次数”，不是 828 种独立语义。攻击模式、更新日志、技能细节等仍可在原始记录查看，不能因为保留了原文就称为统一建模完成。

## 人工规则与版本

`merge-overrides.json` 默认 `{ "version": 1, "entries": [] }`。示意条目：

```json
{
  "entityId": "/Lotus/Weapons/Tenno/LongGuns/SapientPrimary/SapientPrimaryWeapon",
  "field": "stats.rivenCoefficient",
  "expectedSourceHash": "此字段某个有效候选源文件的64位SHA-256",
  "value": 0.65,
  "reason": "审阅说明与依据"
}
```

占位哈希不能直接执行。仅允许规范中已声明的标量、两种语言名称／描述、配方 credits／seconds／quantity。禁止改 ID、成品和材料关系。字段重复、空原因、哈希过期、越界或类型错误、未匹配范围均停止构建。补丁写入单独版本文件，不改原始来源；GUI 暂无补丁编辑器。

`manifest.json` 包含 schemaVersion、mappingVersion、builderVersion、contractHash、overridesHash、inputs、files、scope、quality、summary。`datasetVersion` 为其余清单内容按稳定序列化后的 SHA-256；输出条目的 hash 为实际文件字节哈希，包含格式化末尾换行。App 接入时先核对 schemaVersion，再逐文件验证 bytes/hash。物品规范变化升 schemaVersion，映射或优先级变化升 mappingVersion，构建逻辑修复更新 builderVersion。

## App 离线试接约定

先把完整导出目录作为独立静态资源使用。读取 `search.zh-CN.json` 建列表和检索，按 kind 读取对应 `items` 分片，以 ID 建 Map。详情按 `recipes` 和 `relations` 关联；奖励按 `reward-tables` 的 itemId 找名称与数量。不要用数组位置、翻译名称或图片文件名作关联键。

本版没有实现 App 导入代码，也没有为 uni-app 的各端规定磁盘 API；由 App 同事封装一个读取 JSON 的适配层即可。开发阶段保留 reports 以便核对，正式移动包后续增加独立的 slim 构建规范与 manifest，不直接删改当前包。ECS API、云存储和在线增量更新留在规范稳定后的独立里程碑。
