## 如何复验

```bash
npm run check
npm test
npm run build:data -- --root . --store artifacts/p3-build-store --out artifacts/p3-delivery
node scripts/check-ui.mjs node_modules/electron/dist/Electron.app/Contents/MacOS/Electron .
```

界面脚本默认使用自建临时图片和资料副本，结束后删除副本，不修改原资料；可以设置 `WORKBENCH_IMAGE_ROOT` 指向实际本地图库，以核验真实图片。桌面用户配置与测试配置隔离，不关闭用户正在运行的应用。

核心验收包含：

- 同一输入重复构建字节和版本一致，原 JSON 字节不变。
- 完整路径合并、语言优先级、32% 暴击、0.65 紫卡系数与 1 档分开、战甲 power 映射为能量容量。
- 所有范围内配方和奖励引用闭合，材料及产品关系可导航。
- 奖励现金／内融换算、蓝图命名、原始概率及完整 8 项奖励池。
- provenance 的候选原值、源文件哈希、指针、字典与派生成品来源逐项验证。
- 缺引用、循环、重复 ID、关键配方冲突、坏概率、输入中途变化阻止发布。
- 人工规则的过期哈希、重复、越界和未匹配规则拒绝。
- 构建与导出文件校验、损坏检测、失败保留旧版、快照／目录隔离。
- 图片完整 ID、文件名、大小写唯一匹配、路径逃逸／符号链接逃逸拒绝、无图与伪图片降级。

界面验收包含五个顶层入口、原 JSON 的五种视图、官方集合层保留卡片、完整卡片详情、来源跳转、合并搜索和类别筛选、关系跳转、四个汇总视图、失败提示及 1080 宽度无横向溢出。原 Oracle、browse.wf 和赏金检查仍执行。

本次语法检查 55 个文件；核心测试共 63 项。最终打包与运行证据补充在本文末尾。开发输出保存在不进入 Git 的 `artifacts/p3/`、`artifacts/ui-result.json`，截图有 `ui-catalog.png`、`ui-detail.png`、`ui-rewards.png`、`ui-issues.png`、`ui-narrow.png`。

## 3～4 位同事如何分工

先约定统一 ID、语言键、单位、provenance 和 manifest，再分数据域；不能让每人各做一套不兼容的输出结构。共用规范修改由一个集成人审核，减少同时改动 build 主流程的冲突。

| 角色 | 可以独立开展的任务 | 交付物与验收 |
| --- | --- | --- |
| A：输入与武器 | 新来源适配、主副近战武器、攻击模式建模；核对面板与模式单位 | 独立 adapter／字段规范、少量固定向量、来源指针；不把百分数直接放入比例字段 |
| B：战甲与制作 | 战甲技能、同伴／守护等实体，蓝图和材料闭包 | 分类扩展、关系文件、缺引用及循环检查；蓝图与成品 ID 分开 |
| C：奖励与中文 | 扩展其他赏金清单、奖励类型、字典缺项和差异复核 | 完整表路径映射、包数量依据、翻译来源、已审阅补丁；不按任务排序猜阶段 |
| D：集成与 App | 构建器／规范版本、工作台问题视图、App 离线读取和 manifest 校验 | 可复现包、列表／详情／配方／奖励联调、验收报告及发布决定 |

如果只有 3 人，由负责集成的人兼任 C；不要让 A 和 B 同时重写 manifest 或核心裁决逻辑。图片可交给 C 按稳定 ID 建索引，界面展示交给 D。复杂模式字段先提交规范提案和两三条真实样例再扩展，不能直接把来源对象塞进统一 stats。

建议每人每次只新增一个数据域／一组明确映射，提交以下五项：输入文件及固定哈希、字段含义与单位、转换规则、异常样例、可复现输出和测试。仍然未知的内容进入 issues／unmodeled，明确边界后再推进。

## 下一轮推荐里程碑

1. App 同事用本包走通离线列表 → 中文详情 → 配方材料 → 奖励项；记录缺的 UI 字段和磁盘读取适配。本轮只提供数据合同，没有改动 App 仓库。
2. 复核当前 51 项文字差异；制定字段级而非整个来源的优先级，并通过规则／补丁形成可审阅的决定。
3. 把武器、战甲、资源、蓝图扩到全量，增加明确的范围配置和全量覆盖率阈值；攻击模式单独建模。
4. 增加 App slim profile、独立图片 manifest 和分包大小指标；完整开发包继续保留报告。
5. 数据合同稳定后再设计 ECS 只读 API／版本清单下载，uniCloud 是否持久化业务数据另行决定。先做一致的离线数据，再增加发布和在线更新。

本轮不把“需要人工复核”的数据自动升级为正式发布；不接真实邮箱、不部署 ECS、不上传云空间。后续服务端可以直接消费相同分片和 manifest，无需重新发明物品 ID。
