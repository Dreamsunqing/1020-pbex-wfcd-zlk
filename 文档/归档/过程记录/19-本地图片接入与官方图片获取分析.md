# 本地图片接入与官方图片获取分析

应用版本 0.8.0；本地盘点与联网样例核对：2026-10-22。先完成 P3 和桌面打包，再进行本节联网分析。只请求了明确列出的少量样例，没有批量下载官方图库。

## 本版图片已接入什么

本机发现目录：

```text
/Users/dream/Desktop/tools/给写攻略人员准备的图片提取工具/assets/content/
├── catalog.json
└── img/                  # 12,233 张，621,154,171 字节
```

这套图库来自 WFCD 固定提交 `20f8d9427a5a62268817853eefd8962d18c0b70e`，经另一个图片工具整理为哈希文件名。它是社区处理的素材副本，不能称为 DE 原始下载字节。

工作台“配置 → 本地图片”支持选择上面的 content 或 img，也支持标准 WFCD `data/img`。本机可尝试识别资料目录旁既有图片工具；换电脑后可重新手选。图库目录保存在本机偏好，不硬编码到数据包，也不放入桌面 ZIP。

匹配规则：

1. 有相邻 `catalog.json` 时，按统一实体 ID 精确匹配 `items[].id`，取 `assetName`。只采用 `hasImage=true` 且 `imageKind=original`，不自动拿敌人参考图冒充原图。
2. 普通 WFCD img 用记录 `imageName` 精确匹配文件名；无精确项时允许唯一、无歧义的大小写匹配。
3. 不按中英文名称模糊搜索，不按相似名字拼 URL；冲突或缺图保留文字。哈希目录不能直接用 `imageName` 找文件，必须先查 catalog。

实际样本有 45／51 张原始图片可匹配，6 项缺图是两种现金包以及 Gauss 三个部件蓝图、Gyre 头部神经光元蓝图。原 JSON 卡片及合并卡片均可显示本地图片，保持精简列表和统一卡片高度；详情仍是单张完整卡片。缺图不显示破损图片占位。

后台限制只读所选目录的 PNG／JPEG／WebP，核验文件签名、真实路径及大小；不接受任意路径或 SVG 脚本。单图上限 2 MiB，每批最多 80 项、16 MiB。图片通过受限 IPC 返回 data URL，不让页面直接读取任意本地文件。

## 真正的官方数据里有什么

对本包官方英文目录的所有 JSON 递归扫描键和值，图片类字段集中在：

```text
official-public-export/manifests/en/ExportManifest.json
  Manifest[].uniqueName
  Manifest[].textureLocation
```

本地快照统计：

| 项目 | 数量 |
| --- | ---: |
| Manifest 项／不同 uniqueName | 20,144／20,144 |
| 不同 textureLocation | 12,624 |
| PNG 引用 | 18,478 |
| JPG 引用 | 1,666 |
| 15 个语言目录的 ExportManifest 内容哈希种类 | 1 |

多个物品共享图片，所以“物品条数”不能当成“需下载图片数”；15 个语言副本不应重复累计。此次扫描没有在其他英文官方导出文件发现 `imageName`、`img`、`icon` 等同类图片键；不要因此把 Plus 的 `icon` 字段混称官方字段。该结论只描述本地快照，不保证未来官方格式永不变化。

## 官方图片的正确链路

物品的 `uniqueName` 是索引键，不是图片 URL。按完整键查 Manifest 后，保留 `textureLocation` 全值，包括 `!00_...` 版本标识：

```text
物品 uniqueName
→ ExportManifest.json: Manifest[].uniqueName
→ 对应 textureLocation
→ https://content.warframe.com/PublicExport/ + 去掉开头斜线的 textureLocation
```

这与 [WFCD 固定提交的实际下载实现](https://github.com/WFCD/warframe-items/blob/20f8d9427a5a62268817853eefd8962d18c0b70e/build/build.ts#L278-L307)一致：先按完整 ID 找清单，再访问官方 content 主机。WFCD 的 [文件名解析代码](https://github.com/WFCD/warframe-items/blob/20f8d9427a5a62268817853eefd8962d18c0b70e/build/parser.ts#L577-L590)则去掉版本后缀取 basename，形成 imageName；因此 imageName 不能单独还原完整官方资源 URL。

迅发电浆炮样例：

```json
{
  "uniqueName": "/Lotus/Weapons/Tenno/LongGuns/SapientPrimary/SapientPrimaryWeapon",
  "textureLocation": "/Lotus/Interface/Icons/StoreIcons/Weapons/PrimaryWeapons/Weapons/SapientPrimaryWeapon.png!00_uZ982neYQf9WURACyrZgpA"
}
```

对应[官方图片地址](https://content.warframe.com/PublicExport/Lotus/Interface/Icons/StoreIcons/Weapons/PrimaryWeapons/Weapons/SapientPrimaryWeapon.png!00_uZ982neYQf9WURACyrZgpA)。不要再加 `/Manifest/`，也不要去掉版本后缀。后缀是上游资源版本标识，不能当成下载文件的 SHA-256；本地仍需另算字节哈希。

最小解析示意（不自动发起下载）：

```js
const imageById = new Map(exportManifest.Manifest.map(row => [row.uniqueName, row.textureLocation]));
const texture = imageById.get(item.id);
const url = texture ? 'https://content.warframe.com/PublicExport/' + texture.replace(/^\/+/, '') : null;
```

如果需要取最新清单，先获取官方 `origin.warframe.com/PublicExport/index_en.txt.lzma` 并解压，从中找 `ExportManifest.json!版本标识`，然后向 `content.warframe.com/PublicExport/Manifest/` 请求这个完整版本化清单名。清单下载路径和图片下载路径不同，不能混用；本项目现有官方更新器已具备索引及清单下载流程，未来可在其后增加独立图片任务。

## 本次实际下载核对

| 样例 | HTTP | 正文类型／尺寸 | 字节 |
| --- | ---: | --- | ---: |
| 迅发电浆炮，完整后缀 | 200 | PNG，512×512 | 44,043 |
| Gauss | 200 | PNG，512×512 | 91,311 |
| Gyre 头部神经光元蓝图 | 200 | 通用头部部件 PNG，512×512 | 49,244 |
| 神经元 Neurode | 200 | PNG，512×512 | 42,729 |
| Gauss 疾驰增幅 Mod | 200 | JPEG 插画 | 26,498 |
| 迅发电浆炮，去掉后缀对照 | 404 | HTML 错误页 | 196 |

这些官方响应本次未提供 Content-Type，因此除了 HTTP 状态，还核验 PNG／JPEG 文件头；不能只检查扩展名，也不能把 200 的 HTML 当图片。一个 Mod 的 JPG 是插画素材，并不是带文字、等级、极性等元素的完整游戏卡面。蓝图清单指向通用部件图也正常，不应据此声称拿到了专属成品渲染图。

实测记录（含时间、完整地址、大小、签名和 SHA-256）见 [P3图片获取实测.json](../数据报告/P3图片获取实测.json)；本地盘点见 [P3图片字段核对.json](../数据报告/P3图片字段核对.json)。这是样例成功证据，不代表 12,624 个资源均已逐个检查，也不承诺 CDN 永久可用。

## Plus／browse.wf 补充路线

这部分为社区数据提供的补充索引，和官方 Manifest 分开：

| 输入字段 | 获取方式 | 性质 |
| --- | --- | --- |
| Plus 导出记录 `icon` | 查 `ExportImages.json[icon].contentHash`，拼 `官方 PublicExport + icon + ! + contentHash` | 社区索引、官方 CDN 资源 |
| Plus `icon` | `https://browse.wf` 加完整路径 | 社区镜像，可用但不是官方主机 |
| `ExportImages[icon].forumName` | `https://media.invisioncic.com/Mwarframe/pages_media/<forumName>.png` | 某些浮印的论坛素材，不是所有物品通用 |
| 只有 `/Lotus/...png`，无版本信息 | 先查官方 Manifest 或 Plus ExportImages；仍无项则标缺失 | 不能直接猜一个官方 URL 一定有效 |
| `uniqueName`／语言键／任意含 png 的描述文本 | 先判断字段语义，再决定是否索引 | 关键词命中不等于图片地址 |

这些路线依据 [Plus 项目的图片说明](https://github.com/calamity-inc/warframe-public-export-plus/blob/senpai/README.md#images)。本包 `ExportImages.json` 有 12,467 条，其中 12,466 条带 contentHash，1,347 条带 forumName。用 DanteGlyph 样例，官方带 hash、browse.wf 镜像、forumName 三种地址本次均为 HTTP 200 且为 512×512 PNG，字节数及哈希不同。它们不是字节等价的镜像；单凭大小不能判断哪张视觉质量最好。

还可从已安装游戏中通过资源导出工具离线导出内部纹理，但需另一个解析流程；本次未执行。不能把任何 `/Lotus/...` 内部资源路径简单改后缀就当可公开下载图片。

## 对 P3 下一阶段的建议

当前 51 实体有 49 个能在官方 Manifest 精确找到，其中包括本地缺失的四个部件蓝图；两个现金包无对应项。图片应继续作为独立资产层：

```text
itemId → imageRef（来源、textureLocation、版本、原图哈希、尺寸）
       → 可选缩略图及本地文件
```

后续若决定实现官方补图，优先按完整 ID 精确查表，只为缺图实体下载；相同 textureLocation 去重，验证文件头、尺寸与字节哈希，保存独立图片 manifest，并将缺失状态显式记录。先在电脑生成稳定缓存，再给 App 做缩略图／按需包。不要让可选图片失败阻止规范 JSON 构建。

本版只接本地已有图片，联网样例保存在开发 artifacts 中；尚无后台自动补图、官方图片批量下载、图片 ZIP 或 App 图片更新协议。JSON 导出包保持独立可用。

## 可复现脚本

```bash
node scripts/analyze-images.mjs                 # 仅本地统计
node scripts/analyze-images.mjs --probe         # 固定少量联网样例
node scripts/analyze-images.mjs /path/to/世界状态上游 --probe
```

报告写入 `artifacts/p3/official-image-inventory.json`、`official-image-probes.json`；成功样例写入 `image-probes/*.bin`，不触碰原始资料或本地 WFCD 图库。扩展名 bin 仅用于保存证据，实际类型按签名识别。
