# 打包与备份保留策略（0.9.0 起）

用户约定：后续不再打 Mac arm64；所有项目生成备份只留上一版。采用滚动规则“当前版本 + 一个上一版本”，上一版应用仅保留 ZIP。

原先当前 0.8 时，应保留最新 0.7 ZIP；本次交付 0.9 后保留 0.8 ZIP，再次交付新版时继续向前滚动。不会长期同时堆积多份 0.7 小版本。

## 各类产物的处理

| 对象 | 保留规则 | 清理时机 |
| --- | --- | --- |
| 应用安装包 | 当前 Mac x64／Windows x64 ZIP + 上一个版本对应 ZIP | 两端生成并通过校验后运行 retain:packages |
| 旧 blockmap／Mac arm64 | 删除旧 blockmap、arm64 ZIP 和 mac-arm64 解包目录 | 同上 |
| 当前解包应用 | 保留，供本机运行和验收 | 下一次打包覆盖 |
| 合并规则 | current.json + previous.json | 每次成功保存 |
| 上游快照 | 当前快照 + 切换前一版 | 每次成功发布／回滚 |
| 快照内容对象 | 保留被上述两版及下载候选引用的对象 | 成功更新／导入／回滚后，在更新锁内回收 |
| 合并构建 | 每个目录／快照上下文保留当前 + 上一成功构建 | 成功构建切换后 |
| 导出数据包 | 同一导出父目录保留当前 + 上一个生成目录 | 成功导出后 |
| 验收临时文件 | 仅保留本轮必要报告／截图；重复数据包清理 | 验收结束 |

多个资料目录、快照上下文或多个导出父目录各自独立，不能把所有项目的资料合并当作一套备份。下载候选是失败续传缓存，不是完整历史版本。切换失败不会删当前成功版本。

导出清理只识别 `SourceWorkbench-data-<12位版本前缀>`、manifest 身份正确且没有额外用户文件的生成目录。无法确认归属的目录跳过；不要依赖自动清理删除手工改名、另存的包或其他父目录中的文件。

**不清理：**原始 `世界状态上游/`、本地图库、Git 提交历史、其他项目目录。文档中的历史验收记录可以保留，它们不是大体积应用／资料副本。自动策略不能清理人为散落到任意位置的文件。

## 打包命令

```bash
npm run pack:all
```

依次运行：Mac x64 → Windows x64 → verify:packages → retain:packages。Mac 构建在 macOS 运行；Windows ZIP 可在本机跨平台生成。`pack:mac` 只含 `--x64`，不再请求 arm64。

也可分别运行：

```bash
npm run pack:mac
npm run pack:win
npm run verify:packages
npm run retain:packages
```

只生成一个平台时保留策略会拒绝清理，先保留旧完整交付。不要在失败构建中手工删除唯一可用版本。`dist/备份保留策略.json` 记录保留版本、文件和已释放 ZIP 字节数；解包目录释放量不计入该字节统计。

verify:packages 对两端 app.asar 中全部源码和主要 package 元数据逐一比对当前工作区，记录 ZIP SHA-256。Mac x64 另做实际启动和界面验收；Windows 本机没有实机运行条件，仅做归档、源码和结构校验。当前包未做开发者签名／公证。

Apple Silicon 不再收到原生 arm64 包，需要 Rosetta 运行 x64 包。持续集成仍是 macOS／Windows 两平台矩阵，没有额外 arm64 构建目标。

## 回滚与空间

快照回滚只能选择保留的上一版；回滚后原当前版成为上一版，可再次切回。重复发布同一版不挤掉上一版。规则回滚先载入 previous 为草稿，再保存及重建。构建重复输入复用已有版本，也不挤掉比较基线。

合并工作包包含完整多语言参考和逐字段报告，体积明显大于 App 真正需要的运行分片。复核时保留完整工作包，App 接入前按类别和字段裁剪；图片独立保存并按需读取。暂存目录仅在构建中存在，正常失败会清理，硬退出遗留目录可在确认无构建任务后删除。

本轮清理后，`dist/` 仅保留 0.9.0 和 0.8.0 的两端 x64 ZIP；`artifacts/` 保留当前全量数据 ZIP、上一版 0.8 小闭环 ZIP及必要验收记录，删除重复的解压全量导出和旧测试快照缓存。按目录占用统计约减少 3.3 GiB，不计原始资料与图库。
