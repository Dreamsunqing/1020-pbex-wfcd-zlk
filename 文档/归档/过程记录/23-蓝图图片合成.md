# 0.9.1 蓝图图片合成

日期：2026-10-22。目标是让“xx 蓝图”同时呈现蓝图底纹和对应的成品，不再只显示通用 blueprint.png。

## 展示与数据边界

在资料浏览和合并汇总的卡片列表、卡片详情中，使用两层图片：底层为本地蓝图底纹，顶层为对应成品的本地图片，前景缩至容器的 84% 并居中。列表保持原来 62×62 图片区域和统一卡片尺寸，详情沿用 140×100 图片区域。图片不增加描述行。

这是 DOM/CSS 显示合成，不会生成新图片文件，不改原始 JSON、规范数据包或 WFCD 图库，也不联网补图。图片仍是可选资源。

## 关联顺序

| 场景 | 蓝图到成品的关联 | 成品图的查找 |
| --- | --- | --- |
| 合并汇总 | recipes.json 中 id 对应的 resultId | catalog.items[].id 精确匹配；普通目录回退为该成品的 WFCD imageName |
| 原 JSON 配方 | 当前记录的 resultType | catalog 精确匹配 |
| 原 WFCD Components | 图片为通用 blueprint.png，且 catalog 中该记录仅有一个不同于自身的 parents ID | catalog 精确匹配 |

明确给出的配方产出物优先于图库 parents；即使该成品缺图，也不会转用另一个 parent。parents 有多个、存在不同 parent 的重复索引或只有自引用时，不随意挑选。

哈希图库通过原图索引中的 imageName 或 resolvedImageName=blueprint.png 获取底纹 assetName；标准目录直接查 blueprint.png，允许唯一无歧义的大小写匹配。成品图片本身仍是通用蓝图时，不将其当作成品继续递归叠图。

不使用中文标题去掉“蓝图”、删除英文 Blueprint 后缀或模糊名称搜索来推测身份。名称包含 Blueprint、但并无通用底图或配方关联的普通物品，不自动套蓝图。

## 缺失与校验

- 两层均有：返回两层图片和角色标记，页面按底纹、成品顺序叠放。
- 只有底纹：显示底纹。
- 只有成品：显示成品。
- 两者均无：保留蓝图自身可用图；仍无图片时保留文字卡片。
- 继续只接受原图索引、PNG/JPEG/WebP 签名、所选根目录内的真实路径。单文件 2 MiB、每批 80 项及总计 16 MiB 限制同时适用于两层。

`npm test`：69 项通过；`npm run check`：64 个文件语法通过。

定向界面脚本 `scripts/check-blueprint-ui.mjs` 验证 Gauss 合并列表、合并详情、原 WFCD Components 列表及详情都存在两层图；检查实际图片已加载，以及 1080 宽窗口无整体横向溢出。该脚本使用隔离的临时用户目录和小闭环数据，不覆盖用户现有全量合并版本。

```bash
node scripts/check-blueprint-ui.mjs node_modules/electron/dist/Electron.app/Contents/MacOS/Electron .
# 打包后复用同一流程
node scripts/check-blueprint-ui.mjs 'dist/mac/Source Workbench.app/Contents/MacOS/Source Workbench'
```

截图和报告位于 artifacts/blueprint-ui/。Mac x64 包执行上述界面验证；Windows x64 校验打包内容，未在 Windows 实机运行。0.9.1 不重发未改变的规范 JSON 数据包。应用 ZIP 滚动保留 0.9.1 当前版与 0.9.0 上一版，不生成 Mac arm64。
