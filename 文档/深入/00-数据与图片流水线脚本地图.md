# 数据与图片流水线脚本地图

本文是当前实现的脚本入口清单。先认识“输入、处理、产物”，再看具体适配器。所有路径相对资料包项目根目录；可执行入口统一放在 `工具/`，维护实现仍在 `scripts/` 和 `src/core/`，不复制第二套业务代码。

## 六个阶段

| 阶段 | 可直接运行的入口 | 实际实现 | 读什么 | 写什么 |
| --- | --- | --- | --- | --- |
| 获取数据 | `node 工具/01-获取数据.mjs` | `src/cli.mjs update`；`src/core/updater.mjs`；`src/core/store.mjs` | `config/default.json`、官方与 GitHub 来源 | `.workbench` 内容寻址快照、版本与差异；不覆盖离线原件 |
| 处理数据 | `node 工具/02-处理数据.mjs` | `scripts/inventory-structure.mjs`；`library.mjs`、`json-structure.mjs`、`field-guide.mjs` | `世界状态上游` 各 JSON | `输出/数据处理/字段结构清单.json`；逐文件字段与未解释项 |
| 合并数据 | `node 工具/03-合并数据.mjs` | `scripts/build-merge.mjs`；`src/core/merge/` | 本地原件或指定快照、规则和修订 | `.workbench/merged` 及 `输出/合并数据` 的版本化实体、配方、奖励、溯源与报告 |
| 获取 WFCD 图片 | `node 工具/04-获取WFCD图片.mjs` | `scripts/prepare-data.py`、`image_resolver.py`、`enemy_report.py` | 固定 WFCD 快照压缩包；首次按本地快照 commit 下载 | `assets/content/wfcd/img`、目录与映射索引 |
| 获取官方图片 | `node 工具/05-获取官方图片.mjs` | `scripts/fetch-image-libraries.mjs --official-only` | 官方 `ExportManifest.json` 中的 `uniqueName → textureLocation` | `assets/content/official/img` 与 `official/index.json` |
| 处理图片 | `node 工具/06-处理图片.mjs` | `scripts/complete-image-libraries.py` | WFCD 固定 Git 清单、现有图片和官方索引 | 完整图片索引、校验表、来源覆盖比较；这是耗时维护操作 |
| 合并图片 | `node 工具/07-合成蓝图.mjs --id /Lotus/Types/Recipes/WarframeRecipes/RunnerBlueprint --result-id /Lotus/Powersuits/Runner/Runner` | `scripts/compose-blueprint.mjs`；`src/core/image-composition.mjs` | 蓝图底纹与精确成品图 | `输出/蓝图合成/*.png`；不改原图、不猜成品 |

“处理数据”负责理解结构，不代替 P3；“合并图片”是蓝图的视觉叠加，不把 WFCD 和官方两套源图片互相覆盖。普通资料导出不把图二进制塞进 JSON。

## 推荐顺序

已有离线资料时，先读 [十分钟上手](../入门/01-十分钟上手.md)，用“资料浏览 → 合并规则 → 合并汇总”了解结构；需要 CLI 构建时再运行 02、03。图库已经存在就直接使用，不必重新下载或扫描全部图片。

联网更新得到的是新快照。要用该快照构建，给 03 传 `--release 完整版本ID`；不传时仍合并本地 `世界状态上游`。本地原件与已更新快照不能默默混用。
