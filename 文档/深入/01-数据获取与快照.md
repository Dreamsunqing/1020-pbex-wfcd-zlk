# 数据获取与快照

本文描述数据从来源进入工作台的过程。操作入口见 [脚本地图](00-数据与图片流水线脚本地图.md)；本轮未执行下载、扫描或测试。

## 来源登记

`config/default.json` 是默认来源清单，包含启用状态、语言、并发、时间间隔、GitHub 仓库和分支。来源是否进入实体由合并规则另行决定，不是“启用了来源就把所有文件当物品”。

| 来源 ID | 离线原件位置，相对 `世界状态上游` | 主要用途 |
| --- | --- | --- |
| official | `official-public-export/manifests/<语言>` | DE 本地化公开导出、物品及官方图片 Manifest |
| plus | `git/warframe-public-export-plus` | 以内部路径为键的物品、配方、奖励、任务结构和语言字典 |
| wfcd | `wfcd-items/data/json` | 按类别组织的物品数组、嵌套技能／组件、中文物品字典、imageName |
| oracle | `git/wf.browse.oracle` | JobManifest、字典和推算参考规则 |
| browse | `git/browse.wf` | 周轮换规则、周期、突袭和仲裁排期 |
| plus-gen | `git/warframe-public-export-plus-gen` | 生成器参考、专用提取的技能移植与强化元数据 |

Plus、WFCD 等是社区来源，不应统一标成“DE 官方”。上游代码可用作研究材料，工作台不直接执行抓取的 PHP、TypeScript 或 Lua。

## 两种获取方式

### 已经有离线原件

`src/core/library.mjs` 扫描资料根目录，根据配置识别来源、相对路径和可读文本；`src/cli.mjs import` 把当前原件导入内容寻址快照。导入不等于合并。

```sh
node src/cli.mjs import --root . --store .workbench
```

早期固定原始资料包还提供 `工具/按快照重新获取.py` 和 `工具/缓存WFCD无图片.py`。前者按已有 snapshot-manifest 固定重建到新目录，后者保留 WFCD 文本快照并排除图片。它们不是新版增量更新的替代品，参数与用途见 [工具手册](06-工具运行与协作手册.md)。

### 联网更新到新快照

```sh
node 工具/01-获取数据.mjs
```

实现集中在 `src/core/updater.mjs`。官方先获取 `index_<语言>.txt.lzma`，解压后按带版本的 Export 文件名获取 Manifest JSON；GitHub 来源先固定分支的 commit，使用 tree 中的路径、大小、Git blob SHA-1 获取和校验文本。网络超时、响应大小与重试由获取层处理。

下载的字节通过 `src/core/store.mjs` 写入 `.workbench/objects/<哈希前缀>/<SHA-256>`。只有准备完成的发布清单切换为 current；文件按哈希复用，不用再复制一套相同文本。具体历史、回滚和差异可用 CLI 或“更新与版本”查看。

## 三个版本身份

1. 上游版本：Git commit、官方版本化文件或语言索引。
2. 来源快照：发布清单 `releaseId`，决定“当时输入的是什么”。
3. 合并版本：`datasetVersion`，还包含规则、修订和输出哈希。

运行默认 `node 工具/03-合并数据.mjs` 合并的是本地原件。要合并刚获取的快照，显式传 `--release 完整releaseId`。不允许从新快照取实体，再从当前本地目录取字典拼出一个无法复现的结果。

## 桌面版与 CLI 的路径

CLI 工具箱默认使用项目 `.workbench`。Electron 桌面版默认在系统应用用户目录保存 snapshots、preferences 和 merge-rules；`WORKBENCH_USER_DATA` 可以隔离该目录，`WORKBENCH_ROOT` 可以指定初始资料根目录。它们不是同一个存储上下文。

定时更新只有应用／CLI watch 保持运行才会执行。邮件 `notifications.email.enabled` 目前必须保持 false。GitHub 凭据只从 `GITHUB_TOKEN` 环境变量读取；文档、配置、报告和命令预览都不应写入密码或令牌。
