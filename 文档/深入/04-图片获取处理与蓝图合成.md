# 图片获取、处理与蓝图合成

图片按来源保存，显示时根据完整 ID 和索引关联。不要把 WFCD 图片数、官方物品 ID 数、纹理 URL 数和内容去重文件数混成一个统计。

## 当前目录

```text
assets/content/
  wfcd/
    img/                       WFCD 完整原图，哈希化原始文件名
    catalog.json               顶层物品、中文、部件关系和配图状态
    wfcd-image-index.json       全部原图名、嵌套技能／物品 ID 映射
    checksums.json             图片内容和目录校验
    data-report.json
    enemy-image-report.json
    enemy-images.csv
    UPSTREAM-LICENSE.txt
  official/
    img/                       官方内容去重原图
    index.json                 uniqueName、textureLocation 与本地文件
    ExportManifest.json        用于这份图库的原 Manifest
  image-library-comparison.json
```

`.workbench/official-images` 仅是指向 `official` 的兼容符号链接，不是第二套图库。历史文档中的 `content/img`、`official-public-export/assets` 已失效，以本篇为准。原攻略图片提取工具已经合并删除，不要重建它来存图。

目录调整仅移动实体和索引，不重新下载、不改图片字节。目录选择器支持共享 `content`、`wfcd` 或 `wfcd/img`；完整双源图库需要两套索引及其父目录。

## WFCD：获取与建立目录

入口 `工具/04-获取WFCD图片.mjs`，实现 `scripts/prepare-data.py`。

首次下载默认读取本地 `世界状态上游/wfcd-items-snapshot.json` 的 commit，获取该提交完整 tarball；已有 archive 则使用指定包。只有明确传 `--refresh` 才查询 master 最新提交。准备程序从 tarball 读取 JSON 和图片，不把任意上游路径直接解压进文件系统。

原始图名可能只在大小写上不同，所以磁盘名为“原图名 SHA-256 的前 24 位 + 扩展名”。它不是图片内容哈希，不要用磁盘名推断物品身份。`wfcd-image-index.json.images` 建立原图名到磁盘名映射，`mappings` 建立唯一 ID 到原图映射；有歧义的 ID 单独记录。

`image_resolver.py` 处理明确原图与经说明的敌人参考图，`enemy_report.py` 生成审核记录。参考图要标记，普通资料卡不能拿参考图冒充原始物品图。

准备只替换 `wfcd` 自己的输出，保留官方库。完整 WFCD 图片树都保留；技能常在嵌套对象中，暂未被顶层物品引用的图也不是垃圾文件。

## 官方：Manifest 到原图

入口 `工具/05-获取官方图片.mjs`，实现 `scripts/fetch-image-libraries.mjs --official-only`。

输入来自 `世界状态上游/official-public-export/manifests/en/ExportManifest.json` 的 Manifest：

`uniqueName → textureLocation → https://content.warframe.com/PublicExport/<textureLocation>`

textureLocation 可能带 `!` 版本后缀，下载地址保留完整值。不能把物品 uniqueName 后面直接补 `.png` 当下载 URL，也不能认为任何含 png／img 的字段都是可访问 URL。

下载器检查响应大小和 PNG／JPEG 签名，失败记录保留；磁盘用图片内容 SHA-256 命名，因此多个 URL 可以共用一个文件。`index.json.entries` 保存物品到纹理的关系，`assets` 保存成功纹理到文件的关系。每次显式维护支持检查已有文件和断点记录，不在浏览时自动联网。

## 整理、比较与缺图

入口 `工具/06-处理图片.mjs`，实现 `scripts/complete-image-libraries.py`。这是耗时维护，不是启动步骤，本轮没有运行。

它依据固定 Git blob 清单和现有 WFCD 图片重建完整索引；有 archive 可用于补齐，未保留大 archive 时也能核对现有完整树。官方按索引内容哈希核对。对齐 commit 失败应先解释来源版本，不能删除断言来生成“全通过”。

最近一次迁移前记录为 WFCD 12,543 文件、官方 12,501 个独立文件；这不是本轮重新扫描的结论。细节见 [历史复核](../归档/过程记录/27-WFCD完整图库恢复与官方图库复核.md)。新数量应来自以后明确执行的维护报告。

## 运行时图片解析

`src/core/local-images.mjs` 读取 WFCD 目录与完整索引，优先完整 ID／原图名。普通资料卡缺图时，后台可按完整 ID 查本地官方索引。`src/core/gallery.mjs` 把两套索引变成可搜索图库，图片协议只读取索引允许的本地文件。

卡片和图库读取不扫描每张图片内容，不偷偷联网，不按英文名模糊匹配。缺图允许保留文字和状态；不是必须把每条物品都配上图。

## 蓝图合成：底纹在下，成品在上

关联依据按场景选择：合并资料用配方 resultId，图库目录用单一明确 parent，导出工具可以显式提供经核对的 result-id。不可通过去掉“蓝图”或 Blueprint 后缀猜成品。

- JSON／合并卡片：`src/ui/images.js` 与样式中的 blueprint-layer 叠放，不改原图。
- 图片资源：`gallery.mjs` 产生两层键；`gallery.js` 预览同样叠放。复制、保存和批量导出通过主进程调用合成函数。
- PNG 合成核心：`src/core/image-composition.mjs`，透明画布，底纹全尺寸，成品按 84% 区域等比例居中。
- 可运行脚本：`工具/07-合成蓝图.mjs` → `scripts/compose-blueprint.mjs`，用项目 Electron 的离屏画布输出 PNG。

```sh
node 工具/07-合成蓝图.mjs --id /Lotus/Types/Recipes/WarframeRecipes/RunnerBlueprint --result-id /Lotus/Powersuits/Runner/Runner --out 输出/蓝图合成/Gauss-蓝图.png
```

普通图保存／导出保持原图字节，剪贴板写入 PNG 位图；可合成蓝图输出新 PNG，源底纹与成品图不覆盖。同名输出自动编号。缺底纹、缺成品或关系不唯一时，CLI 不生成误导性合成；页面保留可用单图。本文描述的是实现，新增合成与新目录布局尚未运行本轮验收。
