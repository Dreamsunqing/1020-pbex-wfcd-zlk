# 发布、空间与排错

## 应用、资料、图库分别交付

Mac x64 和 Windows x64 ZIP 位于 `dist`。完整离线使用还需要 `世界状态上游` 和 `assets/content`；程序本体包含当前 Markdown 文档，默认不包含原始资料和大图库。

开发版和发布版在完整项目附近运行时共同查找同一份图库。把应用复制到其他位置时，可在程序中重新选择资料根目录与 `assets/content`；只有应用没有图库时，允许保留文字资料和图片缺失状态。

根目录 `工具/09-打包程序.mjs` 只做两个 x64 包与保留策略，不运行测试。`npm run pack:all` 是维护流水线，仍包含交付文件验证。测试在打包前独立运行；打包过程另验证文件一致性。

## 存储约定

- 图像实体只保留 `assets/content/wfcd/img`、`assets/content/official/img`；兼容符号链接不算新副本。
- 原独立图片工具目录已删除，小型独有源码和许可证保留在 integrations，文档已移入统一归档。
- 应用 ZIP 仅保留当前版本和一个上一版，不再生成 Mac arm64。
- 合并仓库按上下文保留当前和上一构建；内容相同的文件优先用系统写时复制共享，路径仍独立。
- `scripts/storage-audit.py` 可审计 tools 下普通数据／文本并在 macOS APFS 上共享相同字节；这不是日常启动步骤。

此前删旧工具约 4.64 GB 是逻辑字节，另约 560 MB 相同内容使用 APFS 写时复制共享；不能把两数相加宣称精确释放磁盘容量。压缩包、程序运行目录、Git 历史、开发依赖各有用途，不按同名直接删除。

## 常见故障先定位

| 现象 | 先看什么 |
| --- | --- |
| 首页无响应、目录 0 个文件 | 查看启动错误；JSON 登记表要生成 JS 模块，不能放宽 CSP 以掩盖依赖加载失败 |
| 图库为空 | 配置目录是否为 content；wfcd/catalog 与完整索引是否齐全；official/index 是否齐全 |
| 技能有字无图 | 检查完整技能 ID 是否进入 wfcd-image-index；不要只看顶层 catalog |
| 蓝图只有底纹 | 配方 resultId 或单一 parent 是否明确；成品图是否缺失；不删除缺失判断来强行叠图 |
| 官方下载失败 | index.failures、纹理完整版本地址、代理和 HTTP 状态；404 不靠反复全库下载解决 |
| JSON 更新后名称没变化 | 是否仍在历史快照；字典与实体是否同一输入上下文；是否需要重新构建 |
| 图库目录切换后不一致 | 记录配置路径和状态；完整目录应该共同服务资料卡与图片资源 |
| 合并汇总没有刚导出的规则 | CLI 需传 --rules；桌面规则和内置规则是两个存储位置 |
| 文档还是旧内容 | 在完整项目里点刷新；独立应用的内置文档需要重新打包 |
| tools 的 du 数量看起来仍大 | APFS 共享区块可能被重复统计，不能直接按 du 判断物理副本 |

记录问题时附页面、完整文件／物品 ID、资料上下文、规则版本和 datasetVersion。先定位一条关联，不默认删除所有缓存、重新下载或扫描整个图库。
