# 展示规则、文本标记与配图修复

适用工作台 0.13.1，整理日期 2026-10-23。0.13.0 实现时按用户要求未测试；用户恢复测试后，0.13.1 修复启动故障并完成定点展示验证，新增真实文本图标。详见 [启动与图标验证](09-启动故障与真实文本图标.md)。

## 一、暗色模式与强化卡

`src/ui/style.css` 的 `.merge-issue`、`.merge-reward-table` 曾直接写 `background:white`，绕过主题。现在改为主题表面变量；关联卡、奖励子卡、强化卡和报告也统一使用 `--surface`、`--surface-soft`、`--accent-soft`、`--line`。

旧色号变量把按钮背景绿色和文字绿色共用，暗色替换后可能变成浅绿底深色字。强化跳转按钮现在用深绿 `--primary` 加固定浅色前景，普通可移植徽章使用单独的浅／暗紫色。

截图里的强化卡按钮原来插在 `h2.json-card-title` 内，标题有两行、40px 高度及隐藏溢出，按钮会被切掉。现在统一资料卡把强化徽章放到单独区域，保留点击跳转和无障碍名称。卡片高度统一为 220px，多条徽章时可滚动；不在标题里挤按钮。

## 二、哪些条目默认隐藏

入口“统一资料 → 显示内部定义”可恢复查看。实现为 `src/core/merge/display-policy.mjs`，只影响浏览列表，不删除实体、不删关联、不改变导出的合并数据，也不改原始 JSON。

规则一：实体的来源记录全部来自 Plus `ExportVirtuals.json`，没有另一来源的独立物品记录时，默认隐藏。该文件主要提供继承与兼容父类，不适合当独立武器卡陈列。若未来同一 ID 出现真正物品来源，自动不再命中这条规则。

| 截图或同类示例 | 源文件 | 可确认的作用 |
| --- | --- | --- |
| ExaltedSniperBase | ExportVirtuals.json | 肃清者的内部武器父类，继承 LotusSniperRifle |
| SlingerPistolsBase | ExportVirtuals.json | 监察者双枪的兼容／继承基类 |
| ChoirEruptWeaponBase | ExportVirtuals.json | 荣耀武器的内部父类 |
| KubrowPetAntigenBase | ExportVirtuals.json | 库狛抗原组件父类 |
| KubrowPetMutagenBase | ExportVirtuals.json | 库狛突变原组件父类 |
| MoaPetHeadBase、MoaPetEngineBase | ExportVirtuals.json | 恐鸟头部、核心组件父类 |
| MoaPetLegBase、MoaPetPayloadBase | ExportVirtuals.json | 恐鸟腿部、陀螺仪组件父类 |

本地该文件有 172 条记录，这是该输入文件的数量，**不是实际隐藏数量**；是否被其他来源补成真实物品，要按当前构建逐 ID 判断。

规则二：明确的通用源力石父类 `.../NarmerSorties/ArchonCrystal`、`ArchonCrystalMythic` 默认隐藏；保留六种具体颜色的普通与 Tau 物品。

不使用“没有图片”“没有中文”“名字以 Base 结尾”“excludeFromCodex／excludeFromMarket 为 true”作为通用隐藏条件。例如土石坍方是有明确数据和配图的技能武器，虽然不进图鉴，仍应展示。无法确认用途的条目宁可保留。

## 三、缺图的实际原因与处理

### 关联卡漏传配方成品

旧 `mergedDetail()` 仅为 `references` 中的 ID 生成图片描述；配方反向关系和部分技能关系只在 `relations` 中，不一定在物品字段里。因此卡片虽然能跳转，却拿不到 `blueprint`、`resultId`、`resultImageName`。

`src/core/merge/service.mjs` 现把物品、字段引用及正反向关系目标共同加入图片集合。组件、技能、制作蓝图、被配方使用等卡片全部沿用相同的完整 ID 解析；`src/ui/merge.js` 不再用空的 imageName 覆盖已有图标文件名。

截图中的暗杀者灵化之源蓝图来自：

`ExportRecipes.json` 的 `/Lotus/Types/Items/MiscItems/IncarnonAdapters/UnlockerBlueprints/SicarusIncarnonBlueprint`

其 `resultType` 精确指向 `/Lotus/Types/Items/MiscItems/IncarnonAdapters/Secondary/SicarusIncarnonUnlocker`。本地完整 WFCD 索引已包含成品图 `SicarusIncarnonAdapter.png`，磁盘名 `b0f8f59f2bcc84a522a21283.png`。应使用蓝图底纹叠上该成品图，无须下载或猜文件名。

### 图片本来是白色技能图标

土石坍方与 Prime 的 Plus `icon` 都为 `/Lotus/Interface/Icons/Abilities/AtlasRockPunch.png`。WFCD 实际有该文件，磁盘名 `c00a88e8f7deba121b420a1b.png`；定点查看确认它是透明底白色拳头标志，白底看起来像缺图。

现在图片描述同时携带明确 `icon` 与 `abilityIcon`。本地读取可从完整 icon 路径取精确原图文件名；能力图标使用固定深绿底，避免白图标消失。AtlasRockPunch.png 也单独登记为已确认的白色技能图标，供缺少 icon 元数据的旧构建使用。

### 大页响应预算

原图片读取每次最多 80 项、总字节预算 16 MiB，密集页面的大图可能用尽预算。UI 改为每批 16 项，保持顺序加载；实际文件仍经过大小、图片签名和目录边界校验。页面缺图不自动触发下载。缺少确切关联、文件不存在、文件过大等情况依然可能没有图，不以不相干图片填空。

## 四、Tau 源力石：普通叠底，辉光叠顶

实现登记在 `src/core/image-presentation.mjs` 的 `shardPairs`，只列出六个明确同色关系：Amar、Boreal、Nira、Green、Orange、Violet。

`.../ArchonCrystal<颜色>Mythic → .../ArchonCrystal<颜色>`

底图取普通同色源力石，顶图取原 Tau `*MythicGlow.png`；两图均等比例填充同一方形区域，不套用蓝图成品的 84% 缩放。Green 的原文件名是 `ArchonShardMythicGreenGlow.png`，由 ID 索引读取，不拼接推测文件名。

- 资料卡片：`local-images.mjs` 返回 `kind: tau-shard` 及 base／overlay 两层；`ui/images.js` 和样式叠放。
- 图片资源：`gallery.mjs` 同时对 WFCD／官方的 Tau 记录生成图层；同源普通图优先，必要时使用 WFCD 的精确普通图。
- 复制、保存、批量导出：复用 `image-composition.mjs` 的本地透明画布，导出合成 PNG。图库里的源文件仍是各自原图。
- 缺一层时保留可用图，不编造另一层。蓝图仍是底纹＋成品 84% 居中，两种布局不要混淆。

## 五、普通 Forma 的选图依据

官方 `ExportManifest` 和 Plus 资源 icon 均指向 `GenericComponent.png`；WFCD catalog 也采用这张。它不是错物品，而是 512×512、纵向透视的版本，所以小卡片中和其他 Forma 的方向、比例不一致。

本地 WFCD 完整图片索引另有：

| 图 | 本地文件名 | 处理 |
| --- | --- | --- |
| GenericComponent.png | 3a381597bb2714e345bc6b1c.png | 官方与 WFCD 原始映射，保留 |
| Forma.png | 5ea24b454665f27fda1dd80f.png | 256×256，定点查看后选为普通 Forma 的展示替换 |
| OmegaForma.png | 58b6d2de3af78d73e5f543f2.png | 全能 Forma 原图，保留 |
| StanceForma.png | fce5b3e87845cb4173a321fd.png | 架式 Forma 原图，保留 |

替换只针对完整 ID `/Lotus/Types/Items/MiscItems/Forma`。普通物品卡、蓝图合成成品层和 WFCD 图库使用 Forma.png；图库标注替换说明，保留 `sourceImageName`。官方图库来源继续展示官方原图，避免把人工选图冒充 DE 的映射。

不把同名文件批量替换，也不修改 WFCD catalog、官方 Manifest、来源 JSON 或源图字节。未来撤销只需移除 `imageOverrides` 的这一条。

## 六、名称／描述的 <xxx> 中间件

核心 `src/core/inline-tokens.mjs`：`createInlineTokenMiddleware(index)` 创建独立实例，`parse()` 输出安全片段，`plain()` 输出纯文本，`scanInlineTokens()` 输出观察清单。人工登记表为 `src/data/inline-tokens.json`，区分 icon、format、break；token 大小写敏感，实例不暴露可变全局登记表。

界面适配 `src/ui/game-text.js` 只创建 DOM 文本与 span／br／img，不使用 innerHTML；图片仅取受控离线清单，不加载原始 token 提供的 URL。已接入合并名称、描述、技能／组件名称、嵌套字段、资料卡与图库描述；原文、来源候选值、导出原始记录继续保留原 token，便于溯源。

| 输入 | 展示规则 |
| --- | --- |
| `<SHARD_RED_SIMPLE>深红执刑官源力石` | 名称省去重复装饰前缀，显示完整中文名 |
| `造成 <DT_FIRE> 火焰伤害` | 描述显示真实火焰伤害图标，悬停及无障碍替代文字显示中文 |
| `<CREDITS>`、`<ENERGY>` | 真实现金、能量图标及中文替代文字 |
| `<DT_FIRE_COLOR>` 等 | 按 ExportTextIcons 明确映射显示真实图标，保留后续文字 |
| `<br>` | 换行 |
| `<JUMP>`、`<USE>` | 跳跃、互动；不猜用户键盘／手柄绑定 |
| `<RETRO_TM>` | ™ |
| 未登记 `<TOKEN>` | 原样保留并加提示，不直接删除或误当 HTML |
| `|COUNT|` 等参数 | 本轮不推算具体数值，原样保留 |

0.13.1 按 ExportTextIcons 的 DIT_AUTO／DIT_PC 映射获取真实图片，随程序离线读取。0.13.2 已纠正：带 COLOR 后缀但有明确映射的标记使用真实图标，未收录项保留；操作绑定缺映射时保留中文说明。人工 JSON 经脚本生成 JS 模块供浏览器导入，避免触发 connect-src none。业务模块不各写正则。

维护入口：`node 工具/10-文本标记清单.mjs`，实际脚本 `scripts/inventory-inline-tokens.mjs`，显式遍历资料库 JSON 字符串，按 token 统计次数、最多 5 个来源指针及未知项，写 `输出/文本处理/文本标记清单.json`。不覆盖人工登记表，不在启动时扫描，不处理图片。本轮未运行该维护任务；前期只定点核对了 Plus 字典与相关实体文件的标记。

## 七、关联卡简化与仍可追溯

技能、组件、配方与强化卡的关联卡保留中文名、图片、数量、跳转和可展开来源，去掉卡片中常驻的完整 ID。ID 仍放在跳转按钮提示、详情和来源中，用于核对，不影响跳转键。

灵化配方可能既把某物品作为结果，也在 ingredients 中要求同一物品。旧 UI 分“被配方使用”和“制作蓝图”展示两张相同卡；现在合并为制作蓝图卡，并标记“亦作为该配方的材料”。底层两条关系保留，未改写配方含义。
