# 首页启动故障与真实文本图标

适用 0.13.1，2026-10-23。用户恢复测试，反馈停在首页，同时要求优先寻找已有图片与 browse.wf／Oracle 的真实文本图标。本文记录原因、资源、维护入口与验证范围。

## 首页为什么没有响应

0.13.0 的 app.js、merge.js、gallery.js 通过 game-text.js 引入 inline-tokens.mjs，后者直接 `import inline-tokens.json with { type: 'json' }`。Electron 的浏览器进程把 JSON 模块加载作为连接请求，命中页面原有 `connect-src 'none'`，整条模块依赖链失败。控制台可复现 `Connecting to file:///…/inline-tokens.json violates Content Security Policy`，`window.smokeReady` 未设置，目录保持 0 项。

这发生在页面初始化之前，与图库数量或全图像扫描无关。清缓存、全量重新下载图片不能修复它。

修复保留原 CSP：人工编辑 `src/data/inline-tokens.json`，`scripts/prepare-inline-tokens.mjs` 将它和图标清单合并，生成 `src/data/inline-tokens.generated.mjs`；浏览器与 Node 核心统一导入这个普通 JS 模块。没有增加对外连接权限。`npm start`、npm 打包入口、工具箱启动／打包都会先生成登记表；`npm run check` 和对应测试验证生成内容与输入一致。

新增 `src/ui/bootstrap.js` 捕获模块加载错误，在页面显示启动失败与错误原因，避免依赖加载失败时只留下静态首页。业务初始化错误仍由现有提示处理。

## 真实图标在哪里

本地 `世界状态上游/git/browse.wf/text-icons.php` 明确读取 `warframe-public-export-plus/ExportTextIcons.json`，按平台键取图片路径，图片地址为 `https://browse.wf` 加该路径。`browse.wf/common.js` 的 resolveTextIcons 也使用同一份映射。Oracle 本地项目没有另带更完整的文本图标映射，因此本轮沿用有明确代码依据的 Plus／browse.wf 路径。

本轮本地 ExportTextIcons 含 678 个标记。选择顺序为 DIT_AUTO，其次 DIT_PC；没有这两项的不猜其他平台图标、不拼接文件名。共有 623 个标记对应 587 个纹理路径。WFCD 索引按原图名能找到其中 25 个同名候选，但同名不等于完整纹理路径匹配，因此不靠同名直接挪用。

实际获取结果：

| 项目 | 结果 |
| --- | --- |
| 复用官方图库精确纹理路径 | 22 个 |
| 从 browse.wf 获取的其余纹理 | 565 个 |
| 获取失败 | 0 |
| 按内容哈希去重后的 PNG | 586 个物理文件 |
| 图标物理字节合计 | 21,292,423 字节，约 20.3 MiB |
| 实际运行时图片标记 | 624 个，含 DT_HEAT → DT_FIRE 明确别名 |

0.13.2 已纠正对 COLOR 后缀的误判：623 个源映射加 DT_HEAT 明确别名，共 624 个运行时图片标记。原始映射全部记录在下载清单，未改变上游 JSON。

## 目录、溯源与显示行为

- `src/data/inline-tokens.json`：人工中文解释、格式控制、换行、名称省略装饰等规则，扫描和下载不会覆盖。
- `src/data/text-icon-assets.json`：完整 token → 纹理 → 本地文件映射、来源、原始映射 SHA-256、每图字节数与 SHA-256、失败列表。
- `src/ui/assets/text-icons/<SHA-256>.png`：离线运行时图标。相同内容共用一个文件；这些属于应用界面小资源，大图库仍保持在外部 wfcd/img、official/img，不把大图库嵌入 ZIP。
- `src/data/inline-tokens.generated.mjs`：生成产物，不手工修改。
- `src/core/inline-tokens.mjs`：字符串转换为安全片段，原始 JSON 不回写。
- `src/ui/game-text.js`：创建 DOM 图片、文字、换行；不使用 innerHTML。

伤害、货币、能量等已有映射的描述显示真实游戏图片，标题提示和 alt 为中文。大量白色线条图标使用固定深绿小底，浅色和暗色下均保持对比度。图片路径仅允许本地哈希 PNG；不从源字符串拼任意 URL。缺图时回退中文说明，未知标记保留原文。

名称、选项和按钮继续使用可读纯文本，避免装饰符占用紧凑卡片标题；如 `<SHARD_RED_SIMPLE>深红执刑官源力石` 显示完整中文名称。RETRO_TM 显示 ™；有明确图片映射的 `<DT_*_COLOR>` 渲染图标，`<br>` 换行。`<JUMP>`、`<USE>` 等没有明确图标映射的绑定语义显示“跳跃”“互动”，不能替用户猜键盘和手柄绑定。

## 新人如何维护

首次补齐或上游映射更新后，在项目根运行：

```sh
node 工具/11-获取文本图标.mjs
```

底层先运行 `python3 scripts/fetch-text-icons.py`，再运行 `node scripts/prepare-inline-tokens.mjs`。获取脚本并发 6、单次请求 15 秒、最多 2 次尝试，只处理有明确映射的 PNG。已有哈希正确的文件直接复用，不在启动时联网。失败会写入 text-icon-assets.json.failures，不能把它当全部完成。

只改中文说明时：

```sh
npm run prepare:text-icons
npm run check
```

观察 JSON 中出现了什么标记，继续用 `node 工具/10-文本标记清单.mjs`；10 是只读统计，不会覆盖人工规则，也不负责下载。下载后的图片与映射清单需要随源码一起保留，跨电脑开发和发布包才能离线显示。
