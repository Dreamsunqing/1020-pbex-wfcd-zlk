# 字段、字典与多语言映射

适用 0.13.2，2026-10-23。用户要求按字典与 JSON 的真实结构对应中文，重点覆盖技能、组件和多层嵌套，并为后续多语言供数保留边界。本文区分游戏文本翻译与字段用途说明；后者仍由 `field-guide.mjs` 维护。

## 本次缺失的原因

“带电子弹”在官方 `ExportUpgrades_zh.json` 中没有顶层 description，效果实际位于 `levelStats[].stats[]`。过去匿名数组按来源文件顺序选择，英文目录排在中文前，导致等级效果采用英文；详情描述栏又只显示顶层 description。

另一个独立错误是把 `<DT_ELECTRICITY_COLOR>`、`<DT_FIRE_COLOR>` 当成控制码删除。Plus `ExportTextIcons.json` 实际给它们提供了 ElectricitySymbol、HeatSymbol 等图标。现在按明确映射显示真实图片。未收录的 `*_COLOR` 保留原标记，不根据后缀推断并删除。原始 JSON 不改动，文本中间件只处理展示。

## 先区分四种文本结构

| 来源结构 | 查找依据与字段 | 本次处理与证据 |
| --- | --- | --- |
| 官方 `official-public-export/manifests/{语言}/Export*.json` | Export 分组中的 `uniqueName`；技能用 `abilityUniqueName`；字段 name、abilityName、description、passiveDescription、levelStats 等 | 从语言目录明确识别语言；相同完整 ID 的对应字段分别保留语言版本，来源指向真实字段 |
| Plus `git/warframe-public-export-plus/Export*.json` → `dict.{语言}.json` | 实体对象键是物品 ID；name、description 或任意深层字符串值可能是完整语言键 | 只在目标语言字典中精确命中完整键时替换；保留原字段位置及字典位置两份证据 |
| Oracle `git/wf.browse.oracle/data/*` → `dicts/{语言}.json` | 业务记录引用完整语言键；部分字段已有文本 | 通过相同的精确字典索引处理，保留来源优先级；原有周常、赏金专用解析继续负责其业务语义 |
| WFCD `wfcd-items/data/json/i18n/{语言}.json` | 完整物品 ID → 本地化对象，非扁平字符串字典 | 将已知 ID 的本地化对象作为文本候选；递归索引 abilities，再按完整技能 ID 关联。支持数组 description、levelStats、被动、trigger、systemName |

当前 WFCD 中文字典有 19,505 个物品键。字段分布：name 18,093、description 15,975、levelStats 1,793、trigger 540、systemName 269、abilities 128、passiveDescription 120。Plus 中文扁平字典 36,165 个键，Oracle 中文扁平字典 227 个键。这些是当前离线输入统计，不是固定上限。

`zh` 显式规范为 `zh-CN`，`tc` 为 `zh-TW`，其余代码保持原值。不能把物品路径、语言键、奖励表路径看作同一命名空间；也不能仅截取文件名或英文标题匹配。

## 嵌套字段如何对应

1. 对象逐字段递归，保留未知字段。字段路径中的特殊键使用 JSON 方括号形式；来源位置始终用正确转义的 JSON Pointer。
2. 有身份的数组，使用 `uniqueName`、`abilityUniqueName`、`ItemType`、`itemId` 对应，不按下标跨源拼接；技能／组件子实体与独立文件的同 ID 实体合并。
3. 无身份数组保持整组候选。例如 `levelStats`、攻击模式数组不会把英文第 0 项与中文第 0 项强行拼接。优先采用对应语言的完整数组；所有原候选仍可回查。
4. 已知展示字段 name、abilityName、description、passiveDescription、displayName、title、label、compatName、levelStats、trigger、systemName、locTag、descriptionKey、nameKey 支持按来源语言选择，数组内继续检查这些文本字段。
5. 任何深层字符串若完整命中语言字典键，都可形成带证据的翻译候选。对象键和身份路径保持不变；不对任意英文字符串机器猜译。
6. 语言版本差异不作为数值冲突；数值或中性数据的跨来源差异仍记录为冲突，不能因为文件语言不同而忽略。

## Mod 等级效果与技能实例

带电子弹完整 ID：`/Lotus/Upgrades/Mods/Archwing/Rifle/ArchwingEventElectricStatusRifleMod`。

- 官方中文 `ExportUpgrades_zh.json#/ExportUpgrades/949`。
- `levelStats/0/stats` 为 +15% 电击伤害、+15% 触发几率，直到 `levelStats/3/stats` 的 +60%。四档全部保留。
- 对应语言没有直接 description 时，取最后一个具有有效 stats 的等级，按换行拼接，形成 description；转换明确记录 `max-rank-stats`、实际等级及 `/levelStats/3/stats` 来源。
- 直接可用的对应语言 description 优先；不会以派生等级文本覆盖已有描述。WFCD 字符串数组 description 采用 `text-lines` 转换，保留原数组证据。
- 派生的满级摘要不能当作所有等级的完整效果，全部等级仍在 attributes.levelStats。

“电击”技能 ID：`/Lotus/Powersuits/Volt/Abilities/ShockAbility`。中文名称与描述来自官方 ExportAbilities 分组，英文描述单独保留。战甲内嵌技能、独立技能目录、组件关联都以完整 ID 找显示名称和图片，不依赖当前语言名称反查。

## 输出及读取边界

| 输出 | 用途 |
| --- | --- |
| `items/*.json` | name、description、passiveDescription 为语言映射；其他字段保留首选语言的兼容视图与完整结构 |
| `localizations/{locale}.json` | 按实体 ID、建模字段路径存储该语言的深层值，以及 source、transform、dictionarySources |
| `reports/localization.json` | 每种语言的名称、描述、被动、嵌套字段、字典字段、派生等级数量与缺失数量 |
| `reports/provenance.json` | 字段候选、选择、转换、人工修订；未把英文误标为中文 |
| `reference/*`、manifest.inputs | 原始输入及哈希；证据中的 input 索引通过 expandEvidence 还原文件、哈希和指针 |

服务 `mergedDetail(data,id,{locale})` 返回对应语言的 item 深层字段和 fields；`mergedList`、关联名称、强化卡徽章也接收语言。工作台“统一资料”支持内容语言切换，界面按钮的语言仍为中文。赏金任务文案目前沿用既有中文业务模块，不宣称整个程序已完成国际化。

深层字段依次查询请求语言、英文、其他已构建语言；后两种情况明确附 `requestedLocale`、实际 `locale`、`fallback`，界面显示回退提示。名称／顶层描述按各语言独立保存，缺失不会写入伪译文。无任何可用文本时保留原值或缺失状态。

人工修订不能被语言投影覆盖；修订仍需有效来源哈希与原因。原始候选文本和 `<xxx>` 标记始终可回查。部分数组同时含原语言段落与语言键时，不会只替换一个键就把整组标为另一语言；语言未知的来源若仍含原文，投影附 partial，界面显示“部分文字保留原文”。

## 扩展语言的方法

默认 `contract.locales` 为 `zh-CN`、`en`。后续在合并规则 JSON 中增加已准备好的语言，例如 `fr`，然后重新构建：

- Plus／Oracle／WFCD 按显式代码载入该语言字典。
- 官方已有英文分类模板自动派生到对应语言目录；仍需实际文件存在，缺失输入记录在问题中。
- 输出增加 `localizations/fr.json`，名称／描述增加 fr，工作台内容语言选项来自构建清单。
- 测试用中文、英文、法文三套不同文本证明语言选择不会相互覆盖；不表示当前离线构建已经发布全部语言。

不要只在前端追加一个“法文”按钮；要有输入、分类、字典、字段投影和缺失报告，并重新验证。

## 图库文本

图库不依赖先构建 P3。`gallery.mjs` 按完整 ID 递归读取 WFCD 中文字典及官方中文清单，优先取官方中文描述，支持技能和 Mod 等级效果，并返回 descriptionLocale、descriptionSource、descriptionTransform。保留 WFCD 英文描述作为明确标记的兜底。图层、图片目录和蓝图精确关系不受翻译影响。
