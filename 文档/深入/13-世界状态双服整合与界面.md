# 世界状态：双服整合、资料关联与界面

> 2026-10-24 界面已更新：默认快速入口、沉沦任务合并、日历仅预览奖励及商店/科研等新交互，以 [第 18 章](18-世界状态精简展示与快速入口.md) 为当前约定。本文其余字段映射和历史说明保留。

0.14.0，2026-10-23。独立入口“世界状态”整合本机“世界状态重构”的解析层，展示双服官方快照，利用本项目的语言字典、实体数据、本地图片和文本图标。旧项目保持原状，不启动或部署原 API 服务。

## 使用

顶部切换国际服 DE／国服 WG，点击“刷新世界状态”获取对应官方 JSON；可勾选每分钟刷新，仅当前页面可见时刷新。首次打开先读取缓存；没有缓存时使用随包离线样本，明确标注“离线样本”和状态时间，不自动联网。刷新失败保留已有快照并显示原因，不用空白数据替换。

“导入快照”通过原生文件选择器读取当前选中服的官方原始 JSON。导入会替换该服当前缓存；程序无法仅靠 JSON 内容可靠识别所属服，请导入前选择正确服务器。导入快照始终标记为导入，不能冒充实时状态。

总览顶部为六类区域周期与数量概览。任务、周常、商店、动态标签用于分区；搜索支持中文名称、任务说明、奖励及条件。裂缝在模块内筛选普通／钢铁／九重天。短内容直接显示；项目或嵌套奖励较多时，卡片显示数量并提供“全部／完整内容”进入模块详情。详情每页 24 项，返回保持原标签、查询、筛选和滚动位置。深浅主题共用语义色，窄窗口自动减少列数。

模块按任务、周常、商店、动态固定顺序全宽排列，间隔 20px；卡片在模块内分列。日历强化和沉沦之地的专用映射、官方公告与社区补充边界见 [周常字段映射](15-日历与沉沦之地映射.md)。

页面底部折叠“解析模块／上游字段／本地字典”提供来源、原始时间、SHA-256、字典文件哈希、未覆盖字段和警告，便于维护核对。

## 数据流与代码位置

```text
DE / WG 官方 raw JSON
  → LiveStateStore：校验、双服缓存、失败回退
  → normalizers：Extended JSON 日期、稳定字段、45 个模块
  → catalog：当前目录/历史快照中的字典及静态实体
  → buildWorldView：分区、有效窗口、奖励关联、展示 DTO
  → live-state.js + live-state.css：图文卡片、筛选、详情
  → images.js / renderGameText：本地图片与文本图标
```

| 环节 | 文件 |
| --- | --- |
| 官方获取、导入、缓存 | `src/core/live-state/service.mjs` |
| 导入的纯解析模块 | `src/core/live-state/normalizers/` |
| 字典上下文适配 | `src/core/live-state/localization/static-worldstate-resolver.mjs` |
| 字典与实体关联 | `src/core/live-state/catalog.mjs` |
| 界面数据投影 | `src/core/live-state/view.mjs` |
| worker 方法 | `src/desktop/worker.mjs`：`liveState`、`importLiveState` |
| IPC 和文件选择 | `src/desktop/main.mjs`、`src/desktop/preload.cjs` |
| 页面和样式 | `src/ui/live-state.js`、`src/ui/live-state.css`、`src/ui/index.html` |
| 单元测试 / UI 回归 | `test/live-state.test.mjs`、`scripts/check-world-state-ui.mjs` |
| 导入来源和原文件校验 | `src/data/live-state/integration-source.json` |

网络请求在 worker 中执行，网页 CSP 保留 `connect-src 'none'`，图片也不增加外网请求。沿用配置中 `network.proxyUrl` 和环境代理；单次请求最长 18 秒，响应和导入文件上限 16 MiB。双服各自单飞，避免重复点击触发并发下载；导入也占用同一服的写入锁。缓存采用原子替换和哈希校验，格式错误不覆盖有效数据，联网响应时间倒退也不覆盖已有联网快照。

运行时缓存位于 Electron 用户目录的 `world-state/de.json`、`world-state/wg.json`。每份包含 `server/kind/source/fetchedAt/hash/raw`。`raw` 保留未知字段，绝不把翻译或图片回写进去。不同字典目录／历史快照采用捕获的读取上下文，不能在加载中串源；刷新会重读字典。

联网快照的上游时间与本机时间相差不足十分钟才显示“实时快照”；否则显示“缓存快照”。页面定时更新倒计时和过期标记。旧快照按捕获时间筛选有效内容，便于离线复核；倒计时仍按本机当前时间，已结束的项目不会伪装仍有效。

## 当前页面覆盖

共导入 42 个已知上游字段的映射、45 个解析模块。解析覆盖不代表每个字段都有玩家卡片。

| 分区 | 界面内容 | 关联与边界 |
| --- | --- | --- |
| 周期 | 地球、夜灵平原、魔胎之境、奥布山谷、扎里曼、双衍王境 | 依服务器时间、集团边界或固定周期锚点推算，显式“推算”；不是六个独立官方实时观测字段 |
| 任务 | 裂缝／钢铁裂缝／虚空风暴、突击、猎杀、警报、入侵、赏金任务（按地区区分）、集团任务、特殊节点 | 每服只用自己的 raw；未出现的模块不凭经验生成 |
| 周常 | 午夜电波、双衍回廊、实验室／Hex 科研、1999 日历、沉沦之地、宝库奖励 | 挑战计数代入已知变量；日历标记游戏日期，不推定现实今日奖励 |
| 商店 | 虚空商人、Prime 重生、每日特惠、限时商店、商店精选 | 未到场商人不拿历史 Manifest 当未来清单；价格字段未验证含义时保留字段名称 |
| 动态 | 新闻公告、活动行动、全服加成、舰队建造、中枢目标、精选氏族、武形秘仪挑战 | 外部公告仅通过按钮在系统浏览器打开，卡片不解释为可执行 HTML |

`PersistentEnemies`、`ProjectPct`、PVP 比赛／替代模式、HubEvents、ExperimentRecommended、TwitchPromos、SkuSales、PrimeAccessAvailability、TemporaryConfig 等保留在完整缓存和解析诊断范围，暂未提供独立完整玩家模块。其中 ProjectPct 没有可靠的建造项目配对，不强拼索引。不把此版本描述成所有字段都完成了精细界面。

世界状态赏金现已接入本地经版本校验的 Oracle 挑战和地区任务算法，使用所选服的快照种子，不借用另一服输入。推算结果显式标记 Oracle；国服模型差异仍需游戏内核对。仲裁等原有查询继续由“推算实验室”提供。

## 统一赏金入口

“地区赏金”和平原类赏金在世界状态中统一为“赏金任务”。标题按地区展示，副标题保留集团名；总览和详情都可以切换地区，返回保留筛选。夜灵平原、奥布山谷、魔胎之境标记“开放世界赏金”；扎里曼、英择谛实验室、霍瓦尼亚标记“地区赏金”。未知集团归“其他赏金”，不丢任务。

归类只使用明确的 `SyndicateMissions.Tag`，不会把所有任务挪成夜灵平原任务。每个任务仍读取自己的 `jobType/minEnemyLevel/maxEnemyLevel/rewards`，有效窗口来自所属集团记录，奖励池及概率不混加。地区入口同时接纳该服原始 Jobs 和 Oracle 推算结果，任务内区分“当前赏金／地区任务／挑战赏金”。Oracle 的 17 档挑战及 15 个地区任务点已接入；缺少唯一有效种子或上游算法校验不符时降级并保留原始 Jobs。地区任务不按列表顺序强配难度，各地区按完整表路径独立确认轮次。奖励详情使用独立对话窗口，难度、候选奖励表及池号分别切换，不在地区卡片中展开。详见 [赏金完整接入与奖励窗口](17-世界状态赏金与奖励池.md)。

地区标签维护于 `src/core/live-state/card-states.mjs`，统一入口及筛选数据在 `src/core/live-state/view.mjs`。日历／沉沦之地的内容状态和卡片排布见 [对应章节](15-日历与沉沦之地映射.md#小卡片的内容状态与排列)。

## 字典、图片与奖励如何关联

| 上游字段 | 字典／静态文件 | 得到什么 |
| --- | --- | --- |
| `Node`、`location`、`Nodes[]` | Plus `ExportRegions` 的 `name/systemName/missionType` + `dict.zh` | 节点、星球、任务类型；WG 节点有独立手工名称覆盖 |
| 任务类型、阵营、集团 Tag | `ExportMissionTypes`、`ExportFactions`、`ExportSyndicates` + 字典 | 中文类别、阵营与集团名 |
| 物品完整路径 | Plus Export 各实体、官方 zh Manifest、WFCD `i18n/zh` | 名称、描述、图标；按 `merge-full-contract.json` 的明确别名归一商店路径 |
| `SeasonInfo.ActiveChallenges[].Challenge` | `ExportNightwave.challenges` 与官方挑战实体 | 挑战名称、说明、声望、required，替换 `\|COUNT\|`；未知占位符保留 |
| 回廊 `choices[]` 的英文名称 | 当前静态实体唯一英文索引 + 对应完整 ID | 关联中文实体及图片；英文重名时不猜 ID，不用于 P3 身份合并 |
| 科研 `deviation/risks/variables` | `/Lotus/Language/Conquest/…`，现有 Oracle 补充字典 | 任务变体、风险、个人限制的名称和描述；显式处理 EMPBlackHole 等已验证别名 |
| `SyndicateMissions.Jobs[].jobType` | `ExportBounties[jobType]` + 字典 | 具体赏金任务名、任务介绍和图标 |
| `Jobs[].rewards` | `ExportRewards[完整奖励表路径]` | 各池物品、itemCount、probability，再以完整物品 ID 关联名称、图片 |
| 突击／猎杀 `Reward` 奖励表键 | 同上 | 候选奖励池，不声称是玩家已领取奖励 |

奖励池序号仅显示“池 N”，不将数组下标未经依据等同为任务阶段。概率是静态表原值，不合并重复物品的不同池概率，也不伪造累计概率。`items`、`countedItems` 和现金分别读取各自数量，不能把 `credits` 当物品路径。

字典优先使用本资料库。少量老板、突击条件和缺失节点采用从旧项目依赖提取的 WFCD 社区兜底，来源是 `warframe-worldstate-data@3.16.10`，MIT 声明在 `community-LICENSE.txt`。该补充不能冒充官方译名。WG 手工节点覆盖也有单独来源标记。社区兜底和当前字典不同步时，应修正精准映射，不能直接用英文覆盖中文。

沉沦之地使用同一周楼层排期生成普通／钢铁对照，静态奖励节点和候选池有独立依据，未提供本周确定奖励。国服奖励规则未核实，不套用国际服候选池。维护见 [沉沦之地双难度与奖励节点](16-沉沦之地双难度与奖励节点.md)。

图片沿用当前 `assets/content`，按完整 ID／已知图标路径解析，不复制第二份图库。蓝图／Tau 继续使用既有分层合成。没有本地图片就显示文字；不尝试根据名称随意套一张图。名称、描述、任务条件、奖励和嵌套说明使用 `renderGameText`，包含 `<DT_…>` 的文本沿用已有真实图标与未知保留规则。

## 验证与维护

```sh
node --test test/live-state.test.mjs
node scripts/check-world-state-ui.mjs
npm test
npm run check
```

UI 脚本使用临时用户目录，读当前资料库／图库但不修改；验证首次离线、中文计数、奖励图片、筛选与返回、双服切换、搜索、暗色、800px 窗口、原生导入及官方联网刷新。报告与截图在 `artifacts/world-state-ui/`。测试官方接口需要网络可用；服务单元测试用受控响应覆盖断网、倒退、损坏和写锁。

扩展字段时：先确认该服 raw 字段和类型 → 添加／修正 normalizer → 通过 catalog 完整键查本地资料 → 添加展示投影 → 明确短卡与详情边界 → 增加异常或语义测试 → 更新本章。不要为了提升“覆盖率”凭名字或数组下标关联数据。
