# WM 搜索、订单与历史统计

2026-10-23：本地工作台新增“WM”入口，查询公开物品和订单，无需登录。本次没有实现账户登录、挂单、修改订单或自动发送游戏消息。

2026-10-23 后续扩展（`wm` 分支）：采用 WM 官方套装关系，实现整套与部件切换；新增裂罅拍卖的只读搜索与展示。本地制造组件与 WM 商品的关系打通留待后续。

## 操作方式

1. 进入顶部“WM”，等待物品目录加载。输入中文、英文或物品名片段，点击提示进入订单页；也可用上下方向键和 Enter 选择。搜索忽略名称里的空格、下划线和连字符，⌘ / Ctrl K 聚焦搜索框。
2. 默认看在线卖家（包含游戏中），按单件价格从低到高排序。可切换买家、全部状态、游戏中、价格范围、Mod 等级及声望排序。每页 40 条。
3. 点击“复制购买私聊”或“复制出售私聊”，在游戏聊天中粘贴。内容包含 `/w 玩家名`、英文物品名、买卖方向、等级等属性、每次交易件数和报价。复制不会发送消息。
4. 切换交易平台后重新读取订单。跨平台开关只影响订单；Switch 禁用该开关。平台选择只表示查询条件，不能替代游戏内的交易资格。
5. 点击“统计数据”查看 48 小时或 90 天记录，可按上游返回的等级切换，勾选 K 线、中间价、简单移动平均线、唐奇安通道、平均价格。下方为统计数量；鼠标移动或聚焦图表后用方向键查看时间点数值。
6. “刷新订单”“刷新统计”“刷新物品目录”分别重新请求对应数据。“打开 WM”进入当前物品的原站页面。

价格筛选使用每次交易总价；排序可使用总价除以 `perTrade` 的单件价。批量订单复制一笔交易的件数和总价，不把卖家的全部库存写进购买请求。

## 接口与数据边界

| 用途 | 来源 | 当前状态 |
| --- | --- | --- |
| 搜索目录 | `GET https://api.warframe.market/v2/items` | 真实请求成功，物品名称使用 `i18n.zh-hans`，缺失时回退英文 |
| 物品订单 | `GET https://api.warframe.market/v2/orders/item/{slug}` | 真实请求成功，使用 `Platform`、`Crossplay` 请求头 |
| 历史统计 | `GET https://api.warframe.market/v1/items/{slug}/statistics` | 兼容旧接口；早先出现 HTTP 502／超时，2026-10-23 后续已验证真实曲线 |

官方 v2 文档快照中没有历史统计接口，因此统计部分是旧版响应兼容适配，不能视为已获得稳定的 v2 支持。原文和译文见 [官方文档资料包](../参考资料/WarframeMarket/README.md)。

统计只读取 `payload.statistics_closed` 的 `48hours` 和 `90days`，不使用实时挂单冒充历史成交。已关闭订单数量也不等于全游戏真实成交量。曲线直接采用 `median`、`moving_avg`、`donch_top`、`donch_bot`、`avg_price` 和 OHLC 字段，不另行猜测 WM 指标算法；缺失的序列禁用对应图层，缺失点保持空缺。等级仅使用响应中的 `mod_rank` 或 `rank`。

历史接口失败时：有成功缓存就显示缓存时间及错误；没有缓存就显示不可用，不绘制演示曲线。用户可稍后点击刷新，或打开原站。测试用的模拟曲线仅存在于临时测试目录，不随产品提供。

## 本地缓存和请求

缓存存放于 Electron 用户数据目录的 `wm/` 下，与资料原件及合并产物分开：

- 物品目录默认缓存 6 小时；订单 30 秒；历史统计 5 分钟。过期后，下次读取时请求更新。
- 订单按平台、跨平台和物品分开；统计按平台和物品分开。
- 同一缓存键的并发请求合并；所有 WM 网络请求统一排队，两次请求开始至少间隔 400 毫秒。
- 单次超时 20 秒，响应大小上限 16 MiB；失败保留上次成功缓存及原更新时间。当前没有后台定时刷新。
- 沿用项目网络代理配置和环境代理；请求使用明确的 User-Agent。所有外部请求由后台执行，渲染页面不直接访问 WM。

## 整套与部件切换

- 选择搜索提示后，请求 `GET /v2/item/{slug}/set`；从整套或任一部件进入，都可得到 `data.id`（当前请求物品 ID）及 `data.items`（同组物品）。普通物品可能只返回自身，此时不显示成员切换按钮。
- 以 WM 独立 ID 识别成员，使用 `setRoot` 标识整套，`quantityInSet` 显示成员数量。不通过物品名称、slug 前缀或本地制造配方推测成员关系。
- 点击成员后，搜索框、物品标题、选中高亮、订单、历史统计和复制私聊均切换为新物品。保留订单／统计页签、平台、买卖方向、在线状态、价格与排序；物品等级条件重新生成。
- 关系成功缓存 24 小时；页面内切换同组成员可直接复用已取得的关系。可单独刷新套装关系；失败保留同一请求的成功缓存，无缓存时显示错误并继续允许普通订单查询。
- 切换物品时使旧订单、统计和关系请求失效，避免迟到响应覆盖当前物品；图片容器随物品重建，避免旧图片异步填入新标题。

## 裂罅拍卖（只读）

“WM → 裂罅拍卖”打开时读取武器、词条目录并查询一次最新公开挂单窗口。武器可按中文、英文或 slug 搜索，通过提示或上下方向键和 Enter 选中；“任何武器”清除选中条件。编辑武器名称后必须重新选择提示，避免把未确认的输入当成全武器搜索。

选定武器或至少一个正面词条后使用搜索接口；未指定时读取最新挂单窗口，其余条件和标价排序仅作用于这批记录，页面明确显示此边界。窗口内标价优先使用一口价，否则使用起拍价。

支持以下筛选：

| 界面条件 | 上游查询参数 |
| --- | --- |
| 武器 | `weapon_url_name` |
| 最多 3 个正面词条 | `positive_stats`，以逗号分隔 |
| 任意／无负面／有负面／指定负面词条 | `negative_stats`，省略／`none`／`has`／词条 slug |
| 极性 | `polarity` |
| 精通段位范围（7–16） | `mastery_rank_min`、`mastery_rank_max` |
| 循环次数范围 | `re_rolls_min`、`re_rolls_max` |
| 全部／满级 | 省略 `mod_rank`／`mod_rank=maxed` |
| 全部／直接出售／拍卖 | 省略 `buyout_policy`／`direct`／`auction` |
| 价格升序／降序 | `sort_by=price_asc`／`price_desc` |
| 平台 | `Platform` 请求头，PC／PlayStation／Xbox／Switch |

修改查询条件后点击“刷新并查询”。切换平台自动查询；在线／游戏中／全部状态与每页 20 条分页在本次返回结果内筛选，不代表全站结果总数。达到本次返回窗口时提示缩小范围，不推测未返回的下一批数据。

词条依照目录中的 `exclusiveTo` 限定武器类型；`positiveOnly` 词条不提供负面筛选。重复正面词条、同一词条同时选作正负条件、倒置范围及未知参数在后台拒绝。特殊 slug（如 `dark_split_sword_(dual_swords)`、`fire_rate_/_attack_speed`）使用 URLSearchParams 编码，不拼成文件路径。

结果展示武器与裂罅名称、原始词条值、正负方向、段位、Mod 等级、循环次数、极性、卖家、状态、声望及更新时间。根据目录 `unit` 显示百分比、倍率和秒；缺少单位时仅展示源数值，不推测。正负词条颜色沿用 `positive`，不通过数值符号猜测收益方向。

直接出售显示一口价；拍卖分别显示起拍价、当前出价和可选一口价，缺失值显示“未报价”，不把起拍价当成成交价。隐藏、私人或已关闭的记录不展示。“在 WM 查看”打开该挂单原站页；本项目不提供出价、购买、发布、编辑、联系消息等写操作。

### 接口、缓存和边界

| 用途 | 接口 | 缓存 |
| --- | --- | --- |
| 裂罅武器目录 | `GET /v2/riven/weapons` | 24 小时 |
| 裂罅词条目录 | `GET /v2/riven/attributes` | 24 小时 |
| 公开拍卖搜索 | `GET /v1/auctions/search?type=riven&…` | 60 秒，按平台和完整查询参数隔离 |
| 最新公开挂单窗口 | `GET /v1/auctions?type=riven` | 60 秒，按平台隔离；同一窗口内本地筛选 |

所有请求共享原有后台队列、400 毫秒最小间隔、代理、超时与响应大小限制。相同查询并发合并；搜索缓存键使用查询字符串 SHA-256；最新窗口共用同平台缓存，然后按本次条件筛选。刷新失败仅回退相同平台与相同筛选的上次成功数据，并显示原更新时间和错误。

官方 v2 快照暂无拍卖列表契约；此处是经过真实网络验证的旧接口兼容，并非获得稳定的 v2 拍卖支持。武器、词条来自有文档的 v2 目录。官方文档仍声明 v1 已弃用且不受支持，后续接口变动需要适配；网络失败时页面明确报错，不填充演示挂单。
