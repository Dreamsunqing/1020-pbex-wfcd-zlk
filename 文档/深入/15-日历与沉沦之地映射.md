## 布局

原来 12 栏网格将每两个模块放在同一行，后一行由较高模块决定位置；突击与猎杀高度不同，警报下面又混入全宽模块，于是出现空洞。

现在模块统一全宽，纵向固定 20px 间距。按任务 → 周常 → 商店 → 动态固定顺序，卡片在模块内按窗口宽度自适应分列；突击／猎杀的三步任务在宽窗口横向排列。模块保持自然高度；日历／沉沦之地的小卡片按下述内容状态统一同组尺寸，不裁切正文。筛选仅改变可见模块，不改变相对顺序；移动到窄窗口时减少卡片列数。

## 小卡片的内容状态与排列

2026-10-23 后续调整：日历大小由事件结构决定，不用是否有图片、是否翻译成功或文字长短来猜状态。**沉沦之地后续按用户要求改为普通／钢铁两列，按原楼层配对排列，替代此前任务／首领／原型战甲分组。** 奖励与界面详见 [双难度与奖励节点](16-沉沦之地双难度与奖励节点.md)。

| 模块 | 状态 | 字段依据 |
| --- | --- | --- |
| 1999 日历 | 挑战日 | 同一天事件均为 `CET_CHALLENGE` |
| 1999 日历 | 奖励日 | 同一天事件均为 `CET_REWARD` |
| 1999 日历 | 强化日 · 三选一 | 同一天事件均为 `CET_UPGRADE`；仍展示全部选项 |
| 1999 日历 | 综合／其他事件日 | 同一天混合类型或上游新增类型，保留内容 |

日历同状态单独一组、等宽等高；不同组可以有不同高度。高度适应该组最长内容，不使用固定高度截断说明。组内保持游戏日／楼层顺序，标题保留原始日期／楼层编号；这是内容类别分组，不是声称玩家已经完成、已领取或已经解锁。

列数随容器宽度和卡片数量共同计算，优先铺满整行。例如六张卡片用三列两行，避免四列排两行的尾部大空位。数量无法均分时在保证最小可读宽度下减少尾行空位；不插入空白占位卡片。卡片间距 12px、分组间距 18px。窗口变化用 `ResizeObserver` 重排。总览每个状态最多预览三项，组标题显示该状态总数，完整列表进入模块详情；详情仍按每页 24 项保留全部条目。

实现入口：`src/core/live-state/card-states.mjs` 负责状态；`view.mjs` 添加 `cardState/groupCards` 展示信息；`src/ui/live-state.js/.css` 负责分组和自适应等高排列。原始 JSON 不写回。

## Plus 中实际有什么

核对本地 `世界状态上游/git/warframe-public-export-plus/`，并查询上游 `senpai` 文件列表：没有专门的 ExportCalendar 或 ExportDescents 文件。Plus 的 `dict.zh.json` 是生成器按引用选择的词条子集，不能理解为游戏全部语言文件。

| 字段 | 实际关联 | 可得到的内容 |
| --- | --- | --- |
| 日历 `Days[].events[].challenge` | `ExportChallenges[完整路径]` 的 `name/description/requiredCount` → `dict.zh` | 官方中文挑战名称、描述、目标计数和图标 |
| 日历 `reward` | 商店别名归一 → Export 实体／官方中文 Manifest | 奖励中文、原图、蓝图关系，复用已有图片索引 |
| 日历 `upgrade` | 当前 Plus `ExportUpgrades` 未导出 `/Lotus/Upgrades/Calendar/` | 本次补充 27 项 WFCD 社区资料，并整理中文；不宣称为官方译文 |
| 日历 `Season` | `CST_*` 项目枚举表 | 春夏秋冬中文标签；不推定现实今日奖励 |
| 沉沦之地 `Type` | 独立 `DT_*` 项目标签表，共 20 项 | 玩家可读的任务类型；不转换成 `MT_*`，不借用伤害图标的同名前缀 |
| 沉沦之地 `Challenge` | 按 `Type:Challenge` 优先，再按明确维护的 Challenge 表 | 头目、祝福、基础目标和苦行加护；共 41 条有作用域或独立键的规则 |
| `Auras[]`、`Specs[]` | 每个完整路径逐一查当前实体／字典 | 命中时显示全部名称和说明；未命中保留原字段，不只取第一个光环 |

日历强化资料来自旧项目已安装的 `warframe-worldstate-data@3.16.10/dist/data/zh/languages.json`。其中这 27 项仍为英文，中文名称和说明是本项目整理，数值沿用该社区版本。来源文件 SHA-256 在规则 JSON 中；项目已保留其 MIT 许可 `src/data/live-state/community-LICENSE.txt`。

沉沦之地中文苦行加护参考 [DE 官方《旧日和平》更新说明](https://www.warframe.com/zh-hans/patch-notes/pc/41-0-0)，使用简述。**公告不提供内部 token 对应表，token 到公告条目的配对属于项目维护规则**，不能标为 Plus 直接关联。比如 `FreezeInShoot` 对应冰封之光，`JumpSmash` 对应跺头者，`SecuritySpin` 对应激光炼狱；映射的来源 ID 明确记录这一层区别。

当前随包样本在 2026-10-19 至 10-26 的 21 层都能显示已整理的挑战标题；不代表未来全部挑战已有译文。未知 token 显示“附加条件待补充”，在详情折叠区域保留原键。没有依据的伤害系数和本周实际选中奖励不生成。现已通过官方掉落表与公告补充静态奖励节点及候选范围，详见双难度章节。`Specs` 和多数 `Auras` 的语义依然缺少静态导出，完整保留用于以后补充。

## 代码和维护方式

- `src/data/live-state/weekly-semantics.json`：独立补充规则、来源、完整强化路径、季节和沉沦之地标签。与原始来源分开保存。
- `src/core/live-state/weekly.mjs`：按字段／类型解析。现有完整实体优先于补充规则；不按文件名尾部、英文名字或 `NC_` 前缀猜关联。
- `src/core/live-state/catalog.mjs`：加载规则并记录哈希证据；沿用当前目录／快照的字典。
- `src/core/live-state/view.mjs`：事件类型分流；保留游戏日、年份迭代、强化解锁要求、场景、全部光环和敌人配置。
- `src/ui/live-state.js/.css`：强化、苦行加护直接显示名称和简述；长列表进入详情；“映射来源与上游字段”默认折叠。来源提示也可在条目名称上悬停查看。

添加规则时先核对完整路径或 `(Type, Challenge)`。同一个 token 可能在基础目标、头目和原型战甲里表示不同内容；不能全局替换 Wisp、Harrow 或 `Basic*`。新语言应建立独立语言投影和来源，不把这些项目中文当作原始名称写回 JSON。后续 Plus 若增加对应实体，优先采用实体中文，补充规则只作为缺失回退。

## 验证

`test/live-state.test.mjs` 验证挑战计数、强化来源、官方实体优先、完整光环数组、同名歧义、未知键和原始数据不变。`scripts/check-world-state-ui.mjs` 验证相邻模块均为 20px、宽度相同、固定顺序、日历强化描述、沉沦之地 21 层和折叠来源，同时验证同组卡片等宽等高及紧凑间距，并保留双服／暗色／窄窗口／联网刷新回归。网络不可用时可显式用 `WORKBENCH_UI_OFFLINE=1 node scripts/check-world-state-ui.mjs` 验证离线界面；该模式在报告中明确跳过联网刷新，不能作为联网成功证明。
