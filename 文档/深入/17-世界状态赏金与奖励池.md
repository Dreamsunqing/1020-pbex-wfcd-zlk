# 世界状态赏金与奖励池

2026-10-23，工作区 0.14.1 后续修订。原始 JSON、图库和推算实验室入口保持原样；本文描述“世界状态 → 赏金任务”。

## 覆盖与数据流

统一六个地区：夜灵平原、奥布山谷、魔胎之境、扎里曼、英择谛实验室、霍瓦尼亚。地区内分开三类任务：

| 类别 | 输入与算法 | 奖励关联 |
| --- | --- | --- |
| 当前赏金 | 当前服、有效窗口内 `SyndicateMissions.Jobs[]` | 每项自己的 `rewards` 完整路径；等级和 `xpAmounts` 保留 |
| 地区任务 | Oracle `location-bounties.pluto` 及 Eidolon／Venus／Microplanet 三份 JobManifest | 对普通任务族提供共享难度清单；不能把第 N 个随机任务配成第 N 档 |
| 挑战赏金 | Oracle `bounty-cycle.pluto` 及 Zariman／EntratiLabs／WF1999 三份 JobManifest | `ChallengeMissionDifficultyTiers[i].rewards`；共 5 + 5 + 7 档 |

实际 DE 离线样本验证：23 项当前赏金；15 个地区任务点选出 45 项任务；17 档挑战。任务数随上游清单、种子、有效窗口而变，不能写死成 UI 限制。地区点未提供可靠中文地名映射，暂按清单顺序展示“地区 1”等，原 `LocationTag` 保留在来源中，不猜地名。

读取流程：`loadWorldCatalog` 用所选本地目录或快照的 `read` 加载输入，通过 `loadOracleData` 校验两份 Oracle 算法源码 SHA-256；源文件变化未经审核时停止对应推算。两个模块共享一次任务内读取缓存，来源文件及哈希纳入世界状态诊断。

`buildWorldBounties` 从当前服原始 `SyndicateMissions` 提取精确种子与时间窗，复用既有 `bountyCycle`／`locationBounties` 和 `describeOracle`。不发起 Oracle 网络请求，不使用推算实验室的手填 seed，不借用另一服务器缓存。推算失败独立降级，原始 Jobs 仍展示。国服使用自身种子复算时标记模型差异待游戏内核对，不能称为国服算法已经验证。

## 难度、奖励表与奖励池

地区任务没有指定难度。只有任务属于该地区普通 `Jobs` 家族时，才提供普通难度清单。无尽、额外、隔离库不会借用普通难度；当前世界状态实际下发的这些特殊任务仍在“当前赏金”中按自身奖励路径展示。

每个地区分别用自己有效窗口 Jobs 中的完整奖励路径，与该难度 `rewardManifests` 精确相交：

- 唯一匹配：当前已确认的奖励表。
- 清单只有一表：固定表。
- 未匹配、多个匹配、窗口缺失或重叠：分别展示候选 A／B／C，不能拿平原轮次套到山谷或魔胎之境。

层次始终为 `任务 → 难度（如有） → 奖励表 → pools[index] → items`。保留原始池序号、概率与来源 Pointer；不把池序号当阶段，不相加跨池概率，不归一化舍入误差，不把候选池当实际已获得奖励。固定基础报酬和随机奖励分开。`xpAmounts` 数组按源值展示，不擅自求和或添加额外目标、钢铁奖励倍率。

挑战清单另有 `HardModeRewards`，在单独表入口展示，不与任务表混合。当前本地 `ExportRewards` 缺少以下三张精确路径：

```text
/Lotus/Types/Game/MissionDecks/ZarimanMissionRewards/HardModeTableRewards
/Lotus/Types/Game/MissionDecks/EntratiLabJobMissionReward/HardModeTableRewards
/Lotus/Types/Game/MissionDecks/1999MissionRewards/HardModeTableRewards
```

这些入口标为“待补充”，内部说明奖励表缺失。不用同名叶子、普通池或 `/Supplementals/` 路径冒充。未来拿到同一完整路径的可靠表后自然填充。

## 中文、数量和图片

`worldBountyRewards` 复用 `rewardResolver` 读取 `type/itemCount/probability`，再以完整物品 ID 关联世界状态目录：

1. 明确 StoreItems 别名转为实体 ID；不改写奖励表路径。
2. 实体字段语言键查 Plus／Oracle 中文字典，同时利用官方 zh Manifest、WFCD zh 精确实体；较新来源只有英文时，保留同 ID 旧候选字段中已有中文名称和描述。
3. 无名称蓝图按 `resultType` 精确关联成品名，再加“蓝图”。
4. 现金包按 `credits × itemCount`，内融核心包按 `fusionPoints × itemCount`；保留原包数和换算来源。
5. 缺名称遗物可用实体明确的 `era/category/quality` 生成中文显示名；标注工作台标签来源，不从路径尾部猜品质。
6. 缺中文时保留原名并标“译名待补充”，不编译名。当前实际 DE 样本所有可用赏金奖励名已通过中文关联检查，此结论不代表所有未来物品已覆盖。

图片复用 `decorateImages` 和现有本地图像服务：同一实体 ID、官方 icon、WFCD imageName；蓝图与 Tau 继续使用已有图层规则。名称、描述和嵌套说明经 `renderGameText` 处理文本图标。未重新扫描或下载大图库。

## 界面与状态

背景只显示等宽等高地区摘要卡、任务类别计数及少量任务名。进入独立原生 `<dialog>` 后查看该地区任务，分类切换保留在窗口中。任务卡统一排列，描述省略部分在奖励详情完整展示。

点击“查看奖励”替换同一个窗口内容，有“返回任务列表”和关闭入口；返回恢复类别与窗口滚动。难度、奖励表、池号为三层独立按钮；切难度重置表和池，切表重置池。一次只渲染当前池的物品卡。窗口内滚动、来源展开不影响背景卡片高度；关闭／Esc 后保持背景位置、分页和筛选。刷新、切服等重绘会关闭旧奖励窗口，避免旧数据继续可见。

深浅色共用语义颜色；800px 窄窗口无水平溢出。图片响应只追加到仍连接的当前节点，快速切池不会把旧图片附到新卡。
