## 舰队进度

`ProjectPct` 的前两个值已经是百分数，直接限制到 0–100，保留两位小数显示：

| 原字段 | 舰队 | UI |
| --- | --- | --- |
| `ProjectPct[0]` | G / Grineer，巨人战舰（Fomorian） | 橙色进度条 |
| `ProjectPct[1]` | C / Corpus，利刃豺狼战舰（Razorback） | 蓝色进度条 |
| `ProjectPct[2]` | 语义尚不明确 | 原始数据保留，不展示为已知舰队 |

0 是有效进度，不能通过 `filter(Boolean)` 丢弃；索引必须保留。缺失、非有限数值显示“数据未提供”，不伪装成 0%。不用乘 100，也不根据比例推测到达日期。

参考本机 App：`/Users/dream/Desktop/hole/交接/页面/status/de/constructionProgress.vue`，及 API 中 `constructionProgress.mjs`。WFCD 本地依赖 `warframe-worldstate-parser/dist/lib/models/ConstructionProgress.mjs` 同样明确按索引 0 / 1 读取。

`ConstructionProjects` 是另一套事件记录：例如国服样本 `RelayReconstructionFire` 为中继站重建，不能与舰队数组按下标配对。本项目将其独立放入“中继站重建”，保留任务与说明。

## 全服加成数据

读取 `GlobalUpgrades[]`，原始类型经 `normalizers/gameplay-fields.mjs::normalizeGlobalUpgrades` 解析，`presentation.mjs::worldBoosters` 产生 UI 条目。

| 字段 | 用途 |
| --- | --- |
| `Activation / ExpiryDate` | 起止时间；未来标记“即将开始”，过期不作为当前加成 |
| `UpgradeType` | 区分资源、经验、任务现金奖励、现金拾取 |
| `OperationType / Value` | 仅 `MULTIPLY` 和有效正值解释成倍数 |
| `Nodes` | 有非空节点列表时标记“节点限定”，经当前服节点字典翻译 |
| `LocalizeTag / LocalizeDescTag` | 未知类型的名称和说明可经现有字典投影 |

已核对的类型：

| `UpgradeType` | UI 类别 | 作用范围描述 |
| --- | --- | --- |
| `GAMEPLAY_MONEY_REWARD_AMOUNT` | 现金 | 任务现金奖励 |
| `GAMEPLAY_MONEY_PICKUP_AMOUNT` | 现金 | 现金拾取 |
| `GAMEPLAY_PICKUP_AMOUNT` | 资源 | 资源获取数量，区别于资源掉落几率 |
| `GAMEPLAY_KILL_XP_AMOUNT` | 经验 | 任务击杀经验 |

相同大类的不同原始记录保留各自作用范围和有效期，不擅自连乘。未知类型保留原类型和运算，不猜测为双倍。节点限制字段损坏时显示“范围待确认”，不能视为全星系；缺少或空 `Nodes` 按无节点限制处理。

现金、资源、经验三个常见全星系加成没有活动时显示“当前未开启全星系加成”；整个字段缺失显示“当前快照未提供加成数据”。限制在个别节点的同类加成独立展示，不取代全星系未开启状态。国际服样本没有活动记录；国服样本带 `Nodes: ["SolNode129"]` 的现金奖励加成，因此须显示限定节点。

## 与个人加成叠加

双倍活动 × 同类个人双倍加成 = 4 倍。个人加成来自游戏内购买或奖励，此页面不查询玩家账号，不默认玩家已拥有。仅给出明确的条件说明：“搭配同类个人加成 2× → 4×”。未来活动注明“生效后”。

这里的 4 倍仅计算全服活动与同类个人加成这两项，不宣称是叠加其他机制后的绝对上限，不把资源数量加成与掉落几率混算。

官方依据：[Luck of the Lotus](https://www.warframe.com/en/news/luck-lotus-0) 明确说明活动与个人资源加成可叠加；[Double Affinity Weekend](https://www.warframe.com/en/news/-541) 说明活动经验双倍。类型映射还参考本地 `warframe-worldstate-data/dist/data/upgradeTypes.json`，不依赖其中不严谨的中文名称来推测语义。
