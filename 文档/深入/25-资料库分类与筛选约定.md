# 资料库分类与筛选约定

适用 0.16.4。该层仅整理玩家阅读入口：不改上游 JSON、不重写 P3 实体类别、不修改物品 ID 或关联。已内置的预构建数据直接应用当前代码的分类规则，不需要重新合并数据。

## 文件与处理顺序

| 文件 | 作用 |
| --- | --- |
| `src/core/player-facets.mjs` | 玩家分组覆盖、类型归一、picker 排序 |
| `src/core/player-library.mjs` | 应用分组和 facets，计算计数、交叉筛选、列表和详情 |
| `src/core/player-labels.mjs` | 归一值的中文标签 |
| `src/ui/player-library.js` | 呈现 picker，同伴入口使用“同伴分类”标签 |
| `test/player-facets.test.mjs` | 真实内置数据、语言一致性、计数、未知边界及源数据不变验证 |
| `scripts/check-player-facets-ui.mjs` | 真实桌面 picker、选项顺序、筛选、详情和语言切换验证 |

数据流：验证过的 P3／内置快照 → `playerGroupOverride` 和 `playerFacetValues` → 统计可见实体 → 基于同一归一值计算选项与筛选 → `comparePlayerFacets` 排序 → 中文标签。列表标签、筛选条件、详情分组共享同一规则。详情雷达比较仍要求相同源实体类别和同一玩家分类／类型。

原始字段保存在 `attributes.category/type` 中；只有玩家接口的 `facets.category/type` 使用显示层归一值。不能拿玩家 facet 值反向覆盖源字段。新增规则要在此模块维护，不在前端散落按中文标题猜类型的逻辑。

## 同伴资源

满足 `kind === weapon && attributes.category === Pets` 的项目从“武器”移动到“宠物与同伴”。玩家 `facets.category` 为 `Companion Resources`，标签“同伴资源”；源 `kind=weapon` 和细分 `attributes.type` 保持不变。卡片也标明同伴资源，细分保留宠物、宠物部件、宠物资源。

当前快照迁移 49 项：武器入口由 1,001 项变为 952 项，宠物与同伴由 38 项变为 87 项。同伴资源筛选只包含这 49 项。真正的 `type=Companion Weapon` 是独立类型，未被“武器下宠物分类”这一规则移走，仍可在武器中筛选。

## Mod 归类

按完整集合路径与已确认的名称判定，不按当前界面语言判定。因此切换英文不会改变分类或数量。

| 源字段／集合 | 玩家类型值 | 中文标签 | 当前数量 |
| --- | --- | --- | ---: |
| 各类 `* Riven Mod`，及 `/Lotus/Upgrades/Mods/Randomized/Raw...` | `Riven Mod` | 裂罅 Mod | 15 |
| 未分类、`Antiques/` 集合中的两字中文名称 | `Operator Mod` | 指挥官 Mod | 20 |
| 未分类、`Necromech/`／`Necramech/`，或中文名以“殁世机甲”开头 | `Necramech Mod` | 殁世机甲 Mod | 28 |
| 未分类、`Hoverboard/` 集合 | `K-Drive Mod` | K 式悬浮板 Mod | 23 |
| 未分类、`Rifle/` 集合 | `PRIMARY` | 主武器 | 3 张重新归类 |
| 原 `Railjack Mod` | `Railjack Mod` | 未融合的神器 | 10 |
| 其他未分类 | `---` | 未分类 | 5 |

原 80 项未分类中，除了三类 Mod，还有 3 张狙击枪弹药转换、1 张同伴武器裂罅 Mod，必须先归回主武器和裂罅，不能全归 K 式悬浮板。`瞬满` 虽然中文只有两个字，属于 `Hoverboard/`，不能误判为指挥官。`SampleAntiqueUpgrade` 是明确保留的样例，不划入指挥官。

当前“未分类”只剩 4 个以“转换核心”结尾的定义和 `Sampleantiqueupgrade`。将来遇到没有已验证集合或身份的新项，仍留未分类，禁止用“剩余全部是 K 式悬浮板”的规则猜测。`Plexus Mod` 的航道星舰 Mod 与 `Railjack Mod` 的神器定义分开；前者仍保留可用的航道星舰 Mod 类型。

## picker 顺序

装备相关的 `category/type` 按以下优先级，缺少某类型时自然跳过：

1. 战甲光环 → 战甲 → 殁世机甲 → Archwing 飞行器。
2. 主武器及步枪／霰弹枪等细分 → 副武器 → 近战 → 架势。
3. Archwing 枪械 → Archwing 近战。
4. 守护／同伴武器 → 库狛、库娃等其他宠物 → 同伴资源。
5. 指挥官／增幅器 → K 式悬浮板 → 航道星舰 → 灭骸之刃 → 裂罅 → 套装等其他类型。
6. 未列入的已知类型按中文标签稳定排序；未分类靠后；“未融合的神器”始终最后。

赋能等类型复用战甲、主、副、近战、指挥官等装备顺序。稀有度固定常见 → 罕见 → 稀有 → 传说；版本普通 → Prime → 赤毒 → 集团 → 入门 → 特殊变体。纪元继续保持古纪 → 前纪 → 中纪 → 后纪 → 先锋 → 安魂，不改遗物系统的规则。其余 picker 以原标签稳定排序。

选项计数、列表总数和筛选均基于同一归一结果，避免出现“选项显示 15 项，选中却只筛出 1 项”。语言切换只影响文案，facet 值稳定；未知选中条件仍显示 0 项，不悄悄改选其他条件。
