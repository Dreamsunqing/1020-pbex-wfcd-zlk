# 获取方式弹窗与 Prime 整套来源

适用 0.16.8。复用已内置的 P3 实体、配方、制造关系和掉落索引；不增加在线抓取，不在启动时重新合并整份数据。界面延续世界状态“沉沦之地／罗瑟奖励”弹窗的独立浏览方式，采用资料库自己的深浅色样式。

## 使用方式

物品详情只保留“查看获取方式”入口；Prime 战甲、武器显示“查看整套部件获取方式”。打开后以物品分组，展示配图、名称、需求数量、获取地点／方式和概率。

- 每个物品默认显示 **3 处来源**；超过 3 处时显示“其余 N 处获取方式”，展开、收起均在弹窗内完成。
- 折叠区首次打开才生成额外来源，每次最多增加 20 条；不在打开详情时一次渲染上千条。
- 顶部可筛选全部、掉落、遗物、奖励池，筛选后的各物品仍默认 3 条。计数是来源条数，不是当前开放任务数。
- 普通来源显示已有概率和明确轮次；遗物每个家族仅一条，列出完整、无暇、良好、光辉四档概率。0% 保留；缺失显示 — 或“概率未知”。
- 点击物品／地点／遗物进入对应资料库详情，同时关闭弹窗；可通过“上一物品”返回。Esc、关闭按钮及外侧背景可关闭弹窗，恢复入口焦点，不影响原详情结构。

静态数据可能含历史、入库或尚未开放内容。来源不全时标明未知，不能把某条概率或四档概率相加成“整套获取概率”。原始地点与文件证据可悬停查看；同名敌人保持第 27 章的译名共识规则。

## Prime 成品如何找到全部部件

`playerAcquisitionPlan(data, item, locale)` 是只读投影，索引完整物品 ID。只对 Prime 的 weapon／warframe 开启整套组件模式，Prime 标识来自已有 isPrime、variantType 或完整英文名中的 Prime。该判断只决定是否展示整套，**关系本身不按名字拼接**。

1. 当前物品自身有直接来源时保留。
2. 从 `recipes.json` 中用 `resultId === 当前完整 ID` 找到制作蓝图；蓝图使用自己的完整 ID 查询来源。
3. 收集该配方的 `materials[].itemId/count`，并以 `has-component` 关系补齐已有部件和主蓝图。
4. 武器枪管、枪机等可直接掉落的部件，使用部件 ID 查询来源。需要制造的 Prime 组件，再用该组件的 `resultId` 找到对应组件蓝图，查询**蓝图的来源和概率**。
5. 组件蓝图显示“用于制作 · 某组件”，可进入真实组件页。不会把蓝图掉率误称为组件成品掉率。
6. 成品需要另一件 Prime 武器／战甲时，沿其制造关系继续列出；完整 ID 访问集合防止循环。普通资源保留直接获取方式，不展开其可选资源蓝图；组件蓝图自己的通用配方材料仍在组件详情中查看，避免整套弹窗无限铺开原材料树。

例：阿利乌双枪 Prime 显示主蓝图、枪管 ×2、连接器 ×1、枪机 ×2，共 4 组；Ivara Prime 显示主蓝图、机体蓝图、头部神经光元蓝图、系统蓝图及奥罗金电池，共 5 组。各组分别查询已有的遗物奖励记录，因此四档概率对应的是**当前组的完整物品 ID**。

## 数量与重复处理

同一配方可能用两条 `itemId/count` 记录表示双持武器需要两把同样的武器。这种配方内的重复材料要相加；WFCD 的 `has-component` 则只是同一个要求的另一种描述，不能再加一次。配方明确列出的数量优先于补充关系；不同可选配方数量冲突时显示未知数量，不把不同路线相加。

嵌套武器按配方产出 quantity 计算所需制作批次（向上取整），再计算其蓝图及材料数量。例如野马双枪 Prime 需要两把野马 Prime，对应两张野马 Prime 蓝图、两根枪管和两副枪机。数量只描述制造需求，不乘入掉落概率；共享材料跨多个制造分支的冲突数量不猜测累计总量。

以完整 ID 去重每项获取物品。默认顺序为当前物品、主蓝图、部件／部件蓝图、通用制造材料。已知 Prime 部件缺少来源时仍显示其分组并说明“本地资料未提供获取地点或概率”，而不是悄悄漏掉该部件。

## 详情页哪些重复内容省略

原始 relations 与 acquisition 数据保留。仅展示层过滤：

- 已被获取弹窗覆盖的“获取遗物／蓝图获取遗物”卡片不再另铺一遍。
- “组件与材料／制造材料／制作蓝图”中，完整 ID 已作为获取物品、或组件蓝图的制造对象出现时，不重复展示；仍可从弹窗进入相应物品。
- 同一蓝图同时出现在“组件与材料”和“制作蓝图”，只保留一个入口。
- 未被覆盖的关系、技能、强化、制造材料和其他有用关联继续展示。

不能简单删除整组 relations，也不能按中文名称去重，否则会丢失同名的不同物品或制造组件的入口。

## 代码与维护

| 文件 | 作用 |
| --- | --- |
| `src/core/player-acquisition-plan.mjs` | 按完整 ID、配方及组件关系生成只读获取计划、数量和角色，防止循环 |
| `src/core/player-acquisition.mjs` | 底层掉落／奖励池索引、敌人名称共识及遗物家族四档概率 |
| `src/core/player-library.mjs` | 新增 `acquisitionGroups`、`componentAcquisition`，补充组内配图、名称和来源跳转信息 |
| `src/ui/player-library.js` | 弹窗、筛选、每组 3 条、其余折叠、跳转关闭及详情关系去重 |
| `src/ui/player-library.css` | 双栏分组、紧凑地点与四档概率、深浅色和窄窗口布局 |
| `test/player-acquisition-plan.test.mjs` | 真正组件蓝图、镜像去重、双份材料、缺失来源、多语言、循环和真实内置数据回归 |
| `scripts/check-player-acquisition-ui.mjs` | 真实 Electron 弹窗、折叠、来源跳转、焦点、Prime 整套、主题及窄窗口验证 |

既有 `acquisition` 和 `relations` API 字段仍可读取；新增分组中，`id` 是实际取得物品，`forIds/forItems` 是该蓝图制造的物品，`quantity` 为已知需求数或 null，`sources` 沿用原来的概率与证据结构。本次只读投影可直接使用内置快照及本地完整构建，无须更改 P3 modelingVersion 或重建原始资料。

```sh
node --test test/player-acquisition-plan.test.mjs test/player-acquisition.test.mjs test/player-library.test.mjs test/player-relics.test.mjs
node scripts/check-player-acquisition-ui.mjs
node scripts/check-player-acquisition-ui.mjs 'dist/mac/Source Workbench.app/Contents/MacOS/Source Workbench'
```
