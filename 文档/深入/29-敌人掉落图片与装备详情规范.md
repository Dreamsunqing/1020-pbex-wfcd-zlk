# 敌人掉落、图片与装备详情规范

适用 0.16.9，核对日期 2026-10-24。承接 [获取方式弹窗](28-获取方式弹窗与Prime整套来源.md)、[掉落关系](27-资料库Wiki与掉落获取.md)。原始 JSON 不变，增加玩家投影与图片索引。

## UI 开发必须遵守的尺寸规则

同排、同状态的卡片必须等宽等高。不能因为某张卡多了“其余 N 处获取方式”、译名换行或缺图，让相邻卡片底部错位。不同业务状态可以使用不同模板，不能靠每张卡内容自然撑高。

本次获取弹窗采用 Grid 两列 `align-items:stretch`，卡片内部为竖向 Flex；来源区占据剩余空间。无折叠入口的卡片保留等高页脚占位，有入口的卡片在相同位置显示。展开内容在卡内限制高度并滚动，不破坏外部页面或同排对齐。窄窗口切单列，概率四列仍在卡内，不溢出。

设计和回归至少检查：来源少于三条／恰好三条／超过三条、展开与收起、长中文名／英文名、图片缺失、深浅主题、窄窗口。验收比较同排卡片的实际边界，不只检查某个元素的固定高度。奖励和关联卡也遵守此规则；不要恢复 `align-items:start` 造成底部错位。

## 敌人掉落的两种证据

`src/core/player-enemies.mjs` 生成 `player/enemy-loot.json`，由 `player-bundle.mjs` 写入内置快照；完整 P3 浏览时读取同一构建中已验证的 reference，不混用另一次下载的实时文件。

| 输入 | 对应关系 | 展示结果 |
| --- | --- | --- |
| Plus ExportEnemies | 敌人完整 ID → `attributes.droptable` → 同构建 `droptables[tableId]` → `items[].type` 完整物品 ID | 确认该敌人的掉落物品、类别、概率及来源指针 |
| WFCD 物品 `drops` | 已校验物品身份的获取来源 → 确认敌人 ID 或同名候选 ID | 无敌人专属表时补充反向记录；同名候选标“变体适用性待核对” |

Plus 的类别 `chance` 与类别内 `probability` 都是 0…1，最终百分数为 `chance × probability × 100`，不是只显示后一项。例如类别 3%、类别内 20%，最终 0.6%。保留 0；未提供则未知，不能当 100%。WFCD 物品来源中的 `chance` 已是百分数，不再次乘 100。

有专属表时不以同名反查覆盖；明确存在空表时也不自动用别的变体掉落填满。未解析物品不制造假链接。敌人自身的 outgoing drops 不是“获得该敌人”的方式。

敌人详情新增“掉落奖励”，显示本地物品卡、中文名称、概率和类别，可进入物品资料。每批 18 条；类别概率计算放在悬停提示。同名来源保留中文及原掉率，提供“查看敌人 · N 个变体”，用户选择后才跳转；显示变体标签与内部末段代码帮助区分，不擅自选钢铁或任务版。

## 为什么有图仍然不能按名称套用

WFCD 的 `jackal.png` 与本地 `Jackal.png` 不能仅通过大小写修复：后者是徽记。Wiki 的 `AladV.png` 是敌人立绘，而 WFCD 同名图也可能是徽记。**跨来源文件名相同，不等于图片内容相同。**

新增 [维护入口](../../工具/15-获取敌人图片.mjs)：

```sh
node 工具/15-获取敌人图片.mjs --预览命令
node 工具/15-获取敌人图片.mjs
```

执行顺序是已有 P3 内置数据、现有 WFCD 图库，再运行该命令；它不在浏览或启动时自动联网。实现为 `scripts/fetch-enemy-images.mjs`：

1. 读取 [Warframe Wiki 敌人 Lua 数据](https://wiki.warframe.com/w/Module:Enemies/data)各派系模块，提取 `General.InternalName`、`Image`、`Name`、`Link`；不执行 Lua。
2. `InternalName` 精确匹配本项目敌人 ID；Agent 通过 Plus `agents[id].avatarTypes` 明确关系关联 Avatar。候选图名冲突则放弃，不按英文子串或 ID 后缀猜。
3. 通过 Wiki `api.php` 的 `imageinfo` 取得文件 URL。仅允许该 Wiki HTTPS 来源，下载有超时、体积和图片格式限制。
4. 不按 WFCD 同名文件复用。校验图片内容 SHA-256 后才复用完全相同的字节；新增图按内容哈希去重。记录模块版本、行号、模块哈希、图片 URL 和图片哈希。

图片仍保存在唯一共享目录 `assets/content/wfcd/img`，作为社区图库存储位置；实际提供方在索引中记为 `wiki`，界面悬停写“Warframe Wiki”，不冒充 WFCD 官方来源。索引为 `assets/content/wfcd/enemy-image-index.json`；诊断为 `artifacts/enemy-images/report.json`，原始模块缓存位于 `.cache/enemy-images`。大图库、索引与报告按既有规则不入 Git，新电脑运行工具恢复。普通 Mac 包不含完整图库，原机包通过现有图库路径读取。

本次快照：5,524 条敌人定义中，1,956 条具备无冲突关联，实际可用 1,948 条，共用 747 个文件，其余 3,576 条未补上。该数字包括 Agent、Avatar、任务变体等内部记录，不能理解为游戏中有这么多独立敌人。通过 API 返回的 normalized 字段处理文件标题规范化（例如下划线转空格），不把存在的文件误判为缺失。缺失清单仍有 Wiki 文件不存在等原因；不宣称全部补齐。首次试跑中按跨源同名复用的条目已重新下载并替换索引。

`local-images.mjs` 只接收上述明确依据且本地文件存在的敌人映射；敌人没有完整 ID 映射时禁止退回名称猜图。`gallery.mjs` 将这些素材归入“敌人”类别。`prepare-data.py` 更新 WFCD 时保留索引引用且哈希正确的补充图，避免整目录替换后把它们删除。官方 NPC 图不一定在 Public Export Manifest，不能凭路径猜 `!...` 哈希后缀；后续游戏缓存提取见 [远端资源指南](30-游戏资源提取与Windows远端调试.md)。

## 装备字段与概率单位

`src/core/player-equipment.mjs` 负责纯字段投影，`player-library.mjs` 负责本地化和关联，UI 按竖向“字段名／值”展示。

| 数据字段 | 用途 |
| --- | --- |
| `polarities[]` | 常规极性槽，保留重复与顺序，不能去重 |
| `exilusPolarity` / `aura` / `stancePolarity` | 特殊功能／光环／架势槽分别展示 |
| `type` / `category` / `trigger` | 武器类型、槽位、扳机；使用现有分类中文映射 |
| `accuracy` / `multishot` / `ammo*` / `noise` | 精准、多重射击、来源确有的弹药字段、噪音 |
| 近战 `blockingAngle` / `comboDuration` / `followThrough` / `range` | 格挡、连击持续、跟进、范围 |
| `slam*` / `slideAttack` / `heavy*` / `windUp` | 近战震地、滑行、重击与准备时间 |
| `attacks[].damage` | 分伤害类型显示，调用现有 `DT_*_COLOR` 文本图标；总伤害不把 `total` 再相加 |
| `attacks[].speed/crit_chance/crit_mult/status_chance` | 当前模式射速、暴击率、倍率、触发率；模式百分数本身是 0…100 |
| `shot_speed` 或 `flight` / `shot_type` / `radius` / `punch_through` | 投射速度、判定、爆炸半径、穿透；同义速度只展示一次 |
| `falloff.start/end/reduction` | 衰减距离和最远保留伤害 `(1-reduction)×100%`，距离 0 不省略 |
| 唯一 `behaviours[0].burst.count/delay` | 点射连发、间隔；模式总伤害乘 count 得单次点射伤害。多个行为时不猜对应哪个模式 |
| `introduced.name` / 原日期 | 推出版本／日期各自展示 |

极性使用项目已有拼图素材，伤害类型复用文本图标，无需复制第二套。基础信息与各攻击模式内部都是竖向排列，多种攻击模式可并列，窄窗口单列。侧栏顺序固定：物品档案、低调的属性轮廓、Wiki。

交易按成品与完整关系中的部件／蓝图区分。例如阿利乌双枪 Prime 显示“部件及蓝图可交易；成品不参与交易”，而非笼统“不可交易”。部件自身显示其真实可交易状态；敌人等无意义对象不列交易行。没有提供交易字段的对象保持未知。

截图中的弹药上限／拾取量不是所有快照都有。例如当前阿利乌双枪 Prime 原件没有这两个值，不能直接抄截图补成 24／6；实际点射间隔为 0.12 秒，不把参考图的 0 当原始字段。官方基础射速与 WFCD 模式射速若不同，保留各自层级，不用一项覆盖另一项。

## 更新与验证

字段投影或敌人掉落变化后，从**完整、已验证** P3 构建运行 `node 工具/14-预构建资料库.mjs <构建目录>`，同时提交 gzip 与 manifest。不要对精简包再做二次精简。本次没有变更 P3 原始合并合同，不要求重新下载来源。

`test/player-equipment-enemies.test.mjs` 验证概率单位、0、变体、真实快照属性；`test/local-images.test.mjs` 验证跨源同名不会误配；`scripts/check-player-acquisition-ui.mjs` 验证同排等高、展开／收起、窄屏、极性和伤害图标、交易、侧栏顺序、敌人跳转与掉落卡。源码及 Mac 解压版分别定点回归；不全量扫描大图库。
