# 官方掉落表与跨模块关联

适用 0.17.0，核对日期 2026-10-24。使用入口：[掉落表](../../src/ui/drop-tables.js)。相关规范见 [获取弹窗](28-获取方式弹窗与Prime整套来源.md)、[敌人掉落及图片](29-敌人掉落图片与装备详情规范.md)。

## 使用方式

总导航“掉落表”离线显示官方静态表；选择中文／English、类别，搜索物品、敌人或地点。默认按地点／来源显示摘要，点击弹窗查看奖励、图片、概率和明确的资料库跳转。长表按批加载，列表每批 18 组、弹窗奖励每批 36 项，不一次性生成五万多个 DOM。已确认物品身份时可进入资料库。

“刷新”只请求 `https://warframe.com/droptables`，完整校验后生成新的本地快照，再运行同一解析和展示逻辑。失败保留旧数据。新来源 `droptables` 同时加入“更新与版本”的整批更新、差异、当前／上一版和回滚。旧版保存的配置缺少该来源时，桌面端自动补入，已有来源设置保持原值。切回掉落表会重新读取当前快照，因此回滚生效。

原网页保留为 `droptables.html.txt`，规范化数据为 `parsed.json`；Store 以 SHA256 存储，不执行网页 HTML、脚本或外部图片。源码中的离线包只内置压缩规范化数据。项目资料目录另保留 `世界状态上游/official-drop-tables/` 原文和解析结果。

## 处理脚本与字段

| 步骤 | 位置／命令 |
| --- | --- |
| 下载、校验、发布本地快照 | `node 工具/16-刷新官方掉落表.mjs`；`src/core/drop-table-store.mjs` |
| 随全部来源更新 | `node 工具/01-获取数据.mjs`；`src/core/updater.mjs` |
| HTML → 分类／来源／轮次／阶段／奖励 | `src/core/drop-tables.mjs` 的 `parseDropTables` |
| 双语名称、节点归属 | `src/core/drop-localization.mjs` |
| 生成随程序内置数据 | `node scripts/prepare-drop-tables.mjs` |
| P3 全量构建和资料库预构建 | `scripts/build-merge.mjs`、`工具/14-预构建资料库.mjs` |
| IPC 与 UI | `src/desktop/worker.mjs`、`src/ui/drop-tables.js`、`drop-tables.css` |

解析支持目前 20 类表，保留赏金阶段和轮次。`conditionalChance` 是池内百分比，`sourceChance` 是触发率；两者都有时最终概率为乘积除以 100。资源触发率可能为 800%，代表多次判定，界面保留两项原值，不把它当 800% 的最终概率。0 不省略，未知不写成 0 或 100。表必须有有效奖励、任务和遗物分类及完整结束标记，才允许替换快照。解析规则变化时应增加 parserVersion 并重新预构建。

## 本轮发现及修复

1. **阿索代蓝图**：WFCD 写 `Venus/Beacon Shield Ring (Caches)`，Plus 节点系统写 `Venus Proxima`。仅对 `CrewBattleNode` 接受这种完整星球别名，不对普通星图开放宽松匹配。六处缓存来源均可译名并跳转，概率 6.45% 保留。缓存来源不能被节点默认的歼灭类型覆盖。
2. **同名不同域**：`Rush` 是冲刺 Mod，也能是突袭任务；`Deep Freeze` 同时是 Mod 和挑战。按表格列的用途区分奖励／敌人，不能拿任意同名字段当译文或 ID。
3. **名称的图标前缀**：官方陨蜓蓝图带 `<ARCHWING>`，掉落表不带。名称匹配只对这一已核实的前置图标做规范化；不删除描述中的任意尖括号，不影响中间件保真。
4. **新版 WFCD 遗物结构**：`rewards` 已为空，部分组件 `drops` 不再有遗物 ID。`player-relic-odds.mjs` 用官方完整遗物名称＋品质＋已确认的奖励 ID 与表中奖励完整英文名核验概率。取得原值后写入内置资料。四品质来源按同一家族折叠；不按稀有度猜概率。依据分别记录 `exact-relic-source-id`／`exact-relic-name-quality`。
5. **名称共识不等于身份**：多个敌人／Mod 完全同名、译文相同时，可以展示共同中文；不能替用户选任意变体跳转。缺少可靠映射的原文仍保留。英文专名、上游敌人别称和未建模的运输舰仍需后续逐项核对，未宣称全部汉化。

## WM搜索和其他变体

资料库详情、获取弹窗、世界状态和掉落表统一校验当前具体实体 `tradable===true` 与 WM 精确目录身份；冲突 gameRef 不降级名称，未知不展示入口。详细规则和成品／部件、同名 Mod 反例见 [第 33 章](33-Wiki图库增量维护与交易校验.md)。进入 WM 时再次校验，只打开本程序正确物品页。

“其余获取方式”统一改为“更多获取方式”。同排卡片仍保留相同折叠入口占位；见 [卡片尺寸规则](29-敌人掉落图片与装备详情规范.md)。

战甲、武器、Archwing、宠物／守护／同伴及 Mod 的玩家详情增加“其他变体”。`player-variants.mjs` 只匹配同 kind／类别的完整英文族名和审核过的前后缀，如 Prime、Umbra、Vandal、Kuva、Tenet、Primed；不会把同前缀的不同武器或部件混入。仅一项的家族不生成空模块。

## 九重天裂缝的身份

一个裂缝由 `_id + Node + Activation + Expiry` 定位。任务类型属于此次实例，同一节点另一个时段可以不同。`VoidStorms.MissionType` 若提供，读取此次字段；不把 `ExportRegions[Node].missionType` 当实时类型。

本轮官方样本与 browse.wf 只提供 Node、时间和纪元，没有 MissionType，所以隐藏缺失徽章。无法从一个节点反推出本次具体任务；未来接入可信的实例任务字段时已有映射与回归用例。

## 仲裁日历与收益接口

仲裁为独立单列，突出任务类型，并显示当日各小时段。月历日期下方显示已标记高质量的数量；选择日期查看当天排期。排期来自 Oracle/browse 的 `arbys.txt`、本项目节点及字典，离线有同版本压缩输入，不依赖每次重新下载。

评级独立于排期。当前未收到用户确认的高收益节点标准，因此默认显示“待评级”，统计为 `—`；未知不会被当成普通／0。部分任务有评级时展示已确认数量和 `+`，完整覆盖且全部已评级才显示确定总数。没有完整排期时单独标注。

内置评级：`src/data/live-state/arbitration-ratings.json`；用户覆盖：Electron 用户数据目录下 `arbitration-ratings.json`。结构示例（仅结构，不是推荐节点）：

```json
{"_source":"经过核实的评级来源", "SolNode123":{"quality":"high","yieldPerHour":100,"unit":"自定义收益单位"}}
```

节点键为完整稳定节点 ID；quality 为 high／normal。收益预留独立字段，尚无实测值不显示假收益。今日高质量仲裁加入世界状态任务统计，与当前查看的日历日期分开计算。国服排期规则未验证，不套用国际服日历。
