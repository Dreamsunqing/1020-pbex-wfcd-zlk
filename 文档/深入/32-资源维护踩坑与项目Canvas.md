# 资源维护踩坑与项目 Canvas

适用 0.17.0。此章记录可复现的维护入口；用户上传截图只作为外观参考，不作为物品属性或 ID 证据。

## Wiki 来源敌人图片

WFCD 或官方有名称，不代表对应立绘已经下载；即使文件名相同，也可能是纹章。优先查已有完整 ID 索引及 Plus 的 agent/avatar 关系，最后才向 Wiki 查询资源元数据。

```sh
node 工具/15-获取敌人图片.mjs
```

当前实现已改为 `scripts/sync-wiki-images.mjs`，旧编号 15 仅维护敌人，新增编号 18 维护完整 Wiki 文件目录及可靠关联原图。**0.17.1 起统一存放 `assets/content/wiki/`**，不再向 `wfcd/img` 新写 Wiki 图片。迁移先校验内容并发布新索引，再移除没有被 WFCD 引用的旧文件。图资源工具增加 Wiki 来源和 Wiki 来源敌人图片分类。

完整命令、断点／增量策略、索引字段、原图和旧缩略图的区别、保守补图依据见 [Wiki 图库增量维护与交易校验](33-Wiki图库增量维护与交易校验.md)。

## 本轮维护容易出错的地方

| 现象 | 原因与正确处理 |
| --- | --- |
| 原图看似同名，实际是纹章 | 只以 ID 证据和图片字节校验复用，不能跨来源按文件名猜图 |
| 原始中文／描述丢失 | 按字段结构选字典，文本图标中间件不删除未知标记；名称图标别名只在已审阅的匹配层处理 |
| 更新后四品质概率全空 | 新 WFCD 遗物 rewards 为空；从同次官方掉落表核验并预构建，见第 31 章 |
| 蓝图英文名称无法匹配 | 官方可能带前置 `<ARCHWING>`；完整名称匹配层处理，不批量删任意尖括号 |
| 一个节点被永久写死为一种裂缝任务 | 实例和静态节点必须分开；无实例字段不推断 |
| 名称汉化了，链接却指错对象 | 中文共识不等于身份；保留候选或原文，不自动选变体 |
| 仲裁日期显示 0 场高质量 | 未评级与低质量不同；无收益依据显示待评级和未知统计 |
| 获取卡底部不齐 | 同排同状态 Grid stretch，Flex 页脚留占位；折叠／无折叠／缺图／长标题都验实际边界 |
| 改共享渲染时总览卡住 | 专属模块变量不能复制到其他函数作用域；对快速入口、总览、详情分别做实际回归 |
| 快照名称相同误判未更新 | 核验来源提交与文件 SHA256；索引与 manifest 同步更新，不沿用旧 commitDate |

全量更新会保留上游原始字节。官方 JSON 格式从缩进改成压缩时，Git 可能显示大量删除行；不代表游戏字段全部删除。评估变化应以 JSON 结构、源哈希、实体／配方／奖励统计为准。

## 三份持续维护的画板

项目 PNG 用于快速阅读，Obsidian Canvas 为可编辑源文件，构图声明集中在 `scripts/build-project-diagrams.mjs`。使用标准 JSON Canvas 节点与连线，无专属插件依赖。

**图示原则：关系明确优先，不追求规整或美观。** 按实际的数据流、页面跳转和功能依赖摆放节点，可用不规则布局、不同节点尺寸、非对称分支；不要为了凑齐行列或统一卡片而拉远直接关联的节点。箭头必须有方向与关系文字，区分来源、处理、展示和维护；连线避开节点正文，交叉不等于关联。每次调整都检查能否顺着箭头看懂关系，不能只检查画面是否整齐。

生成器按逐节点坐标导出，项目图片使用避让节点的折线；Canvas 保留相同节点、连线方向、端口和关系标签，由 Obsidian 自身绘制线条，因此曲线形状可以不同。

Obsidian 当前库通过应用配置确认是 `/Users/dream/Documents/坚果云同步/Obsidian_base`。画板在 `B-开发/项目/上游资料工作台/`，文件与上表同名，扩展名 `.canvas`。项目保留 PNG、SVG、尺寸清单；不会复制整个知识库进项目。

重新生成项目图片：

```sh
node 工具/17-维护项目图示.mjs
```

同时写入当前打开的 Obsidian 库：

```sh
node 工具/17-维护项目图示.mjs --write-vault
```

命令先生成 SVG 和 Canvas（显式开启写库时），再由本项目 Electron 离屏渲染 PNG，不依赖浏览器外网或额外系统绘图软件。没有打开的库时明确报错，不随意写入另一个目录；未传 `--write-vault` 时仅更新项目图。

**维护约定**：修改总导航／详情／弹窗关系时更新 UI 图；修改来源、构建、索引或身份匹配时更新数据图；新增跨模块操作时更新功能图。改完构图声明，同步 Canvas、重新渲染 PNG，并检查连线目标和文字可读性。不要只改 PNG；不要把人工修改 Canvas 后未回填的脚本当最新源。交付前将图示与代码、说明放在同一提交。
