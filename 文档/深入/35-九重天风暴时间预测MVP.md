# 九重天风暴时间与内容候选 MVP

入口：推算实验室 → 九重天 · 未来 24 小时。支持国际服、国服独立刷新、历史演示、参考时间重算和复制 JSON。独立报告脚本输出 HTML、JSON、CSV，无需打包应用。

## 可预测范围

按已知 `VoidStorms` 时间锚点外推：同一时间组每 60 分钟开始一批，每批 90 分钟，重叠 30 分钟。下一批开始是本批结束 **减 30 分钟**。预测区间为 `(参考时间, 参考时间 + 24 小时)`，按开始时间纳入，最后一批结束可能超出区间。

0.17.2 在时间外推之上增加历史频次基线：未来条目携带同服、同开始分钟组下的纪元候选、每纪元前三节点和任务类型。纪元及数量均是历史候选／众数，不作为确定排期；节点是否循环仍未证明。相同分钟组在未来24小时使用相同候选，不伪造小时轮换。

DE 历史记录每小时 `:20` 一组，6 条；WG 历史记录分 `:20`（4 条）与 `:40`（2 条）。两组独立按小时外推，不把国服套成国际服。保留锚点秒级偏移，避免将国服 `:40:11` 截断到整分后制造假误差。UI 显示北京时间；JSON、CSV 时间为 UTC。

没有锚点时返回空预测；锚点超过两小时标明陈旧；源中时长偏离 90 分钟会提示规则可能变化。官方请求失败沿用原缓存／内置示例，明确标为非实时。不借用另一服的锚点。

## 准确率的定义

显示“已观测未来波次时间命中率”，不是任务内容准确率，也不是未来成功概率。

历史每日快照按 `last_updated` 排序。每份快照仅用自身已知时间组生成未来 24 小时窗口。每个后来首次采到的波次，选择开始之前、在 24 小时范围内的最近一次历史预测进行验证。相同波次不因有 6 条任务而计 6 次。新增时间组不能用后来样本回填先前锚点。所有实际条目的开始与结束偏差均须在 ±10 秒内才算命中。

这是固定规则的历史回放，历史“预测参考时间”是复算时间，不声称当时已运行本工具。缺少此前快照、超过 24 小时、采样空洞不计失败；没有可核验样本时命中率为 `null`，界面显示“暂无可核验样本”。按提前 0–6、6–12、12–18、18–24 小时分别展示分母。未采到的预测不计对错，无法从一天一份快照估计完整误报率。24 小时全程连续采样尚未完成。

基于 2026-08-18 至 2026-10-24 的 52 天有效快照（每服 52 份），初始回放结果：

| 来源 | 可核验未来波次 | 命中 | 18–24 小时命中 | 全部观测波次 |
|---|---:|---:|---:|---:|
| DE | 75 | 75（100%） | 73 / 73 | 91 |
| WG | 163 | 163（100%） | 159 / 159 | 192 |

0–6 小时均没有可核验样本。持续 90 分钟的一致性另计为 DE 546/546、WG 566/566，不能冒充预测命中数。结果只适用于这些历史时间证据。

## 数据与实现

- `src/core/void-storm-forecast.mjs`：原始 `VoidStorms`／每日 `isStorm: true` 提取、分组、条件外推、按时间先后回测。
- `src/core/void-storm-store.mjs`：内置历史证据和运行时观测。网络观测以实际收到快照的 `fetchedAt` 为时间，另保留上游生成时间判断陈旧；不会把下载时刻当成上游生成时刻。
- `src/core/void-storm-content.mjs`：节点身份解析、按采集时间截断的频次模型、前三节点／类型候选与逐任务回测。当前算法 `void-storm-frequency-1`。
- `src/data/void-storm-history.json.gz`：schemaVersion 2，104 份来源快照的 1,112 条时间／节点／纪元／原始类型记录和精简静态节点字典，不复制大体积原始快照。记录原文件及静态字典相对路径和 SHA-256；34 个缺失文件（17 天）单列，不补空任务。
- `src/ui/void-storm.js/.css`：24 小时窗口、分时段命中率、逐波次回放证据；renderer 没有网络权限，继续复用 worker 和已有双服缓存。
- 桌面运行时观测保存在应用用户目录 `void-storm-forecast/observations.json`，CLI 在 `.workbench/void-storm-forecast/observations.json`。同服同 hash 只保存一次，缓存重开不增加样本。仅网络观测自动入历史，本地导入／内置示例不充当新实测。

### 命令

```sh
# 当前两服官方快照 → 24小时报告（联网；失败明确降级）
node scripts/forecast-void-storms.mjs

# 无需联网的历史演示
node scripts/forecast-void-storms.mjs --historical

# 复用已获取的官方缓存重新生成报告，避免重复联网
node scripts/forecast-void-storms.mjs --cached

# 单服和指定输出目录
node scripts/forecast-void-storms.mjs --server de --out 输出/风暴DE

# 从只读的每日快照重建内置时间证据
node scripts/build-void-storm-history.mjs --input /Users/dream/Desktop/世界状态数据

# 定点验证
node --test test/void-storm-forecast.test.mjs
node scripts/check-void-storm-ui.mjs
```

默认报告在 `输出/九重天风暴预测/九重天风暴预测.html`，可直接打开，含两服切换和逐波次回测详情。未来所有条目均标“预测 · 尚未验证”。不同版本规则应使用新的算法版本重新评估，不能将回放统计当成已冻结的线上预测成绩。

## 0.17.2 内容候选与准确率

任务类型解析链为 `VoidStorms.Node → Plus ExportRegions[Node].missionName → dict.zh`。`MT_RAILJACK` 仅表示九重天。显式具体实例 MissionType 优先；节点具体类型取专用 missionName。Plus 生成器会由附带的 `extras/Missions.lua` 的 Type 补全九重天节点，不能宣称这些细分类全部直接来自官方原始世界状态。世界状态界面和筛选已接入具体类型，0.17.2 重新打包。

桌面原始每日快照只读。历史保留原节点显示名、纪元与类型字段；精确匹配 Plus 中英文节点名及明确的星球括号格式才关联内部 ID。无法对应的国服旧译名或英文拼写原样保留，按本服原始标签统计，不凭同名猜 ID。类型在有明确节点时查静态表；否则保留原类型证据，并用项目维护的精确类型译名表统一：遭遇战→前哨战、不稳定→爆发、奧菲斯／奥影母艇→奥影、間諜→间谍、殲滅→歼灭。原值仍在历史记录中。

每次历史回放仅使用预测参考时刻及之前已采集的快照，按服务器、分钟组和纪元累计频次。同节点、纪元、分钟批次去重，重开缓存不会增加权重。没有该纪元训练记录时计未命中；不使用后来的目标内容补全训练。静态字典来自当前版本，其来源文件与哈希记录在 bundle 中。

| 来源 | 节点首选命中 | 节点前三覆盖 | 类型首选命中 | 可核验任务 |
|---|---:|---:|---:|---:|
| DE | 76 / 450（16.9%） | 226 / 450（50.2%） | 208 / 450（46.2%） | 450 |
| WG | 101 / 476（21.2%） | 328 / 476（68.9%） | 268 / 476（56.3%） | 476 |

节点前三覆盖是实际节点落入该组前三候选的比例；类型首选是该组历史最常见类型命中实际类型的比例，与首选节点附带的静态类型分开计分。它们都不是整批任务完全命中率。候选旁的占比是训练数据频次，不是未来概率；类型查表的正确性也不能冒充未来类型预测准确率。回测按提前0–6／6–12／12–18／18–24小时保留分母，逐任务证据在 JSON 和界面可查。

每日稀疏采样主要核验18–24小时区间，不能核验全部未采到的窗口。该基线可展示候选但不能可靠报出下一波节点；尚未发现固定循环。

```sh
# 仅用历史数据推算指定时刻之后24小时；旧时间锚点明确标为陈旧
node scripts/forecast-void-storms.mjs --historical --at 2026-10-26T00:00:00+08:00
node --test test/void-storm-content.test.mjs
node scripts/check-void-storm-mission-ui.mjs
```

报告同时输出每服 forecast.json（含逐任务回测）、窗口 CSV、candidates.csv（每窗口每纪元的前三节点、任务类型、训练频次）。Electron 入口与 CLI 复用同一核心；历史演示不联网，实时刷新沿用官方缓存及网络失败降级。
