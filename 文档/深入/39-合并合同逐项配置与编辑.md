# 合并合同逐项配置与编辑

`src/data/merge-full-contract.json` 决定“哪些原始记录进入统一实体、同一字段怎样选值、哪些集合建立关系”。这里按程序实际读取逻辑解释全部选项，并给出在“合并规则”页面填写和添加的办法。

整体思路与文件关系见 [P3 设计与代码图解](38-P3设计与代码图解.md)，奖励建模细节见 [P3 合并规则与奖励关系](03-P3合并规则与奖励关系.md)。本文对应 0.17.2 的编辑器与 schemaVersion 2。

## 1. 先看规则在哪一步生效

![P3：上游 JSON、合同、合并引擎与界面的关系](../图示/P3-01-从上游到界面.png)

| 步骤 | 做什么 | 主要选项 | 负责代码 |
| --- | --- | --- | --- |
| ① 校验 | 检查结构、路径、数量和类型定义 | schemaVersion、scope、各规则合法性 | `src/core/merge/rules.mjs` |
| ② 身份与分类 | 命中文件、提取 ID、选类别、索引有数据的子实体 | catalogs、classificationPriority、nested.entityKind | `full-inputs.mjs`、`nested.mjs` |
| ③ 语言 | 用指定语言文本、完整语言键和字典生成名称、描述与嵌套文本 | locales、catalogs.locale、priority | `full-build.mjs`、`src/core/text-localization.mjs` |
| ④ 字段 | 收集候选 → 校验类型与范围 → 规范精度 → 按优先级选择 → 人工覆盖 → 留证据 | fields、priority、overrides | `full-build.mjs`、`contract.mjs` |
| ⑤ 配方与关系 | 配方成品、材料、技能、奖励、集合关系及缺失引用 | nested、aliases；配方三个数值的 overrides | `full-build.mjs`、专用关联模块 |
| ⑥ 版本产物 | 写入合同、数据、溯源、问题报告与版本身份，验证后切换当前版本 | mappingVersion、builderVersion、scope；全部配置的哈希 | `full-build.mjs`、`repository.mjs` |

②中的子实体索引发生在字段合并前；⑤再生成集合和关系。未被字段表接管的普通对象仍按子字段合并；有明确 ID 的对象数组按身份对齐，无 ID 数组保留整组候选。

## 2. 在程序中怎样编辑与添加

1. 进入 **合并规则**。先“导出规则”留备份；当前草稿与源 JSON 分开。
2. 选择下表对应标签。表格左右滚动可见全部列，表头显示真实 JSON 键；展开“每个选项的功能”可边填边查。
3. 修改现有行；新增时点表格下面 **＋ 添加一条**，把示例占位值换成已核对的真实字段或路径。删除行立即影响草稿，尚未保存。
4. 点 **校验规则**，填写底部“本次修改说明”，再点 **保存规则**。
5. 到 **合并汇总** 重新构建；检查差异、冲突、缺失翻译和待补引用。保存只更换本地规则，不会自动重建。
6. 如需回退，点 **载入上一版为草稿**，校验并保存，再重新构建。该按钮不会直接替换当前合并数据。

| 编辑页 | 可直接改什么 | 怎么新增 |
| --- | --- | --- |
| 版本与流程 | mappingVersion、builderVersion、priority、locales、scope.maxEntities | 修改输入框；语言与优先级使用英文逗号 |
| 分类 | catalogs 每条的全部九个属性 | 添加一条，核对来源、文件结构、类别和标识字段 |
| 字段映射 | fields 每条的十二个属性，包括 required | 添加一条，先选统一路径、来源顶层键、类型和适用类别 |
| 嵌套与关系 | nested 每条的七个属性 | 添加一条，指定来源集合、结果集合、关系方向、是否提取子实体 |
| 路径别名 | aliases 每条的 mode、from、to | 添加一条，用精确路径或明确前缀 |
| 人工修订 | overrides.entries 每条的五个属性 | 从合并详情复制实体 ID、目标路径、有效候选的源文件哈希 |
| 完整 JSON | 完整 contract 与 overrides；schemaVersion、scope.id/mode/label、overrides.version 在这里查看／编辑 | 改对象或数组；切换标签会先解析 JSON，保存仍需校验 |

版本号不用于开关功能：`mappingVersion` 是规则标记，`builderVersion` 是兼容标记，`schemaVersion` 是配置结构版本；应用版本在 `package.json`，互不替代。

本地保存位置是 **应用用户数据目录/merge-rules/current.json**；上一份为 `previous.json`。不会改写仓库内置的 `src/data/merge-full-contract.json`。如果要让所有安装默认使用新规则，应评审导出的 contract，再更新源码内置合同。

### 导入为什么不能直接用源 JSON

编辑器和导出文件需要以下外层结构；`src/data/merge-full-contract.json` 本身只是 contract 的值：

```json
{
  "contract": { "这里放完整 merge-full-contract.json 的全部内容": "此行只是结构说明，不能直接导入" },
  "overrides": { "version": 1, "entries": [] }
}
```

最稳妥的方式是先从程序导出，再改导出文件。下面的命令也可将内置合同包装为**可校验、可导入**的完整规则文件：

```sh
node --input-type=module -e 'import fs from "node:fs"; const contract=JSON.parse(fs.readFileSync("src/data/merge-full-contract.json","utf8")); fs.writeFileSync("/tmp/merge-rules.json",JSON.stringify({contract,overrides:{version:1,entries:[]}},null,2)+"\n")'
```

导入只载入草稿，文件须小于 2 MB；仍需校验、填写说明、保存和重建。完整 JSON 不支持注释或尾逗号，不执行脚本。未知额外键不等于新增能力，应只使用下列已实现选项。

### 合同顶层选项

| 选项 | 名称 | 影响步骤 | 功能与填写规则 |
| --- | --- | --- | --- |
| `schemaVersion` | 规范版本 | ① 校验 | 固定为数字 2；决定配置结构是否受支持。仅完整 JSON 可见，不用它切换试点或全量模式。 |
| `mappingVersion` | 映射版本 | ⑥ 版本 | 1～80 位字母、数字、点、下划线或连字符。标识本次规则语义，写入构建清单；规则变化后建议递增。 |
| `builderVersion` | 构建兼容标记 | ⑥ 版本 | 同映射版本的字符限制。进入构建身份与清单；修改它不会下载或切换合并引擎，也不是程序版本号。 |
| `locales` | 输出语言 | ③ 本地化 | 用逗号分隔唯一语言代码，如 zh-CN,en,fr。控制名称、描述及嵌套文本的语言投影；第一项是属性的首选语言，需要对应上游文件或字典。 |
| `priority` | 来源优先级 | ②③④ 候选选择 | 从左到右，必须恰好包含 official,plus,wfcd,oracle 各一次。影响同具体程度的分类、字典和字段候选；字段可以另设顺序，不会丢弃低优先来源的证据。 |
| `scope` | 构建范围 | ①②⑥ 范围 | 对象包含 id、mode、label、maxEntities；展开下方逐项查看。它限制全量建模，不负责下载范围。 |
| `catalogs` | 来源分类表 | ② 身份与分类 | 最多 600 条，至少一条。指定哪些来源文件提取成实体及采用哪种结构；不是名称相似度合并。 |
| `fields` | 字段映射表 | ④ 字段合并 | 最多 300 条，把语义相同的来源顶层字段映射到统一路径；类型、边界、精度和优先级在这里设置。 |
| `nested` | 嵌套与关系表 | ②⑤ 嵌套关联 | 最多 40 条。指定哪些集合提取实体、建立关系；整个字段缺省时使用内置五条，空数组表示不启用这些集合规则。 |
| `aliases` | 引用路径别名 | ⑤ 引用解析 | 最多 100 条，纠正配方、奖励等内部引用路径；最长匹配仅替换一次，不改原文件，不重命名所有实体。 |

### scope · 构建范围

| 选项 | 名称 | 影响步骤 | 功能与填写规则 |
| --- | --- | --- | --- |
| `id` | 范围标识 | ⑥ 报告 | 默认 full-static，写入范围与版本清单。完整 JSON 编辑；不是过滤器，也不选择代码分支。 |
| `mode` | 构建模式 | ① 校验 | 本编辑器仅接受 full。试点 profile 由独立命令选择，不能在这里改成 pilot。 |
| `label` | 范围标题 | ⑥ 报告 | 默认“全量静态资料”，供范围说明使用；完整 JSON 编辑，不影响纳入哪些文件。 |
| `maxEntities` | 实体数量上限 | ②⑤ 容量保护 | 1～300000 的整数。初始实体、嵌套实体以及待补引用总数超限时阻止构建；不是截断条数或界面分页大小。 |

### catalogs · 分类选项

| 选项 | 名称 | 影响步骤 | 功能与填写规则 |
| --- | --- | --- | --- |
| `enabled` | 启用 | ② 文件纳入 | true 才执行本条分类；false 停止本条实体提取，其他分类仍可能命中同文件。已识别来源仍可保留为参考。 |
| `source` | 来源 | ② 文件匹配 | 只能选择 official、plus、wfcd、oracle，须与资料浏览中的来源身份一致；显示名不能代替来源代码。 |
| `file` | 来源内文件 | ② 文件匹配 | 来源目录下的相对 JSON 路径，区分大小写，不接受绝对路径、../ 或通配符。输入清单中需要确实存在该文件；缺失会记入问题报告。 |
| `kind` | 实体类别 | ② 分类 | 选择现有类别代码，例如 weapon、blueprint、mod。决定实体分组、后续 fields.kinds 是否适用；新增类别还需要代码支持。 |
| `classificationPriority` | 分类优先级 | ② 分类冲突 | 可留空（默认 1），或填 0～20 整数，越小越具体、越优先。先比较本值，再比较来源顺序；不控制数值字段优先级。 |
| `shape` | 文件结构 | ② 提取记录 | map：顶层键作 ID；array：根数组；group：顶层指定数组；nested：递归路径键对象及带 uniqueName 的数组记录（深度最多 5）。 |
| `group` | 顶层分组 | ② 提取记录 | 仅 shape=group 时必填，如 ExportWeapons；读取 JSON 的直接属性，不把点号当嵌套路径。其他结构留空。 |
| `idKey` | 标识字段 | ② 实体身份 | array/group 的记录标识字段，默认 uniqueName。map 始终用顶层键；nested 不支持用此项更换递归的识别规则。 |
| `locale` | 记录语言 | ③ 文本候选 | 标记本文件记录的语言（例如 zh-CN、en）。留空时 WFCD 默认 en，其他来源通常按语言键查字典；设置语言不会执行翻译。 |

### fields · 字段映射选项

| 选项 | 名称 | 影响步骤 | 功能与填写规则 |
| --- | --- | --- | --- |
| `path` | 统一字段路径 | ④ 写入结果 | 每条唯一；允许 masteryRank、tradable、rarity、imageName、icon，或 stats.xxx、bundle.xxx、custom.xxx（末段字母数字下划线）。不是任意 JSON 路径。 |
| `key` | 来源字段 | ④ 收集候选 | 读取每条实体记录的顶层属性原名，如 criticalChance。不会把 attack.damage 当作子字段路径；嵌套数据由递归合并或 nested 规则处理。 |
| `label` | 中文标题 | ④ 字段说明 | 必填，用于规则解释、字段展示和人工阅读，不改变数值或源字段名。 |
| `description` | 中文说明 | ④ 字段说明 | 可留空，记录语义、来源差异与边界；不是转换表达式，不执行代码。 |
| `kinds` | 适用类别 | ④ 适用范围 | 逗号分隔已定义类别，如 weapon,warframe；* 表示全部。按实体最终分类决定是否套用该映射。 |
| `type` | 值类型 | ④ 候选校验 | number（有限数字）、integer（整数）、string（字符串）、boolean（布尔值）。严格检查原值；字符串 "12" 不会自动变为数字 12。 |
| `unit` | 单位 | ④ 字段说明 | 可留空，用于说明与显示，如秒、比例、倍。不自动把 32% 转为 0.32，也不转换时间单位。 |
| `min` | 最小值 | ④ 候选校验 | 仅数值类型，可留空；包含边界。低于本值的候选记录问题并跳过，不强行改成最小值。 |
| `max` | 最大值 | ④ 候选校验 | 仅数值类型，可留空；包含边界，必须不小于 min。超限候选跳过，未填写时无此上限。 |
| `precision` | 小数精度 | ④ 规范化 | 仅数值类型，0～10 整数，可留空。通过校验后按 toFixed 四舍五入成数字；不是界面补零位数。 |
| `priority` | 字段优先级 | ④ 候选选择 | 留空继承全局；填写时用逗号列出全部四个来源且不重复，仅覆盖这一字段的候选顺序。 |
| `required` | 必需字段 | ④ 缺失报告 | 勾选后，适用实体完全没有该来源字段时记录 required-field-missing 警告；不补默认值，也不保证有候选时其值有效。默认未启用。 |

### nested · 嵌套选项

| 选项 | 名称 | 影响步骤 | 功能与填写规则 |
| --- | --- | --- | --- |
| `enabled` | 启用 | ②⑤ 提取与关联 | 开启本条的实体提取与关系建模。关闭后原集合仍可作为普通 attributes 递归保留，不会自动删除原始资料。 |
| `key` | 来源集合字段 | ② 读取集合 | 唯一的来源顶层字段名，如 abilities、components；以字母开头，后接字母数字下划线。 |
| `path` | 统一集合字段 | ⑤ 输出集合 | 可选 abilities、components、additionalItems、exaltedItems，或 custom 开头且随后大写的字段，如 customSocketedItems。只改路径不会自动新增玩家界面模块。 |
| `label` | 中文标题 | ⑤ 规则说明 | 必填，说明这个集合用途；不改变关系方向或数量。 |
| `relation` | 关系类型 | ⑤ 关系图 | 小写字母和连字符，例如 has-component。写入 relations.json 的 kind，用来区分实体间联系；不是任意可执行动作。 |
| `entityKind` | 嵌套实体类别 | ② 补充实体 | 可留空（仅建关系）。填写现有类别后，具有完整内部 ID 和额外数据的子对象可提取成实体；只有 ID／数量的引用不会凭空补全实体。 |
| `reverse` | 反向父级 | ⑤ 关系方向 | 默认 false，关系为当前实体→集合目标；true 时目标→当前实体。用于 parentUniqueNames，不会反转来源优先级。 |

### aliases · 路径别名

| 选项 | 名称 | 影响步骤 | 功能与填写规则 |
| --- | --- | --- | --- |
| `mode` | 匹配方式 | ⑤ 引用匹配 | exact 要求完整路径相同；prefix 匹配路径前缀。多条命中时只用 from 最长的一条，不连续级联替换。 |
| `from` | 来源路径 | ⑤ 引用匹配 | 以 / 开头的内部路径或明确前缀，不可为单独 /，各条 from 唯一；不接受正则或名称模糊匹配。 |
| `to` | 统一路径 | ⑤ 引用替换 | 以 / 开头且不同于 from。prefix 会保留匹配后缀；目标缺少实体时仍记录待补引用，不伪造实体。 |

### overrides · 人工修订选项

| 选项 | 名称 | 影响步骤 | 功能与填写规则 |
| --- | --- | --- | --- |
| `version` | 修订格式版本 | ① 校验 | 固定为数字 1，完整 JSON 编辑；与 contract.schemaVersion、应用版本不同。 |
| `entries` | 修订列表 | ④⑤ 人工修订 | 最多 20000 条，同实体同字段仅一条。空数组表示不做人工覆盖。 |
| `entityId` | 实体 ID | ④⑤ 精确定位 | 从合并详情复制完整 ID，不填显示名称；不能用修订创建新实体。 |
| `field` | 统一字段 | ④⑤ 修订目标 | 填写 fields 中已有 path，或 name.语言、description.语言、recipe.credits／seconds／quantity；不支持覆盖任意原始属性或关系。 |
| `expectedSourceHash` | 预期源 SHA-256 | ④⑤ 过期保护 | 复制该字段有效候选所属源文件的 64 位小写 SHA-256。源变更、没有匹配候选或修订未命中会阻止构建，需要重新核对。 |
| `value` | 修订值 JSON | ④⑤ 替代选择 | 严格符合目标类型与范围：文字需双引号，数字不加引号，布尔值用 true/false。仍按该字段精度规范化。 |
| `reason` | 依据 | ④⑤ 审核记录 | 必填，说明核对来源与修改原因；保留在 overrides 与溯源中，不作为游戏说明文字。 |

### 导入与导出的外层结构

| 选项 | 名称 | 影响步骤 | 功能与填写规则 |
| --- | --- | --- | --- |
| `contract` | 合并合同 | ①～⑥ 全流程 | 对应 src/data/merge-full-contract.json 的内容；完整编辑与导入时必须包在 contract 属性内，不能直接粘贴裸合同。 |
| `overrides` | 人工修订 | ④⑤ 覆盖候选 | 与 contract 同级，结构为 {"version":1,"entries":[]}。导入、导出使用二者组成的完整对象；不执行脚本。 |

## 4. 当前内置映射各自做什么

<!-- rule-defaults:start -->

### 默认 24 条字段映射

全部作用于步骤④。未设置单字段优先级，继承全局；默认都未标记 required。比例字段没有设置 max=1，允许超过 100%。以下是**当前规则值**，并不保证游戏实时平衡参数不变。

| 功能 | 来源 → 结果 | 适用类别 | 类型；单位 | 限制与语义 |
| --- | --- | --- | --- | --- |
| 段位要求 | `masteryReq` → `masteryRank` | weapon、warframe | integer；段 | ≥ 0 |
| 可交易 | `tradable` → `tradable` | * | boolean；— | 无范围／精度限制 |
| 基础暴击率 | `criticalChance` → `stats.criticalChance` | weapon | number；比例 | ≥ 0，小数 6 位。基础面板比例值；可超过 1（100%）。不与攻击模式百分数混用。 |
| 暴击倍率 | `criticalMultiplier` → `stats.criticalMultiplier` | weapon | number；倍 | ≥ 0，小数 6 位 |

### 分类结构怎么判断

| shape | 原始结构示意 | ID 从哪里取 | 其他字段 |
| --- | --- | --- | --- |
| map | `{ "/Lotus/X": { "name": "…" } }` | 顶层 `/Lotus/X` 键 | 不需要 group 或 idKey |
| array | `[ { "uniqueName": "/Lotus/X" } ]` | 记录的 idKey，默认 uniqueName | group 留空 |
| group | `{ "ExportWeapons": [ { "uniqueName": "/Lotus/X" } ] }` | 指定顶层数组中记录的 idKey | group=ExportWeapons |
| nested | `{ "分组": { "/Lotus/X": { "name": "…" } } }` | 递归遇到路径键，或数组对象的 uniqueName | 最多递归深度 5；不能用 idKey 替换识别算法 |

map 的值必须是对象，数组根结构必须与 shape 相符；group 目标不存在时会跳过。ID 以 `/` 开头就保留完整路径，其他标识变为 `wf:<kind>/<原标识>`。不要用中文名称或英文显示名替代稳定 ID。

分类优先级与字段优先级分开：例如一份精确 blueprint 分类设 0，一份泛用 Components 分类设 2，前者决定最终类别；数值字段仍按 fields.priority 或全局来源顺序选择。分类的行顺序不应作为消解歧义的手段。

## 5. 四个实际添加场景

### A. 添加一个标量字段

例如已核对武器源记录存在顶层数字 `accuracy`，要在合并结果保留精度：进入 **字段映射 → 添加一条**，填写：

```json
{
  "path": "custom.accuracy",
  "key": "accuracy",
  "label": "精准度",
  "description": "来源提供的基础精准度，不与散布角度混用",
  "kinds": ["weapon"],
  "type": "number",
  "min": 0,
  "precision": 2
}
```

表格中适用类别填 `weapon`；单位、最大值、字段优先级留空，required 不勾选。先查看现有 path，确认没有重复。构建后结果为 `item.custom.accuracy`，溯源列出来源候选；原 `accuracy` 不再作为未知属性重复输出。

这不会自动在玩家“基础属性”新增专用布局。通用合并详情可读取新数据；玩家界面若要增加业务展示，还需修改 `src/ui/player-library.js` 等实际消费代码。

### B. 添加一个新文件分类

假设**当前资料清单确实已有** `plus/ExportNew.json`，根结构是完整路径键对象，进入 **分类 → 添加一条**：source=plus、file=ExportNew.json、kind=misc、shape=map、enabled=true；其余留空。`ExportNew.json` 是示例占位名，不会因添加规则而生成或下载该文件。

若实际数据是根数组，改为 array 并核对 uniqueName 或填真实 idKey；若是顶层分组数组，使用 group 并填写 group。新增上游下载源需要在获取流程中另行接入，分类页只消费已经可读取的文件。相同 source/file/group 组合不能重复，即使其中一条停用也一样。

### C. 新增子集合关联

假设源记录有 `socketedItems` 集合，元素含完整物品 ID，进入 **嵌套与关系 → 添加一条**：

```json
{
  "enabled": true,
  "key": "socketedItems",
  "path": "customSocketedItems",
  "label": "已装入物品",
  "relation": "has-socketed",
  "entityKind": "gear",
  "reverse": false
}
```

只有当子对象包含 ID 以外的实际属性时，entityKind 才允许它参与实体提取。单独一个 `/Lotus/…` 字符串只提供关系目标；引用未找到会明确标记待补。子对象可识别的 ID 字段为 uniqueName、abilityUniqueName、ItemType、itemId；不按同名和数组下标猜测。

集合中的数量、次序和已有正向／反向资料由关系代码处理；path、relation 或 label 不是任意转换公式。新集合还需要消费端决定如何展示。

### D. 改一个已知错误值

进入 **人工修订 → 添加一条**。从该实体的字段详情复制 ID、统一路径和有效候选对应的源文件 SHA-256；填 JSON 值和核对依据。例如目标为 `stats.criticalChance` 时填 `0.32`，不是 `"32%"`；改中文名时填 `"正确中文名"`。

人工修订优先于普通候选，但必须先有对应有效候选。哈希过期、目标实体不存在、目标字段未触发或未命中的修订会阻止构建；重新核对源数据后更新或删除修订。reason 用于审核，保存栏 note 则说明这整次规则变更，二者都要填。

## 6. 常见误区与排查

| 现象 | 先检查 |
| --- | --- |
| 保存后结果没变化 | 是否到合并汇总重新构建；是否处在同一份资料目录／快照上下文 |
| 新分类没有实体 | 文件是否进入当前清单、source/file 大小写与相对路径、shape/group/idKey 是否吻合；查看 optional-input-missing |
| 新字段没有值 | 实体最终 kind 是否符合、key 是否为真实顶层属性、类型是否严格一致；查看 invalid-value |
| “必需”仍未停止构建 | required 是缺失警告，不是硬性抛错；全部候选无效走 invalid-value，不会补零 |
| 改 unit 后仍是原数字 | unit 只解释语义；真正单位转换需要明确代码，不能靠改中文标签 |
| 设置 min/max 后数据消失 | 越界候选被拒绝，不会夹到边界；原来源仍可回查 |
| 把攻击数组映射为 number 失败 | 标量字段规则不支持数组公式；攻击模式整组数据和嵌套子字段由专用流程处理 |
| 加入 fr 但没法语 | locales 声明不创造翻译；需要对应文件与字典。官方会从已启用英文 manifest 规则推导同类语言路径，文件不存在会报告 |
| 别名没把旧实体都改名 | 别名只在明确引用处应用一次；不是全库搜索替换或通用身份合并 |
| 修改规则后程序版本没涨 | builderVersion / mappingVersion 都不是 package.json 的应用版本 |

配方字段 `resultType`、`ingredients[].ItemType/ItemCount`、`buildPrice/buildTime/num`，奖励表字段与概率含义，以及技能强化／灵化／套装关联仍由专用代码解释。不要添加未实现的 contract 选项来推断阶段、概率或游戏机制。
