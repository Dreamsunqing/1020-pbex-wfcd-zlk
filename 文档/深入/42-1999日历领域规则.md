## 二、规则

### 全年日序

`ordinal` 是 1999 年全年、从 1 开始的日序，与 [WFCD Calendar.ts getDate](https://github.com/WFCD/warframe-worldstate-parser/blob/master/lib/models/Calendar.ts) 相同：`Date.UTC(1999)` 加上 `day - 1` 天。

| 日序 | 日期 | 星期 |
|---|---|---|
| 1 | 1999-01-01 | 周五 |
| 59 | 1999-02-28 | 周日 |
| 60 | 1999-03-01 | 周一 |
| 90 / 91 | 1999-03-31 / 1999-04-01 | 冬春交界 |
| 104 | 1999-04-14 | 周三 |
| 181 / 182 | 1999-06-30 / 1999-07-01 | 春夏交界 |
| 273 / 274 | 1999-09-30 / 1999-10-01 | 夏秋交界 |
| 365 | 1999-12-31 | 周五 |

- 只接受 1–365 的整数。`0`、`366`、`1.5`、`'91'`、`null`、`NaN` 等一律返回 `null`，不进位到 1998 或 2000 年（上游 `getDate` 没有这个检查）。
- 固定为非闰年。`yearIteration` 只识别轮回，2 月 29 日不存在。

### 计算方式：不使用 Date

日期由整数运算与固定月长表求出，星期由「1999-01-01 为周五」推出。这本身就是 UTC 历法，不经过 `Date` 对象，因此：

- 结果不受宿主时区影响；
- domain 不可能读取当前时间；
- 测试逐日对照 `Date.UTC(1999, 0, day)` 的 `toISOString()` 与 `getUTCDay()`，证明与上游换算一致。

### 季度对应月份

| 季度代码 | 显示月份 | 日序 | 天数 |
|---|---|---|---|
| `CST_WINTER` | 1–3 月 | 1–90 | 90 |
| `CST_SPRING` | 4–6 月 | 91–181 | 91 |
| `CST_SUMMER` | 7–9 月 | 182–273 | 92 |
| `CST_FALL` | 10–12 月 | 274–365 | 92 |
| `CST_AUTUMN` | 10–12 月 | 274–365 | 92 |

- 依据 [DE Update 38](https://www.warframe.com/en/patch-notes/pc/38-0-0) 的季度说明。上游 `warframe-worldstate-data` 的 `translateSeason` 接受任意 `CST_*`，没有月份表；对应关系由项目维护。
- `CST_AUTUMN` 是项目在 `src/data/live-state/weekly-semantics.json` 已有的别名，此处保持一致。
- 其他代码（含大小写不同、前后空白、`constructor`、`__proto__` 等继承键）都是未知季节：没有月份，所有事件进入未映射。

### 完整月份与星期

每个显示月份都从 1 日排到月末。每一天包含 `day`、`ordinal`、`date`（`YYYY-MM-DD`）、`weekday`（0 为周日，与 `getUTCDay` 相同）、`listed`、`kind`、`entries`，与 `ports.mjs` 的 `CalendarDay` 一致。

### 事件与日期对齐

`buildSeasonMonths(season)` 返回 `{months, unmapped}`：

- 事件保持原对象（不复制、不改写），因此完整物品 ID 与 `evidence` 不会丢失。
- 同日多个事件全部保留，按来源顺序；重复事件、甚至同一对象出现两次，都算两条。
- 以下事件按来源顺序进入 `unmapped`，不丢弃：日序不是 1–365 的整数；日期不在本季三个月内（例如春季中的第 1 天或第 182 天）；季度代码未知；事件本身不是对象。
- `listedDays` 列出但没有事件的日期：`listed: true`、`kind: null`、`entries: []`，不推定为生日或其他类型。
- `listed` 与 `entries` 互相独立：没被列出的日期如果有事件，仍会显示事件。
- 本季之外的 `listedDays` 不显示，也不变成未映射事件；它只保留在 `season.listedDays`。
- `eventDays` 是该月有事件的天数，不计只被列出的空日期。

### 事件分类

`classifyDay(entries)` 决定一天的类型：

| 当日事件 | 结果 |
|---|---|
| 没有事件 | `null` |
| 全部同一类型（含重复） | 该类型 |
| 两种以上类型 | `mixed` |
| 类型不在 `EVENT_KINDS` 中（例如 `plot`、缺少 `kind`） | 视为 `other` |

结果总是在 `EVENT_KINDS` 或 `null` 之内。上游 `CET_*` 到类型的映射（含 `CET_PLOT` 生日事件）属于世界状态适配器，不在 domain 决定。

### 不变性与确定性

- 不修改传入的季度、数组或事件；测试以深度冻结的输入执行。
- 同样的输入返回相等的结果；每次调用都返回新的月份、日期与数组，修改一次的结果不影响下一次。
- 常量表（`SEASON_MONTHS` 及其月份数组）已冻结。

## 三、domain 函数

| 函数／常量 | 输入 | 输出 | 无效输入 |
|---|---|---|---|
| `DAYS_IN_YEAR` | — | `365` | — |
| `SEASON_MONTHS` | — | 冻结的季度 → 月份表 | — |
| `isAnnualDay(value)` | 任意值 | `boolean` | `false` |
| `ordinalToDate(ordinal)` | 日序 | `{ordinal, month, day, date, weekday}` | `null` |
| `dateToOrdinal(month, day)` | 月、日 | 日序 | `null`（如 2/29、4/31） |
| `seasonMonths(code)` | 季度代码 | 冻结的月份数组 | 空数组 |
| `monthDates(month)` | 1–12 | 该月全部日期 | 抛 `RangeError` |
| `buildSeasonMonths(season)` | `{code, listedDays?, entries?}` | `{months, unmapped}` | 季度不是对象、`entries`／`listedDays` 不是数组时抛 `TypeError` |
| `classifyDay(entries)` | 当日事件数组 | 类型或 `null` | 不是数组时抛 `TypeError` |

数据层面的边界（无效日序、未知季节、空日期）返回明确的数据结果；结构错误（传错类型）抛错，因为那是调用方的程序错误。正式数据在进入会话前已由 `validateCalendarDocument` 检查。

## 四、相对 MVP 原型的修正

| MVP 原型的做法 | CAL-02 |
|---|---|
| `seasonStarts[code]` 直接查表，`constructor`、`toString` 会取到继承的函数 | 以 `Object.hasOwn` 查表，继承键视为未知季节 |
| 未知季节直接返回传入的 `entries` 数组作为 `unmapped` | 返回新数组，事件对象保持原样 |
| `calendarEventKind` 会把未知类型（如 `plot`）原样返回 | 词汇外的类型视为 `other` |
| 以 `Date.UTC` 与 `new Date()` 计算 | 整数运算，不使用 `Date`；测试逐日对照 `Date.UTC` |
| `calendarDate` 只返回日期字符串 | `ordinalToDate` 一次返回月、日、日期与星期，另提供反向的 `dateToOrdinal` |
| 事件与季度分两个参数传入 | `buildSeasonMonths(season)` 直接读取契约中的 `season.entries` |
